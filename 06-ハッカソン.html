GIS とはどうあるべきか

渋谷ミニハッカソンで痛感したのは、多くの現場で GIS が「地図を描くツール」にとどまり、「場と情報を一体化させて理解を支援する基盤」として使われていない点です。KASUGAI Canvas は、本来あるべき GIS の姿を実現することを目指します。

一番大事なこと：GIS で「何ができて、何が解決できるか」を先に体験する

結局、最も重要なのは、「GIS を使うことで何ができて、どんな課題が解決できるか」を本番導入前に体験できるかということです。GIS 導入が進まない、あるいは導入されても活用されない現場の多くは、GIS 自体の理解が不足していることが原因です。

そのためのエージェントこそが、KASUGAI Canvas の ANTIGRAVITY 情報レイヤーです。

  • 体験を先に：本番データを必要とせず、サンプル・資料・GIS が連動した状態で「GIS ならではの理解」を体験
  • 理解を深める：地図と情報の一体化、レイヤーの切り替え、FlyTo・属性表示など、GIS の利点を実感
  • 正しい導入判断へ：体験を通じて「本当に必要なデータ・機能・運用」が見え、無理な導入や失敗を減らす

ANTIGRAVITY エージェント：目標と 3 つの機能

ANTIGRAVITY エージェントの目標は、利用者を正しい GIS 導入判断と課題解決へ導くことです。そのために、以下 3 つの機能が必要です。

自然言語からレイヤーと属性を自動構成

「○○の資料を作って」と話すだけで、必要な地図レイヤー・属性・凡例・カメラ位置を自動で選定・構成する。

現実に近いサンプルデータを自動生成し、GIS の利点を可視化・体験化

本番データがなくても、エリア・業種・目的に応じた架空サンプルを生成。地図と情報の一体化、レイヤー切り替え、FlyTo、属性表示など、GIS ならではの理解を実感してもらう。

属性から課題を抽出し、平面・内容・解決案を提示した資料作成

レイヤー・属性から課題を抽出し、その平面（地図上の状況）・内容・解決案をまとめた資料のベースを自動生成。資料には GIS へのパーマリンクを付与する。

目標：正しい GIS 導入判断と課題解決へ導く

上記 3 つの機能を通じて、利用者は本番導入前に「GIS で何ができて、どんな課題が解決できるか」を体験します。その結果、「本当に必要なデータ・機能・運用」が見え、無理な導入や失敗を減らし、課題解決につながります。

ANTIGRAVITY エージェントの本質：資料を作る・見せる・説明する

ANTIGRAVITY エージェントは、資料の基本である 作る → 見せる → 説明する を自動化するエージェントです。

資料の基本ANTIGRAVITY の機能具体的な動作
作る自然言語からレイヤーと属性を自動構成「○○の資料を作って」と話すだけで、必要なレイヤー・属性・サンプルデータを自動生成する
見せる現実に近いサンプルデータを自動生成し、GIS の利点を可視化・体験化地図上にサンプルを表示し、レイヤー切り替え・FlyTo・属性表示で GIS 体験を提供する
説明する属性から課題を抽出し、平面・内容・解決案を提示した資料作成属性から課題を読み取り、平面・内容・解決案をまとめた資料を作成する

この 3 ステップを通じて、資料は「PDF への地図貼り付け」ではなく、GIS と連動した生きた理解資料となります。そして、その体験が正しい GIS 導入判断と課題解決へ繋がります。

資料のベース作成と GIS パーマリンク連携

最も重要なのは、資料は資料として必要なものであるという点です。資料は会議の進行、結論の提示、合意形成のための要約として不可欠です。ANTIGRAVITY エージェントは、GIS 上のレイヤー・属性から課題を読み取り、平面（地図上の状況）・内容・解決案をまとめた資料のベースを自動作成します。

資料に載せきれない背景・範囲・詳細は GIS 側に置き、資料にパーマリンク（QR や短縮 URL）を載せることで、資料と GIS を双方向に連動させます。

なぜパーマリンクなのか

  • 資料の要約性を維持：資料は簡潔なままで、詳細は GIS へ誘導
  • 深い理解へ誘導：「なぜこの範囲か」「背景データは何か」「周辺の状況は」などを地図上で探索可能に
  • 会議の一体感：参加者全員が同じ URL から GIS を開き、同一視点・レイヤーで議論できる
  • 判断の加速：空中戦を減らし、必要な情報に即座にアクセスすることで、より速い課題解決・意思決定を実現

想定される使い方

  1. 資料の該当部分に https://kasugai-canvas.example/#cam=...&layers=... 形式のパーマリンクを配置
  2. 会議参加者がリンクを開くと、KASUGAI Canvas が即座にその場所・レイヤー・属性を表示
  3. 必要に応じてレイヤーを追加・非表示・属性をクリックし、深掘りを行う
  4. 新たな視点が見つかったら、新しいパーマリンクを生成し資料にフィードバック

ANTIGRAVITY との関係

資料作成時に、ANTIGRAVITY エージェントが「資料に載せるべき GIS 視点」を自動提案し、パーマリンク付きで資料と GIS を同時生成します。資料と GIS がお互いを補完し合うことで、会議の一体感と意思決定のスピードが向上します。

ANTIGRAVITY の狙い

ANTIGRAVITY 情報レイヤーは、上記 3 つの機能を自然言語で実現し、「正しい GIS 導入判断と課題解決へ導く」ことを目指すエージェントです。「○○の資料を作って」と話すだけで、作る → 見せる → 説明する という資料作成の基本が自動化され、場と情報が一体化した GIS 体験が構築されます。

ANTIGRAVITY の最終目的は、利用者が本番導入前に「GIS で何ができて、どんな課題が解決できるか」を体験し、GIS への理解を深めることにあります。サンプルデータや資料×GIS 連携を通じて、正しい GIS 導入判断と課題解決を後押しします。

課題発掘

地図情報の伝わりにくさ

「地図情報がどのようなものか、何ができるか」が相手に正しく伝わりにくい。PDF 等の資料では実際の内容が正確に伝わらない。

地図と情報の分断

地図と情報が分断されやすく、地図が資料から孤立した「作り物」として残ってしまう。本来の価値が伝わらない。

空中戦・取り残され

会議等で位置や場所に詳しくない人が取り残され、理解が深まらないまま会議が進む「空中戦」が起きる。

現在の対応とつらい点

段階内容課題
事前の行動説明できる事例をあらかじめ集めるGIS 自体の理解が浅く、何を示せばよいか分からない。実例も手間で作れない
資料化PDF 等にまとめる実際の地図・空間情報の操作性や詳細が正確に伝わりにくい
完成時喜ばれるただし、作るまでに情報の伝達・分断・空中戦が発生しやすい

渋谷ミニハッカソンからの学びと ANTIGRAVITY への反映

上記の課題は、GIS 導入前に「何ができて、どんな課題が解決できるか」を体験できる環境がないことに起因しています。これを解決するために、ANTIGRAVITY エージェントで 作る → 見せる → 説明する を自動化し、GIS と連動した資料を生み出す方向性が固まりました。

また、渋谷ミニハッカソンでは以下のような応用アイデアも出ました。これらは ANTIGRAVITY の 3 つの機能を拡張するものです。

  • 交通連携：駅すぱあと API MCP サーバーで到達圏・ルートをレイヤー化し、資料の説得力を補強
  • 画像解析：GMI Cloud / Earth Engine / Vision AI で衛星写真から建物・道路・植生を自動検出
  • 会議支援：自然言語で FlyTo やレイヤー切り替えを自動制御し、全員が同じ視点で議論できる状態を作る

出展構想：KASUGAI Canvas — GIS 利活用を促進する Agentic AI エージェント

出展タイトルは 「KASUGAI Canvas — GIS 利活用を促進する Agentic AI エージェント」 です。KASUGAI Canvas を、Agentic AI（ANTIGRAVITY エージェント）が空間情報レイヤーを自動構築・自動更新し、GIS の利活用を促進するプラットフォームとして出展します。GIS 本番導入前の「フロントローディング」として、利用者が GIS の利活用を体験し、正しい導入判断と課題解決につなげることを重視します。

課題設定

多くの現場で GIS が導入に至らない、あるいは導入後も活用されない状況があります。原因は GIS 自体の理解不足と、「何ができて、どんな課題が解決できるか」を導入前に体験できる環境がないことです。本ハッカソン出展テーマとしては、「GIS に何ができて、どう課題解決に繋げられるか」を本番導入前に体験できる ANTIGRAVITY エージェントを作り、GIS の利活用を促進することに位置づけます。

本ハッカソンの参加条件（必須プロダクト・必須 AI 技術・提出物）に対し、KASUGAI Canvas は以下のように対応します。

解決策：ANTIGRAVITY 情報レイヤー（GIS 利活用を促進する Agentic AI エージェント）

本番導入前に、自然言語や文脈から「今必要な情報レイヤー」を自律的に選定・追加・更新するエージェント機能を提供します。重力に逆らって情報が自動的に「浮かび上がる」ように、必要なレイヤーが勝手に追加される体験を目指します。

ANTIGRAVITY の本質は、「GIS で何ができて、どんな課題が解決できるか」を本番前に体験してもらうためのエージェントにあります。サンプルデータ・資料・GIS を連動させることで、利用者の GIS 理解を先に深め、正しい導入判断と課題解決への期待値を形成します。

  • 文脈理解：ユーザーの質問・目的・現在の視点を Gemini などの LLM で解析
  • レイヤー推論：必要な GeoJSON、XYZ、3D Tiles、DEM、画像、属性情報を推定
  • 自動取得・変換：外部 API や Google Cloud 上のデータから自動取得し、表示可能なレイヤーへ変換
  • ガバナンス：取得元・更新時刻・ライセンスを可視化し、不要なレイヤーは自動で非表示

協賛企業 API・サービスの GIS 活用法

本ハッカソンの Support スポンサーおよび Google Cloud が提供する API・サービスを、KASUGAI Canvas の空間情報レイヤーとしてどう活かせるか整理しました。参加条件の必須技術（Cloud Run / Gemini API / ADK）を中核に据えつつ、協賛企業 API を MCP・外部ツールとして ANTIGRAVITY エージェントから呼び出すことで、「GIS 利活用の促進」というテーマを協賛エコシステム全体で実現します。

駅すぱあと API MCP サーバー（株式会社ヴァル研究所）

電車・バス・飛行機・船などの経路探索を、LLM/エージェントから自然言語で直接呼び出せる MCP サーバーです。

  • GIS への活用法：
    • 出発地→目的地の経路を GeoJSON 化し、KASUGAI Canvas の geojson: レイヤーとして追加
    • 駅・バス停をポイントレイヤーで表示し、 FlyTo や属性表示と連動
    • 所要時間や運賃を属性として持たせ、ルート比較レイヤーを重ねる
    • 「渋谷から新宿まで30分以内で行ける場所」など、到達圏（アイソクローン）を生成
  • エージェント連携例：「渋谷駅から横浜駅までの電車ルートを地図に表示して」→ Gemini が Ekispert MCP を呼び出し → 取得した経路を GeoJSON に変換 → KASUGAI Canvas へ自動追加

YouCam API（パーフェクト株式会社）

AI 肌解析、バーチャル試着、画像・動画生成など 50 種類以上の AI 機能を提供する API です。GIS とは分野が異なりますが、以下の活用が考えられます。

  • GIS への活用法：
    • 建物・構造物の外観を AI 生成し、3D モデル/テクスチャとして KASUGAI Canvas に重ねる
    • 都市景観シミュレーション：開発予定地の外観を生成し、周辺地形にドレープ
    • 観光・小売向け：店舗や商品の AR 試着映像を地図上の POI と連携
    • 画像解析系 API を利用し、ストリートビュー風画像から看板・建物を抽出して POI 化
  • エージェント連携例：「この地点に新しい商業ビルを建てたら景観はどう変わる？」→ 周辺カメラ視点を生成 → YouCam 画像生成 → 結果を Info パネルまたは 3D プレーンで表示

GMI Cloud

200 以上の AI モデルを推論できる AI ネイティブクラウドです。TrendAI™ Vision One を使ったセキュリティ機能も備えています。

  • GIS への活用法：
    • 衛星画像・航空写真を対象に、物体検出・変化検知・セグメンテーションモデルを実行
    • 検出結果（建物、道路、植生、駐車場など）を自動で GeoJSON レイヤー化
    • LiDAR/点群の分類モデル推論で、建物・樹木・地面を自動分類
    • 推論環境のセキュリティ監視：ANTIGRAVITY エージェントが外部データを取得する際の脅威分析・対処自動化
  • エージェント連携例：「このエリアの建物を AI で自動検出してレイヤー追加して」→ GMI Cloud 上の Vision モデルに航空写真タイルを投入 → 検出結果を GeoJSON 化 → KASUGAI Canvas へ追加

Google Cloud（協賛）

ハッカソンの必須技術となる Google Cloud プロダクトを、GIS 用途に絞って整理します。

  • Gemini Enterprise Agent Platform / Gemini API / ADK：自然言語からレイヤー追加意図を理解し、実行計画を立てる AI エージェントの中核
  • Cloud Run / Cloud Run functions：ANTIGRAVITY エージェント API、外部 API 連携、GeoJSON 変換処理をホスティング
  • Earth Engine：衛星画像・DEM・土地利用データの大規模分析。分析結果を KASUGAI Canvas 用 XYZ/GeoJSON タイルへエクスポート
  • BigQuery GIS：大規模空間データの集計・検索。例：「半径 1km 以内の全ての公園」などを SQL で抽出しレイヤー化
  • Cloud Storage / Firestore：生成したレイヤーファイル、メタデータ、キャッシュの保存
  • Vision AI / Natural Language AI / Translation AI：画像・テキスト・多言語の前処理。地名・住所の正規化、多言語属性表示など

今回追加する機能（実装計画）

KASUGAI Canvas は現在、CesiumJS フロントエンド（レイヤー表示・FlyTo・Share URL・ベクトル検索・属性/凡例パネル・.kasc 設定）とローカル静的サーバーで構成されており、AI・エージェント機能は未実装です。エージェントの「手足」となる機能はすでに揃っているため、今回追加するのは既存機能を自然言語から操作する頭脳部分です。

1. ANTIGRAVITY エージェント API（新規バックエンド／Cloud Run）

FastAPI + Gemini API（ADK）による新サービス。参加条件の「Cloud Run ＋ Gemini API / ADK」を充足する中核部分です。

エンドポイント機能
POST /agent/chat自然言語指示を受け、実行計画（レイヤー構成・FlyTo・資料生成）を返す
POST /agent/layers指示から .kasc 相当のレイヤー定義（JSON）を生成
POST /agent/sample-dataエリア・業種・目的から架空 GeoJSON サンプルを生成
POST /agent/reportレイヤー属性から課題抽出→資料（Markdown/HTML）＋パーマリンク生成

2. チャットパネル（フロントエンド新規タブ）

  • 既存のパネルタブ（Layers / Camera / Search / Share …）に 「Agent」タブを追加
  • 「○○の資料を作って」と入力 → エージェントの応答（追加レイヤー・FlyTo 実行・生成資料リンク）を表示
  • エージェントの行動ログ（取得データ・出典・ライセンス）を表示し、審査基準の可観測性に対応

3. レイヤー自動構成の実行層（フロントエンド側ブリッジ）

  • エージェントが返した JSON を既存の layerState / Inspector 形式に変換して即反映する applyAgentLayers() を実装
  • 新規コードは薄く保ち、既存の .kasc パーサー・FlyTo・凡例をそのまま再利用

4. サンプルデータ自動生成

  • Gemini に「春日井市の避難所 20 件、属性：収容人数・耐震・標高」等を生成させ GeoJSON 化
  • 既存のベクトル検索・属性表示・凡例がそのまま動く形式で出力し、本番データなしで GIS 体験を実現

5. 資料生成＋パーマリンク連携

  • 属性から課題を抽出し、「平面・内容・解決案」構成の資料を自動生成
  • 既存の Share URL 生成ロジック（#latitude=...&layers=...）を流用し、資料の各節に該当視点のパーマリンクを埋め込む

6. MCP 連携（拡張・任意）

ADK のエージェントに MCP クライアント／外部ツールを登録し、ANTIGRAVITY が必要と判断したときに自律的に呼び出します。取得結果はすべてGeoJSON への変換 → applyAgentLayers() で既存レイヤー機構へ追加という共通パターンに集約します。

6-1. 駅すぱあと API MCP サーバー（経路・到達圏レイヤー）
  • 接続方法：ADK の MCPToolset にヴァル研究所提供の MCP サーバーを登録し、経路探索ツール（駅名解決・経路検索）をエージェントから呼び出し可能にする
  • 変換処理：Cloud Run functions に POST /convert/route-to-geojson を実装。MCP の経路レスポンス（区間・駅リスト）を LineString（経路）＋ Point（駅・乗換駅）の FeatureCollection へ変換し、所要時間・運賃・路線名を properties に格納
  • 表示：経路は geojson: レイヤーとして追加し、駅ポイントは既存の属性表示・FlyTo と連動。乗換駅は色分けし凡例に反映
  • 到達圏（アイソクローン）：「渋谷から 30 分以内」の指示に対し、複数目的地への所要時間を MCP でバッチ照会 → 到達可能駅を集計 → 凸包/バッファで Polygon 化して到達圏レイヤーを生成
  • デモシナリオ：「春日井市役所から名古屋駅までの通勤ルートを地図に出して」→ エージェントが MCP 呼び出し → 経路レイヤー追加 → 経路全体が入る視点へ FlyTo → 資料に所要時間・運賃と経路パーマリンクを記載
6-2. GMI Cloud（航空写真・衛星画像の AI 解析レイヤー）
  • 接続方法：GMI Cloud の推論 API（OpenAI 互換エンドポイント）を ADK のカスタムツール detect_features_from_imagery として登録
  • 処理フロー：現在のカメラ範囲（bbox）から XYZ タイル座標を計算 → 航空写真タイルを取得 → GMI Cloud 上の Vision モデルで物体検出（建物・道路・駐車場・植生） → ピクセル座標を bbox から地理座標へ逆変換 → Polygon/Point の GeoJSON 化
  • 属性設計：properties に検出クラス・信頼度スコア・使用モデル名・推論日時を格納し、レイヤーの出典・鮮度を可視化（可観測性対応）
  • デモシナリオ：「この辺りの駐車場を検出してレイヤーにして」→ 現在視点のタイルを解析 → 検出結果レイヤー追加 → 「駐車場が少ないエリア」を課題として資料に反映
6-3. Vision AI（POI・テキスト抽出）
  • 接続方法：Cloud Vision API（テキスト検出・ランドマーク検出・オブジェクト検出）を ADK ツールとして登録
  • 活用例 1 — 看板・地名の POI 化：ユーザーがアップロードした現地写真・ストリート画像から OCR で店名・看板を抽出 → Geocoding で座標付与 → POI ポイントレイヤーとして追加
  • 活用例 2 — 資料画像の取り込み：既存の紙地図・PDF のスクリーンショットから凡例・注記テキストを抽出し、エージェントがレイヤー構成のヒントとして利用
  • 参加条件との関係：Vision AI は必須 AI 技術リストに含まれるため、Gemini API / ADK に加えて使用技術としてアピール可能

GIS 利活用促進の観点からの効果まとめ

各 MCP 連携が「KASUGAI Canvas — GIS 利活用を促進する Agentic AI エージェント」の目標（GIS で何ができるかを体験→理解→正しい導入判断・課題解決）にどう寄与するかを整理します。

連携GIS 利活用促進への効果解消する導入障壁
駅すぱあと API MCP 「動き・時間」の GIS 体験を提供。静的な地図では伝わらない「移動・所要時間・到達圏」を、話しかけるだけでレイヤー化。通勤圏分析・施設配置検討・防災避難計画など、GIS が意思決定に直結する場面を非専門家がその場で体験できる 「GIS は地図を描くだけ」という誤解。時間・コストという業務上の関心事と地図が結びつき、GIS の実用価値が伝わる
GMI Cloud 「データがなくても始められる」体験を提供。航空写真から建物・駐車場・植生を AI が自動抽出するため、整備済みの GIS データを持たない組織でも、いま見ている場所から即座にレイヤーが生まれる過程を体験できる。データ整備コストの見積り精度も向上 「使えるデータがないから GIS は導入できない」という最大の障壁。データ整備が導入の前提ではなく、AI で後追い可能であることを実証
Vision AI 「手元の資料・写真が GIS 資産になる」体験を提供。現地写真や紙地図・PDF という既存の業務資産を OCR で POI・レイヤー構成ヒントへ変換し、これまでの仕事の蓄積がそのまま GIS で活きることを実感できる 「GIS 導入 = ゼロからの作り直し」という心理的負担。既存資料からの移行パスを示し、導入の初期ハードルを下げる

3 つの連携に共通するのは、専門知識・本番データ・移行作業という従来の GIS 導入の三大障壁を、エージェントとの対話だけで乗り越えられることを体験してもらう点です。この体験が「GIS で何ができて、どんな課題が解決できるか」の理解を深め、正しい導入判断と課題解決につながります。

最小プロトタイプ（MVP）の範囲

機能 1〜3 と 5 が MVP です。3 分デモ動画では、「避難所の資料を作って」→ サンプルレイヤー自動追加 → FlyTo → 属性から課題抽出 → パーマリンク付き資料出力までの一連の流れを収めます。機能 4 は 1 の中に含めて実装し、機能 6 は時間があれば追加する優先順位とします。
