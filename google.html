AI 接続方式と利用規約上の判断

判断対象は「この接続方式でサービスに接続し、提供されるモデルを利用することが禁じられているか」です。以下は各利用者が自分のアカウントで正規認証し、利用可能なモデルを契約の利用枠内で使う構成についての判断です。OSS アプリ・自作ブリッジの配布と、配布者の AI アカウントの共有・AI サービス自体の再販は区別します。

接続方式公式資料の根拠本プロジェクトの判断
GitHub Copilot：アプリ → ブリッジ → 公式 SDK / Copilot CLI → モデルSDK 認証ガイドが、本人のログイン資格情報を使うデスクトップアプリ・開発／テスト環境を明示的に想定。採用。公式に想定された接続方式であり、この方式でのモデル利用を禁止する規定は確認されていません。
Devin：アプリ → ブリッジ → devin acp → モデル公式 ACP 連携ガイドが、ACP 対応クライアントからの子プロセス起動とブラウザ認証を案内。採用。公式の外部接続機構を使用しており、この方式でのモデル利用を禁止する規定は確認されていません。KASUGAI 自体が Cognition の公式製品・認定連携という意味ではありません。

上記の GitHub Copilot / Devin 経路について、ブリッジを挟むこと、自作 OSS アプリから呼ぶこと、通常の機能確認・回帰テストで自動呼び出しすること自体を一律に禁じる条項は、確認した資料には見当たりません。本人の利用枠・レート制限・組織ポリシーを守り、制限回避や第三者向けの共有バックエンド運用は行わない前提です。モデルへの会話・カメラ・レイヤー情報の送信自体を不採用理由にはしません（送信権限があり、サービスの禁止データに該当しないことが前提）。アクセス制御やツール制限の実装品質は、接続方式の可否とは別に確認します。

根拠となる規約：GitHub 追加製品規約（Copilot の契約別適用先）・GitHub 利用規約・GitHub AUP・Cognition 利用規約（§2）・Cognition AUP。

M365 / Microsoft Copilot を見送った理由

「M365 のモデル利用そのものが禁止」ではありません。以前検討した Web UI 自動化と、条件を満たして使う公式 API を分けて判断します。GitHub Copilot と Microsoft 365 Copilot は別サービスです。

  • 消費者向け Microsoft Copilot の Web UI 自動化：規約上の禁止が理由。Microsoft Copilot 使用条件の「WHO CAN USE COPILOT」は “Don’t use tools or computer programs (like bots or scrapers) to access Copilot.” と明示しています。画面への自動入力・送信・応答取得をブリッジ化する方式は採用しません。本人アカウント・ローカル利用だけでこの制限が解除されるわけではありません。
  • 職場・学校向け M365 Copilot の Web UI 自動化：正規のプログラム接続経路として採用しない方針。上記の消費者向け規約は、職場・学校・組織（Entra）アカウントには適用しないと明記されています。その条項を根拠に M365 も一律禁止とは断定しません。Web UI 自動化の許諾を確認できていない経路や、認証・アクセス制御・ボット対策の回避を前提とする経路は提供せず、連携を追加する場合は公式 API と適用契約に従います。
  • M365 Copilot 公式 Chat API：禁止ではなく、導入条件により標準連携を見送り。公式 Chat API（プレビュー）は自作アプリへの組み込みを想定しています。ただし、Microsoft 365 Copilot アドオンライセンス・アプリ登録・職場／学校アカウントの委任アクセスと必要権限への同意が前提です。確認時点の chat API 仕様では7権限すべてが必要で、個人 Microsoft アカウント・アプリケーション権限（ユーザーなしの app-only）は非対応です。

必要な7権限：Sites.Read.All・Mail.Read・People.Read.All・OnlineMeetingTranscript.Read.All・Chat.Read・ChannelMessage.Read.All・ExternalItem.Read.All。このうち ChannelMessage.Read.All などは管理者同意が必須であり、利用者が自分でログインするだけでは導入できません。管理者同意が必要ということと、実際の利用者本人が管理者でなければならないということは別です。

このため、組織の事前設定なしで使える標準ブリッジとしては見送っています。ライセンス・管理者同意等を整え、M365 Copilot APIs 使用条件に従う公式 API 連携は別途検討可能です。確認時点では /beta API で本番利用は非サポートと案内されており、製品への採用時には提供状況の再確認も必要です。

確認日：2026年10月13日。上記は公開規約・公式資料に基づく接続方式の判断であり、提供元による本アプリの個別承認や、用途を問わない適合保証ではありません。個別契約・組織ポリシー・規約改定がある場合はそれらを確認してください。

AI プロバイダの2系統（【API】と【ブリッジ】）

「AI プロバイダ」の選択肢は名前の先頭の接頭辞で2系統に分かれます。入力方法も動作モデルも異なるため、目的に応じて選びます。

【API】Gemini / OpenAI互換【ブリッジ】GitHub Copilot / Devin / 外部エージェント
接続先プロバイダの公式 API へブラウザから直接接続（HTTPS）ローカル等のエンドポイント（/agent）へ POST
設定するものAPIキー＋モデル（OpenAI互換はベースURLも）エンドポイントURL＋トークン（任意）＋BYOキー送信（任意）
AI 側の資格BYO キー、またはサーバーキー（/api/gemini）ブリッジ側が持つ（Copilot CLI ログイン等）。ブラウザにキーは不要
ツール実行方式function calling ループ — ツール結果を見て複数往復で判断するため多段操作に強い単発キュー — 応答の actions を一括実行。ツール結果を見た往復はしない
向いている用途高精度な地図操作・プラグイン生成・資料生成などの本体 AI既存の Copilot 契約や自作エージェント（外部実装）を繋いで使う
提供形態通常版GitHub Copilot / Devin の専用選択肢は V5 アプリ版のみ。外部エージェントは通常版でも利用可

どちらを選んでもチャット UI・地図操作・runCode・破壊的操作の確認ダイアログは共通です。ブリッジ系を選んだ場合のみ「エンドポイントURL・トークン・BYOキー送信」のブリッジ欄が表示され、GitHub Copilot / Devin ではさらにモデル選択と疎通ステータスが表示されます。

🤖 AIチャット（Gemini / OpenAI互換）

右下の Chat パネルから AI の function calling で地図を操作。「◯◯へ飛んで」「レイヤを消して」等をAIが実行。50ツールでカメラ・レイヤ・ベースマップ・検索・地形/効果・地下表示・断面クリップ・Flyパス・プロジェクト切替・データ取得/加工・プラグイン生成・資料生成（showReport＋パーマリンク）まで網羅（一覧は V3: AI 連携）。AI移動はドローン視点（対象地上+200m・-30°）が既定。管理（⚙）→ AI → チャット で API キー・モデルを設定。Cloudflare/Cloud Run にサーバーキー（/api/gemini）があればキー未設定でも動作

AI プロバイダは Gemini（既定）のほか「OpenAI互換」を選択可能。GitHub Models（GitHub PAT）・OpenAI・Azure OpenAI・Ollama・LM Studio など chat/completions 互換エンドポイントに、ベースURL・キー・モデル名を指定して接続します。GitHub Copilot 契約を使いたい場合はエージェント連携の copilot-bridge/ を参照

🗺️ Photorealistic 3D Tiles

管理（⚙）→ Google Maps で Maps Platform API キーを設定し、「Photorealistic 3D Tiles」を ON にすると、Google のフォトリアル3Dタイルがレイヤ一覧へ自動追加され表示されます。Map Tiles API は従量課金です

🔍 Maps Platform の検索・ Places ・ Street View

Maps API キーを保存すると、住所検索タブのプロバイダに「Google」が追加されます。Geocoding API と Places テキスト検索を並列で呼ぶハイブリッド検索で、住所・施設名・キーワードのいずれにも対応します。検索結果の「SV」ボタンや「地図をクリック → Street View」でストリートビューを別タブで開き、「候補ラインを表示」で撮影済み道路の青いラインを地図上に重ねられます。AIチャットには searchPlaces（Places テキスト検索）・openStreetView（ストリートビューを別タブで開く）ツールが有効時のみ公開され、「近くのカフェを探して」「この地点のストリートビューを見せて」といった指示に対応します

🔑 API キー管理

Gemini キーは Google AI Studio、Maps キーは Google Cloud Console で発行。キーは localStorage にのみ保存され、.kasc エクスポートには含まれません

Google Cloud で有効化・キー制限への追加が必要な API:

  • Map Tiles API — Photorealistic 3D Tiles
  • Geocoding API — 検索プロバイダ「Google」（ハイブリッド検索の住所側）
  • Places API (New) — ハイブリッド検索の施設・キーワード側 / AIツール searchPlaces
  • Street View Static API — Street View のメタデータ確認（「SV」ボタン・地図クリック・AIツール openStreetView。パノラマ自体は Google マップを別タブで開くだけなので API 不要）

Geocoding / Places / Street View の Web サービス API は HTTP リファラー制限付きキーを拒否します。リファラー制限をかけたい場合は「Web サービス用キー」欄に制限なしの別キーを設定してください（Map Tiles API のみリファラー制限が有効なので、上の「Maps API キー」に制限付きキーを入れる運用が可能です）。Street View 候補ラインは Google マップ内部のカバレッジデータ（キー不要・非公式）を使用します

サーバー配布（BYO 不要化）：バックエンド（Cloud Run・Cloudflare Pages/Workers）のシークレットに GOOGLE_MAPS_API_KEY を設定すると、/api/capabilities が google.mapsApiKey を通知し、ブラウザに Maps キーが未保存の場合に自動登録します。訪問者は何も入力せずに Maps 系機能を使えます（BYO キーが保存済みならそちらが優先）。Maps キーはタイル URL 等に埋め込まれる設計上の公開キーなので、保護は秘匿ではなく GCP コンソールの HTTP リファラ制限（https://<配信ドメイン>/*）で行ってください

APIキー未設定でも /fly /layers /layer /basemaps /search /camera で地図操作を試せます

履歴はプロジェクト単位で localStorage に永続化（最大200件・ヘッダーの🗑でクリア）。AIのツール実行は「実行: ...」とログ表示

🔐 セキュリティ

🤝 エージェント連携

ADK等のフレームワークは内蔵せず、外部で構築されたエージェント（Antigravity等）をAPIで呼び出す構成。アプリが担うのはチャットUI・地図操作・応答往復のみで、静的WEBサーバーのまま成立します。管理（⚙）→ AI → チャット で「AI プロバイダ」を「外部エージェント (ブリッジ)」にし、ブリッジ欄にエンドポイントURL・Bearerトークン（任意）を設定して保存すると、チャット入力がそのエンドポイントへ POST されます。要求JSONは {message, project, camera, layers, history, tools}（tools は現在公開中のツール宣言・functionDeclarations 形式）、応答JSONは {reply, actions:[{name,args}]} で、actions はAIチャットと同名のツール（flyTo・setLayerVisible 等）として順次実行されます。エンドポイント側ではこのオリジンからの CORS 許可が必要です

GitHub Copilot 接続：アプリ版では起動時に同梱の copilot-bridge/（GitHub Copilot SDK 使用・要 Copilot サブスクリプション＋Node.js）が自動起動し 127.0.0.1:8511 で待受けます。管理（⚙）→ AI → チャット の「AI プロバイダ」に「GitHub Copilot」が表示される（アプリ版のみ）ので、選んで保存すれば疎通したブリッジへ自動接続され、Copilot を内蔵AIとして利用できます。通常版ではこの選択肢は表示されませんが、閲覧者のマシンでブリッジを手動起動し（既定 http://127.0.0.1:8788/agent・セットアップは同 README を参照）、プロバイダ「外部エージェント」から接続すれば利用できます。本アプリでは、ブラウザからモデルへ直接接続する代わりに公式 SDK / CLI をローカルブリッジ経由で利用します

Devin 接続：アプリ版の「Devin」を選択して保存すると、devin-bridge/（127.0.0.1:8512）へ接続します。ブリッジは devin acp に対して ACP 認証を行い、利用者自身のアカウントでモデルを利用します。ブラウザ認証または本人の DEVIN_API_KEY を使用し、ローカル CLI のログインだけに依存しません。手動起動時の既定ポートは 8789 です。接続方式の判断・利用条件と M365 を見送った理由も参照してください。

🗂️ データソース（MCP 接続）

管理（⚙）→ AI → データソース でリモート MCP サーバー（Model Context Protocol・Streamable HTTP）を登録すると、そのサーバーのツールが AI チャットへ合成され、「Box の資料を検索して」等の指示で外部データを参照できます。Box は公式リモート MCP（mcp.box.com）専用ボタンがあり、Client ID を入れて OAuth 2.0 + PKCE でブラウザ内認証が完結します（Box Developer Console で Custom App 作成＋このアプリの URL をリダイレクト URI に登録が必要。Enterprise は Admin Console での MCP 有効化が前提）。その他の MCP サーバーは URL・Bearer トークン（任意）で追加できます。トークンは BYO として localStorage にのみ保存。読み取り系ツールのみ既定公開で、書き込み系は設定を ON にしても実行ごとに確認ダイアログが出ます。CORS 非対応のサーバーは POST /api/mcp 中継（ローカル版・Workers・Cloud Run で提供・BYO トークン転送のみ）に自動フォールバックします

🧩 AIプラグイン生成（自己拡張）

チャットに「〜するプラグインを作って」と頼むと、AIがコードを生成してブラウザ内 IndexedDB に保存・即時有効化。適用前にコード全文の確認ダイアログが出ます。読み込みエラーはAIへ返るため、修正→再保存の自律ループが回ります。管理（⚙）→ AI → プラグイン で一覧・有効化・コード確認・.kasp 出力/取込・削除が可能。ストレージ保存のため配布物とは分離され、気に入ったものだけ PLUGIN/ に登録して公開できます

📊 データ取得・加工・表示パイプライン

fetchData（外部URL取得・CORS前提）と getLayerGeoJson（読込済みレイヤーのGeoJSON取り出し・描画切り捨て時も全件）でデータを取得し、runCode で任意の加工・集計・変換を行い、addDataLayer で GeoJSON を直接レイヤー表示。feature の properties に simplestyle 属性（marker-color/fill/stroke/description 等）を書けば色分け・ポップアップも制御できます。一時レイヤーは .kasc には含まれません。URL・ファイル指定のレイヤーを .kasc に永続追加する場合は addLayer（geojson/layer/geoparquet/flatgeobuf/gpkg/duckdb/sql の各行タイプに対応、duckdb は where=/limit=/bbox=auto 等のオプション指定可）を使います

🌐 実行環境ティア（公開/ローカルの使い分け）

AI機能は操作の影響範囲で3ティアに分かれます。static（静的配信のみ）と workers（Cloudflare Pages/Workers 公開環境）では、セッション内に閉じる安全な機能（地図操作・runCode・データ加工・IndexedDBプラグイン生成）を誰でも利用可能。local（ローカルサーバー版）では永続化・共有・システムに触れる高権限機能（/api/fetch によるCORS回避の取得プロキシ、/api/plugins による PLUGIN/ へのプラグイン公開、ファイル保存）が使えます。フロントは /api/capabilities で能力を検出してツール・UIを出し分け、バックエンド無しでも安全機能のみで動作します。昇格ルートは「IndexedDB草稿 → .kasp出力 → ローカル版で公開ボタン → PLUGIN/」です

ローカルサーバー版の独自API（公開環境では無効）

GET  /api/capabilities   → {"tier":"local","features":["fetchProxy","pluginWrite","fileWrite",...]}
GET  /api/fetch?url=...  → CORS回避のGETプロキシ（http/httpsのみ・30秒・20MB上限）
POST /api/mcp?url=...    → リモート MCP サーバーへの中継プロキシ
                           （Workers/Cloud Run にも同パスあり。Authorization・
                           セッションヘッダ・ボディをそのまま転送。
                           SSRF 制限は /api/fetch と同じ・応答32MB上限）
POST /api/plugins        → {"id","name","version","description","layer","code"}
                           PLUGIN/<id>/plugin.js・manifest.json を作成し plugins.json に登録
DELETE /api/plugins/{id} → プラグインの公開取り消し（PLUGIN/<id>/ と plugins.json 登録を削除）
GET  /api/files?project= → projects/<project>/DATA/ 内のファイル一覧（{name,size,modified}[]）
PUT  /api/files/{project}/{path} → DATA/ へボディを書き込み（サブフォルダ可・64MB上限）
DELETE /api/files/{project}/{path} → DATA/ 内のファイルを削除

プラグインIDは半角英数・-・_ のみ（64文字まで）。公開・削除は実ファイルを書き換えるため、フロント側では必ず確認ダイアログが出ます。公開環境（Pages/Workers）に同等の無認証書き込みAPIを置かないでください。
