GIS とはどうあるべきか

渋谷ミニハッカソンで痛感したのは、多くの現場で GIS が「地図を描くツール」にとどまり、「場と情報を一体化させて理解を支援する基盤」として使われていない点です。KASUGAI Canvas は、本来あるべき GIS の姿を実現することを目指します。

一番大事なこと：GIS で「何ができて、何が解決できるか」を先に体験する

結局、最も重要なのは、「GIS を使うことで何ができて、どんな課題が解決できるか」を本番導入前に体験できるかということです。GIS 導入が進まない、あるいは導入されても活用されない現場の多くは、GIS 自体の理解が不足していることが原因です。

そのためのエージェントこそが、KASUGAI Canvas の ANTIGRAVITY 情報レイヤーです。

  • 体験を先に：本番データを必要とせず、サンプル・資料・GIS が連動した状態で「GIS ならではの理解」を体験
  • 理解を深める：地図と情報の一体化、レイヤーの切り替え、FlyTo・属性表示など、GIS の利点を実感
  • 正しい導入判断へ：体験を通じて「本当に必要なデータ・機能・運用」が見え、無理な導入や失敗を減らす

ANTIGRAVITY エージェント：目標と 3 つの機能

ANTIGRAVITY エージェントの目標は、利用者を正しい GIS 導入判断と課題解決へ導くことです。そのために、以下 3 つの機能が必要です。

自然言語からレイヤーと属性を自動構成

「○○の資料を作って」と話すだけで、必要な地図レイヤー・属性・凡例・カメラ位置を自動で選定・構成する。

現実に近いサンプルデータを自動生成し、GIS の利点を可視化・体験化

本番データがなくても、エリア・業種・目的に応じた架空サンプルを生成。地図と情報の一体化、レイヤー切り替え、FlyTo、属性表示など、GIS ならではの理解を実感してもらう。

属性から課題を抽出し、平面・内容・解決案を提示した資料作成

レイヤー・属性から課題を抽出し、その平面（地図上の状況）・内容・解決案をまとめた資料のベースを自動生成。資料には GIS へのパーマリンクを付与する。

目標：正しい GIS 導入判断と課題解決へ導く

上記 3 つの機能を通じて、利用者は本番導入前に「GIS で何ができて、どんな課題が解決できるか」を体験します。その結果、「本当に必要なデータ・機能・運用」が見え、無理な導入や失敗を減らし、課題解決につながります。

ANTIGRAVITY エージェントの本質：資料を作る・見せる・説明する

ANTIGRAVITY エージェントは、資料の基本である 作る → 見せる → 説明する を自動化するエージェントです。

資料の基本ANTIGRAVITY の機能具体的な動作
作る自然言語からレイヤーと属性を自動構成「○○の資料を作って」と話すだけで、必要なレイヤー・属性・サンプルデータを自動生成する
見せる現実に近いサンプルデータを自動生成し、GIS の利点を可視化・体験化地図上にサンプルを表示し、レイヤー切り替え・FlyTo・属性表示で GIS 体験を提供する
説明する属性から課題を抽出し、平面・内容・解決案を提示した資料作成属性から課題を読み取り、平面・内容・解決案をまとめた資料を作成する

この 3 ステップを通じて、資料は「PDF への地図貼り付け」ではなく、GIS と連動した生きた理解資料となります。そして、その体験が正しい GIS 導入判断と課題解決へ繋がります。

資料のベース作成と GIS パーマリンク連携

最も重要なのは、資料は資料として必要なものであるという点です。資料は会議の進行、結論の提示、合意形成のための要約として不可欠です。ANTIGRAVITY エージェントは、GIS 上のレイヤー・属性から課題を読み取り、平面（地図上の状況）・内容・解決案をまとめた資料のベースを自動作成します。

資料に載せきれない背景・範囲・詳細は GIS 側に置き、資料にパーマリンク（QR や短縮 URL）を載せることで、資料と GIS を双方向に連動させます。

なぜパーマリンクなのか

  • 資料の要約性を維持：資料は簡潔なままで、詳細は GIS へ誘導
  • 深い理解へ誘導：「なぜこの範囲か」「背景データは何か」「周辺の状況は」などを地図上で探索可能に
  • 会議の一体感：参加者全員が同じ URL から GIS を開き、同一視点・レイヤーで議論できる
  • 判断の加速：空中戦を減らし、必要な情報に即座にアクセスすることで、より速い課題解決・意思決定を実現

想定される使い方

  1. 資料の該当部分に https://kasugai-canvas.example/#cam=...&layers=... 形式のパーマリンクを配置
  2. 会議参加者がリンクを開くと、KASUGAI Canvas が即座にその場所・レイヤー・属性を表示
  3. 必要に応じてレイヤーを追加・非表示・属性をクリックし、深掘りを行う
  4. 新たな視点が見つかったら、新しいパーマリンクを生成し資料にフィードバック

ANTIGRAVITY との関係

資料作成時に、ANTIGRAVITY エージェントが「資料に載せるべき GIS 視点」を自動提案し、パーマリンク付きで資料と GIS を同時生成します。資料と GIS がお互いを補完し合うことで、会議の一体感と意思決定のスピードが向上します。

ANTIGRAVITY 情報レイヤーは、上記 3 つの機能を自然言語で実現し、「正しい GIS 導入判断と課題解決へ導く」ことを目指すエージェントです。「○○の資料を作って」と話すだけで、作る → 見せる → 説明する という資料作成の基本が自動化され、場と情報が一体化した GIS 体験が構築されます。

課題発掘

地図情報の伝わりにくさ

「地図情報がどのようなものか、何ができるか」が相手に正しく伝わりにくい。PDF 等の資料では実際の内容が正確に伝わらない。

地図と情報の分断

地図と情報が分断されやすく、地図が資料から孤立した「作り物」として残ってしまう。本来の価値が伝わらない。

空中戦・取り残され

会議等で位置や場所に詳しくない人が取り残され、理解が深まらないまま会議が進む「空中戦」が起きる。

現在の対応とつらい点

段階内容課題
事前の行動説明できる事例をあらかじめ集めるGIS 自体の理解が浅く、何を示せばよいか分からない。実例も手間で作れない
資料化PDF 等にまとめる実際の地図・空間情報の操作性や詳細が正確に伝わりにくい
完成時喜ばれるただし、作るまでに情報の伝達・分断・空中戦が発生しやすい

出展タイトルは 「KASUGAI Canvas — GIS 利活用を促進する Agentic AI エージェント」 です。KASUGAI Canvas を、Agentic AI（ANTIGRAVITY エージェント）が空間情報レイヤーを自動構築し、GIS の利活用を促進するプラットフォームとして出展します。GIS 本番導入前の「フロントローディング」として、利用者が GIS の利活用を体験し、正しい導入判断と課題解決につなげることを重視します。

提出スコープ（2026/10/11 見直し）：提出締切（10/15）までの残り期間を考慮し、当初計画した MCP・協賛 API 連携はスコープ外（将来拡張）とし、V3（AI 連携）の強化として — Cloud Run を KASUGAI Canvas の稼働・保存先に、Gemini API を GIS 制御に使う、実装済みの構成のみで出展を組みます。本ページでアピールする機能はすべて実装済みであり、残作業は Cloud Run デプロイ・本番検証・提出物（構成図・デモ動画）のみです。

課題設定

多くの現場で GIS が導入に至らない、あるいは導入後も活用されない状況があります。原因は GIS 自体の理解不足と、「何ができて、どんな課題が解決できるか」を導入前に体験できる環境がないことです。本ハッカソン出展テーマとしては、「GIS に何ができて、どう課題解決に繋げられるか」を本番導入前に体験できる ANTIGRAVITY エージェントを作り、GIS の利活用を促進することに位置づけます。

解決策：ANTIGRAVITY 情報レイヤー（GIS 利活用を促進する Agentic AI エージェント）

本番導入前に、自然言語や文脈から「今必要な情報レイヤー」を自律的に選定・追加するエージェント機能を提供します。重力に逆らって情報が自動的に「浮かび上がる」ように、必要なレイヤーが勝手に追加される体験を目指します。

ANTIGRAVITY の本質は、「GIS で何ができて、どんな課題が解決できるか」を本番前に体験してもらうためのエージェントにあります。サンプルデータ・資料・GIS を連動させることで、利用者の GIS 理解を先に深め、正しい導入判断と課題解決への期待値を形成します。以下の要素はすべて提出スコープ内の実装済み機能です。

  • 文脈理解：ユーザーの質問・目的・現在のカメラ視点・レイヤー一覧を Gemini API で解析
  • レイヤー構成：必要なレイヤー・属性・カメラ位置を推定し、addDataLayer/addLayer/flyTo 等のチャットツールとしてブラウザが順次実行
  • データ生成・取得：Gemini が架空サンプル GeoJSON を生成し addGeoJsonLayer／addDataLayer で投入。fetchData ツールで外部データ取得（CORS 範囲）
  • ガバナンス：生成データへの出典・生成時刻の付与、破壊的ツールの確認ダイアログ、起動制御モード（トークン／Cookie ゲート／IAP）、GCS 署名付き URL による秘匿データ配信

  • GIS への活用法：
    • 出発地→目的地の経路を GeoJSON 化し、KASUGAI Canvas の geojson: レイヤーとして追加
    • 駅・バス停をポイントレイヤーで表示し、 FlyTo や属性表示と連動
    • 所要時間や運賃を属性として持たせ、ルート比較レイヤーを重ねる
    • 「渋谷から新宿まで30分以内で行ける場所」など、到達圏（アイソクローン）を生成
  • エージェント連携例：「渋谷駅から横浜駅までの電車ルートを地図に表示して」→ Gemini が Ekispert MCP を呼び出し → 取得した経路を GeoJSON に変換 → KASUGAI Canvas へ自動追加

YouCam API（パーフェクト株式会社）

AI 肌解析、バーチャル試着、画像・動画生成など 50 種類以上の AI 機能を提供する API です。GIS とは分野が異なりますが、以下の活用が考えられます。

  • GIS への活用法：
    • 建物・構造物の外観を AI 生成し、3D モデル/テクスチャとして KASUGAI Canvas に重ねる
    • 都市景観シミュレーション：開発予定地の外観を生成し、周辺地形にドレープ
    • 観光・小売向け：店舗や商品の AR 試着映像を地図上の POI と連携
    • 画像解析系 API を利用し、ストリートビュー風画像から看板・建物を抽出して POI 化
  • エージェント連携例：「この地点に新しい商業ビルを建てたら景観はどう変わる？」→ 周辺カメラ視点を生成 → YouCam 画像生成 → 結果を Info パネルまたは 3D プレーンで表示

GMI Cloud

200 以上の AI モデルを推論できる AI ネイティブクラウドです。TrendAI™ Vision One を使ったセキュリティ機能も備えています。

  • GIS への活用法：
    • 衛星画像・航空写真を対象に、物体検出・変化検知・セグメンテーションモデルを実行
    • 検出結果（建物、道路、植生、駐車場など）を自動で GeoJSON レイヤー化
    • LiDAR/点群の分類モデル推論で、建物・樹木・地面を自動分類
    • 推論環境のセキュリティ監視：ANTIGRAVITY エージェントが外部データを取得する際の脅威分析・対処自動化
  • エージェント連携例：「このエリアの建物を AI で自動検出してレイヤー追加して」→ GMI Cloud 上の Vision モデルに航空写真タイルを投入 → 検出結果を GeoJSON 化 → KASUGAI Canvas へ追加

Google Cloud（協賛）

ハッカソンの必須技術となる Google Cloud プロダクトを、GIS 用途に絞って整理します。

  • Gemini Enterprise Agent Platform / Gemini API / ADK：自然言語からレイヤー追加意図を理解し、実行計画を立てる AI エージェントの中核
  • Cloud Run / Cloud Run functions：AI プロキシ・外部 API 連携、GeoJSON 変換処理をホスティング
  • Earth Engine：衛星画像・DEM・土地利用データの大規模分析。分析結果を KASUGAI Canvas 用 XYZ/GeoJSON タイルへエクスポート
  • BigQuery GIS：大規模空間データの集計・検索。例：「半径 1km 以内の全ての公園」などを SQL で抽出しレイヤー化
  • Cloud Storage / Firestore：生成したレイヤーファイル、メタデータ、キャッシュの保存
  • Vision AI / Natural Language AI / Translation AI：画像・テキスト・多言語の前処理。地名・住所の正規化、多言語属性表示など

提出スコープ：実装済み機能で構成

KASUGAI Canvas は v5.10.0 時点で、CesiumJS フロントエンド（レイヤー表示・FlyTo・Share URL・ベクトル検索・属性/凡例パネル・.kasc 設定）に加え、AIチャット（Gemini function calling・48種のツール＝カメラ/レイヤー/検索/データ加工/資料生成まで網羅）・外部エージェント接続・Google Maps Platform 連携・ローカルファイル保存が実装済みです。さらに提出構成（Cloud Run での稼働・保存＋Gemini API による GIS 制御）も agent/ の FastAPI サービス1つに実装済みのため、提出に必要な機能に新規実装はありません。残作業はデプロイ・本番検証・提出物のみです。

Cloud Run サービス構成（実装済み）

agent/ の FastAPI サービス1つで、KASUGAI Canvas 本体（静的配信）・GIS 保存 API・AI プロキシを Cloud Run 上に同居させます。プロジェクト設定・データの保存先は Cloud Storage（GCS・未設定時はローカルストアにフォールバック）、AI 制御はブラウザ内蔵のエージェントが Gemini API（function calling・48種のチャットツール）を直接実行します。サーバー側のエージェント実装は廃止し、Cloud Run は「KASUGAI の稼働・保存先＋キー隠蔽プロキシ」に集約する構成です。

エンドポイント・機能内容
POST /api/gemini内蔵AI向けの薄いキー隠蔽プロキシ。ブラウザの generateContent リクエスト（{contents, systemInstruction, tools, generationConfig, model}）にサーバーの GEMINI_API_KEY を注入して転送。推論ループ・ツール実行・地図操作はすべてブラウザ側。model 必須・GEMINI_MODELS 許可リスト・1MB 上限・レート制限・認証モードのトークン/Cookie/IAP で保護可能。キーを持たない審査員・訪問者でも内蔵AIの全機能がそのまま使える
POST /api/auth・POST /api/kascID/PASS ログインで HMAC トークンを発行し、プロジェクト設定（.kasc）を GCS の kasc/<ID> へ保存・ログイン時に一括返却。起動時に同梱 web/projects/*/*.kasc を冪等シード
GET/PUT /api/data/<key>gs:// 秘匿データの保存・配信。GET は GCS V4 署名付き URL へ 302（データがコンテナを通らない直接転送。未整備環境は Range 対応プロキシ配信にフォールバック）
起動制御 KASUGAI_AUTH_MODE=5/6/75=API・データのみトークン保護 / 6=kasugai_session Cookie 全ゲート / 7=Cloud IAP 委譲。/auth-methods.json を環境変数から動的応答するため、モード変更にイメージ再ビルドは不要
  • 自律実行：function calling ループはブラウザ側で回り、48種のチャットツール（カメラ・レイヤー・検索・データ加工・資料生成まで網羅）を直接実行する。レイヤー自動構成・サンプルデータ生成（Gemini が GeoJSON を生成し addGeoJsonLayer で投入）・showReport による資料出力・buildShareUrl による視点パーマリンク埋め込みはすべて内蔵ツールで完結
  • キー方式：BYO（Bring Your Own）キー登録済みのブラウザは Gemini を直接呼び（キーは localStorage に閉じサーバーへ送らない）、未設定のブラウザは /api/gemini 経由でサーバーキーを使う。能力通知は GET /api/capabilities の features:["aiProxy"] で行われフロントが自動切替
  • 外部エージェント窓口：フロントのエージェント設定で任意のエンドポイントURLを指定すれば、{message,project,camera,layers,history,apiKey?} → {reply,actions,report} 契約の外部実装を差し込める（本リポジトリにはサーバー側実装を同梱しない）

詳細は agent/AUTH_MODES.md・auth/cloudrun.html。審査用の公開 URL はモード 0（認証なし＋レート制限）で運用し、保存・認証系のデモは動画内でモード5の流れを見せる想定です。

チャットパネル・エージェント接続（実装済み）

  • 実装済：内蔵AI（Gemini function calling・48ツール）が本体。/api/capabilities が aiProxy を通知する環境では BYO キー未設定でもそのまま動作し、審査員が無設定で使える。BYO キー登録時はサーバーを介さず直接呼ぶ
  • 実装済（v4.20.0）：外部エージェント設定（エンドポイントURL・Bearerトークン・有効化トグル）も残置 — 外部のエージェント実装があれば差し込める拡張窓口（サーバー側実装は同梱しない）
  • ツール実行はチャットにシステムメッセージとして記録済み。出典・ライセンスは生成 GeoJSON の properties・attr= 出典で表示し、審査基準の可観測性に対応

レイヤー自動構成の実行層（実装済み）

  • 実装済（v4.20.0）：エージェント応答の actions:[{name,args}] をチャットツールと同名で順次実行する機構が applyAgentLayers() の役割を担う
  • 既存の .kasc パーサー（applyInspector/addLayer）・FlyTo・凡例をそのまま再利用

サンプルデータ自動生成（実装済み）

  • 内蔵AIが Gemini に「春日井市の避難所 20 件、属性：収容人数・耐震・標高」等を生成させ、addGeoJsonLayer／addDataLayer ツールでそのままレイヤー化する
  • 生成 GeoJSON の properties に出典・生成時刻・「AI生成サンプル」の旨を付記するよう指示でき、データの性格を可視化する
  • 既存のベクトル検索・属性表示・凡例がそのまま動く形式で出力し、本番データなしで GIS 体験を実現

資料生成＋パーマリンク連携（実装済み）

  • 属性から課題を抽出し、「平面・内容・解決案」構成の資料を自動生成（Markdown/HTML）
  • showReport アクション（実装済）：エージェント応答の report フィールドまたは同名アクションで資料をモーダル表示＋ファイルダウンロード。Markdown は簡易レンダリング（リンククリック可）、HTML は sandbox 付き iframe で隔離表示
  • buildShareUrl ツール（実装済）：座標・視点を引数指定してURLを組み立てられ、資料の各節に視点別パーマリンクを埋め込める（URL形式は既存の ?longitude=...&latitude=...&height=...&project=... を踏襲）
  • QRコード・短縮URLは将来拡張とし、MVP ではURLリンク埋め込みとする

提出 MVP とデモシナリオ

提出 MVP はすべて実装済みです。3 分デモ動画では、「避難所の資料を作って」→ サンプルレイヤー自動追加 → FlyTo → 属性から課題抽出 → パーマリンク付き資料出力の一連の流れをそのまま収録します。保存面のアピールとして、認証モードでのログイン → .kasc が GCS に保存され再訪時に復元される流れも動画に含めます。
