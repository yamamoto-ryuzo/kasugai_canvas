3. Cloudflare 認証（cloudflare）：Pages 実装

概要

Cloudflare Pages + Pages Functions を使ったサーバーレス ID/PASS 認証です。ID/PASS は環境変数、.kasc の内容は Cloudflare KV に登録しておき、認証成功後にその内容を取得してアプリを起動します。安全な本番運用に推奨します。

この方式のみ .kasc の読み書きが可能です。他の方式（0〜2）では .kasc は静的ファイルからの読み取り専用で、「適用」はブラウザ内への反映のみです。この方式では「適用」が KV への保存も行います。

Cloudflare 認証は将来 Workers 実装など別バリアントを追加できるよう、本実装を「Pages 実装」として位置付けています（control: 3 の選択子は共通です）。

推奨デプロイ構成

データ種別ごとに配置先を分け、無料枠内で秘匿性と速度を両立させる構成です。

静的配信（リクエスト無制限無料・2万ファイル/25MiB 上限）
  └─ HTML/JS/CSS

外部タイルサービス or R2 公開バケット（認証なし）
  └─ タイル（PMTiles または地理院タイル等の外部サービス）
     ※ R2 公開バケットの読み出しは無料枠 1,000万回/月（Class B）まで

Functions 認証ゲート（無料枠 10万リクエスト/日）
  ├─ /api/auth, /api/kasc
  └─ 秘匿 GeoJSON 等（R2 バインド経由で配信）※今後の拡張予定

Cloudflare KV
  └─ .kasc（kasc:<プロジェクトID>）

静的配信はファイル数・サイズの上限があるため、タイルのような大量ファイルは置けません。公開データは R2 公開バケットか外部タイルサービスを使います。R2 は1ファイル最大5TiB・転送料（egress）無料で、読み出しは無料枠 1,000万回/月（Class B オペレーション）までです。カスタムドメイン経由にして CDN キャッシュを効かせると実際の R2 アクセス数をさらに減らせます。

利用シーン

  • インターネットや不特定多数からアクセスされる本番運用
  • ID/PASS と .kasc 設定情報をサーバー側で管理したい場合
  • 静的アセットのみの Workers プロジェクトでは環境変数・バインディングを設定できないため、Pages プロジェクトとしてデプロイしてください

起動と設定

web/auth-methods.json の control を 3 に設定すると、この認証方式が選択されます。

{
  "control": 3
}

ブラウザで https://<your-site>/ を開くだけで起動します。

デプロイ手順（Pages プロジェクト）

  1. ダッシュボード → Workers & Pages → Pages でプロジェクトを作成します（Workers ではありません）。
  2. Git 連携の場合は出力ディレクトリを web に設定するか、リポジトリルートで直接アップロードします。
npx wrangler pages deploy web

リポジトリルートの functions/ が自動検出され、/api/* エンドポイントとして動作します。

環境変数

Pages プロジェクト → Settings → Environment variables（環境変数）に設定してください。

.dev.vars などのローカルファイルは git 管理外とし、本番環境では必ずダッシュボード経由で管理してください。

KASUGAI_AUTH_USER      = ユーザーID
KASUGAI_AUTH_PASS      = パスワード
KASUGAI_TOKEN_SECRET   = 署名鍵（任意・未設定時は KASUGAI_AUTH_PASS）

.kasc 登録手順（Cloudflare KV）

.kasc の内容は Cloudflare KV に登録します。ID/PASS 認証後にのみ取得できます。

  1. ダッシュボード → Workers & Pages → KV でネームスペースを作成します。
  2. Pages プロジェクト → Settings → Bindings → Functions で、ネームスペースを KASUGAI_KV という変数名でバインドします。
  3. キー kasc:<プロジェクトID> に .kasc の内容を登録します（例：kasc:default）。
  4. デプロイから元の .kasc は削除してください（KV に無いプロジェクトは静的ファイルが読まれるため、残すと公開されます）。
wrangler kv namespace create KASUGAI_KV
wrangler kv key put --binding KASUGAI_KV "kasc:default" --path web/projects/default/kasugai_canvas.kasc

KV の書き込みが全エッジへ反映されるまで最大60秒程度かかります。

.kasc の保存

この認証方式でログイン中は、インスペクターの「適用」ボタンが POST /api/kasc 経由で KV に保存します（静的ホスティング時は従来どおりエクスポート運用）。

保存にはログイン時に発行される署名トークン（有効期間12時間）を使います。署名鍵は環境変数 KASUGAI_TOKEN_SECRET（未設定時は KASUGAI_AUTH_PASS）です。

セキュリティ上の注意

  • 保護できるもの：アプリ起動制御（サーバーレス ID/PASS 認証）、.kasc 設定情報の内容（ID/PASS 認証後に Cloudflare KV から取得）
  • 保護できないもの：HTML/JS/CSS 等の静的ファイル、静的配信に置いた DATA/ 内の画像・GeoJSON 等、R2 公開バケットの内容
  • 秘匿データ（GeoJSON 等）を保護したい場合は R2 に配置し、Functions バインド経由で認証付き配信とする方針です（配信エンドポイントは今後の拡張予定）。なお Functions 経由の配信は1ファイルごとにリクエスト枠（10万/日）を消費します
  • 静的ファイル自体を含めて完全に保護したい場合は、Cloudflare Access（Zero Trust）を使うか、Worker スクリプトで全リクエストをゲートする Workers 実装が必要です
