V3: AI 連携

Gemini・OpenAI互換 API（GitHub Models・OpenAI・Ollama 等）・GitHub Copilot（ブリッジ経由）を使った AI チャットによる地図操作と、ブラウザ内コード実行の基盤です。詳細・設定手順は Google 連携・AI を参照してください（経路ごとの通常版/アプリ版対応は同ページの「AI の利用形態」表を参照）。

通常版とアプリ版の違い：AI チャット本体・地図操作・コード実行・プラグイン生成は両方で使えます。アプリ版（ローカル exe）だけが持つのは /api/fetch・/api/plugins・/api/files などの高権限ツール群と、GitHub Copilot プロバイダ（選択肢はアプリ版のみ表示。起動時に copilot-bridge を子プロセス化し 127.0.0.1:8511 で待受け・要 Node.js）です。通常版で手動ブリッジの Copilot を使う場合はプロバイダ「外部エージェント」から接続してください。

🗨️ AI チャット（Gemini / OpenAI互換）

管理（⚙）→ AI → チャット で Gemini API キーを登録すると、右下のチャットパネルから自然言語で地図を操作できます。ブラウザから Gemini API を直接呼び出す構成（BYO = Bring Your Own キー方式：各ユーザーが自分の API キーを登録して使う）で、静的配信のまま利用可能です。キーの供給経路は2つあり、BYO キーが無い環境でも、バックエンド（Cloudflare Pages/Workers・Cloud Run）が POST /api/gemini（aiProxy 機能）を通知していればサーバー側のキーでキーレス利用できます。

AI プロバイダは切替式で、選択肢は【API】系と【ブリッジ】系の2系統に分かれます（選択肢名の先頭に接頭辞が付きます）。【API】系は公式APIへブラウザから直接接続する BYO キー方式、 【ブリッジ】系はローカル等のエンドポイント（/agent 契約）へチャット入力を POST する方式で、ツール結果を見て往復する function calling ループは【API】系のみが持ちます。【API】系では Gemini（既定）のほか「OpenAI互換」を選べます。GitHub Models（GitHub PAT）・OpenAI・Azure OpenAI・Ollama・LM Studio など chat/completions 互換エンドポイントにベースURL・キー・モデル名を指定する BYO 構成で、ツール定義・実行ループは Gemini と共通（宣言を OpenAI 形式へ変換して送信）。GitHub Copilot は同梱の copilot-bridge/（GitHub Copilot SDK・要 Copilot 契約）経由で、プロバイダ選択肢はアプリ版のみに表示されます（アプリが起動時にブリッジを自動起動・8511・要 Node.js）。選んで保存するだけで疎通したブリッジへエージェント接続が自動設定されます。通常版では選択肢は出ませんが、手動起動したブリッジ（既定 8788）へプロバイダ「外部エージェント」から接続すれば利用可能です — Copilot に直接呼べる公開APIは無いためブリッジ経由が正規ルートです。

接続しない AI：Microsoft 365 Copilot・消費者向け Copilot など、プログラム利用を認めた公式経路を持たない AI への Web UI 自動化接続は、各サービスの使用条件（自動アクセスの禁止・技術的制限の回避の禁止）に抵触するため、本プロジェクトでは実装・提供しません。ブリッジ接続は公式 SDK/CLI 等の正規プログラム経路があるもの（現状は GitHub Copilot SDK）に限ります。

AI の実行経路は function calling によるツール呼び出しで、48個のツールがアプリの全主要機能を網羅します：

カテゴリツール
カメラ・視点flyTo・getCamera・flyToFeature・flyToPreset・listCameraPresets
レイヤーlistLayers・setLayerVisible・focusLayer・addLayer（geojson/geoparquet/duckdb/sql 等）・addGeoJsonLayer・applyInspector・exportInspector
ベースマップ・地形・効果listBasemaps・setBasemap・setTerrain・setEffect・setUnderground・setClip
Fly・プレゼンlistFlyPaths・playFlyPath・stopFly・toggleDrawMode
検索searchLocation・vectorSearch・searchPlaces*・openStreetView*（* Maps キー設定時のみ）
共有・資料生成getShareUrl・buildShareUrl（視点パーマリンク）・showReport（Markdown 資料をモーダル表示）
プロジェクトlistProjects・switchProject
データ取得・加工fetchData（CORS 範囲の URL 取得）・getLayerGeoJson・addDataLayer・removeDataLayer
データファイルlistDataFiles*・saveDataFile*・deleteDataFile*（* ローカル版のみ）
コード実行・プラグインrunCode（サンドボックス）・savePlugin・listPlugins・getPluginCode・removePlugin・setPluginEnabled・publishPlugin*（* ローカル版のみ）
システムcheckUpdate・installUpdate・shutdownApp

資料生成のフロー：「◯◯の資料を作って」と頼むと、レイヤー自動構成 → FlyTo → 結果を Markdown にまとめ showReport でモーダル表示（ダウンロード可）、buildShareUrl で発行した視点パーマリンクを資料に埋め込みます。架空・サンプル GeoJSON を生成する場合は dataSource・generatedAt・aiGenerated:true の出典スタンプが必須付与されます。

チャット履歴はプロジェクト単位で永続化されます。AI の回答言語は UI 言語に追随します。API キー未設定時はローカルコマンド（/fly 等）が使えます。

実行されるツール群は /api/capabilities で取得したバックエンド能力に応じて出し分けられます（ティア分け。公開環境ではセッション内に閉じる安全な機能のみ）。

🧪 runCode サンドボックス

AI が生成した JavaScript を opaque origin の iframe + postMessage ブリッジで実行するブラウザ内コード実行基盤です。メイン画面とは DOM・ストレージが分離された状態で kasugaiApi 経由のみ地図を操作できるため、生成コードが誤動作しても本体状態や他ユーザーの共有資源を汚染しません。ブラウザローカルの IndexedDB プラグイン生成もこの基盤の上にあります。

🔌 kasugaiApi

window.kasugaiApi は viewer・カメラ・レイヤー・イベントへ外部からアクセスする操作 API です。AI チャットの function calling、runCode サンドボックス内コード、プラグイン、外部エージェントの actions 実行がすべてこの API を通る共通経路になっています。イベント購読（camera-changed 等）もここから行えます。

この V3（AI 連携）の強化がハッカソン提出の中核です — Cloud Run へのデプロイ構成・/api/gemini キー隠蔽プロキシ・提出物については ハッカソン を参照してください。50ツールの引数・提供条件の詳細仕様は AI ツール仕様 を参照してください。
