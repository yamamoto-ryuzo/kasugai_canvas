V5: アプリ化（ローカル連携）

ローカル Rust サーバーと一体で動く「アプリ」だからこそ実現できる機能群です。ブラウザの外（OS・ファイルシステム・ネイティブバイナリ）に踏み込むため、静的配信やコンテナ実行では提供されず、/api/capabilities で提供可否を判定します。ブラウザ GIS との差別化要因となる流れで、今後もこのテーマで拡張していきます。

☁️ クラウドストレージ連携（rclone）

設定 → クラウド タブから rclone 経由で Box / GoogleDrive / OneDrive / Dropbox / pCloud / MEGA / WebDAV / S3 に接続します。2つの利用形態があります：

  • Windows ドライブ割当 — rclone serve webdav を localhost で起動し net use でドライブ化（既定 K:）。エクスプローラーや Office・QGIS など他のアプリから通常のドライブとして使えます
  • アプリ内 cloud: スキーム — レイヤーURLに cloud:フォルダ/file.geojson と書くと /api/cloud/file プロキシ経由で接続中ストレージのファイルを読み込みます。HTTP Range を転送するため DuckDB-WASM 等の範囲読み経路でも利用でき、ドライブ割当なしで動作します

なぜ静的配信（HTTP サーバーのみ）では実現できないか: rclone の実行・ドライブ割当（net use）・cloud: の解決プロキシはすべてブラウザ外の処理であり、Box 等の OAuth 認可コードフローに必要な client_secret も静的 web には埋め込めません。そのため本機能はアプリ（ローカルサーバー）専用です。

クラウドストレージ連携（rclone）の詳細

Box Drive 等のクライアントがインストールできない環境でも、単体バイナリで動く rclone を介してクラウドストレージを利用する機能です。ローカルサーバー（local ティア）のみで有効で、/api/capabilities の cloudRclone で提供可否を判定します。コンテナ実行時は /api/cloud/* を公開しません。

この連携の意義: 静的 HTTP サーバーにデータを置くのではなく、認証・ACL・監査・バージョン履歴を備えたクラウドストレージをデータ基盤にできます。各ユーザーは自分の OAuth アカウントで接続するためプロバイダ側で権限が強制され、.kasc には cloud: パスのみが書かれ認証情報は共有されません。同じフォルダを K: ドライブ経由で Office・QGIS・エクスプローラーからも使えるため、資料や GIS データを一元管理するシステムを組みやすい構成です。

rclone の導入

  • 自動検出の順序: 設定ファイル（kasugai_canvas.cloud.json の rclonePath）→ PATH → C:\kasugai\rclone\rclone.exe
  • 未導入時は「インストール先フォルダ」を指定して「ダウンロードして配置」で公式配布物を取得（インストーラー不要の単体バイナリ）
  • リモート追加は種別（Box / GoogleDrive / OneDrive / Dropbox / pCloud / MEGA / WebDAV / S3）を選ぶだけで、その種別名をリモート名として rclone config create を起動し、ブラウザで OAuth 認証します

ルートフォルダとフォルダURL

  • 「ルートフォルダ」に指定したフォルダが接続の起点になります（空欄はリモート全体）
  • フォルダURLを指定するとフォルダID起点（rclone の root_folder_id）で接続します。権限や共有経路によってリモート内の見える位置が異なる環境間でも、全員が同じフォルダをルートとして参照でき、.kasc の cloud: パス指定を環境間で統一できます
  • 対応URL形式: Box の …/folder/<ID> と共有リンク …/s/<slug>（Box API の shared_items でフォルダIDに解決）、Google Drive の …/folders/<ID>、OneDrive / pCloud の ?id= パラメータ。その他の種別はフォルダパスで指定します

権限とプロジェクト保存

  • 読み取り専用: rclone serve webdav --read-only で起動し、プロキシ書き込みは 403 で拒否。意図しない書き込みを防げます
  • 読み書き: --vfs-cache-mode full で起動。ファイルのアップロード・削除・.kasc のクラウド保存が可能

主な API

GET  /api/cloud/status    … 検出状態・バージョン・リモート一覧・接続状態
POST /api/cloud/install   … 指定フォルダへ rclone をダウンロード配置
POST /api/cloud/config    … リモート追加（config create → OAuth）
POST /api/cloud/serve     … WebDAV 起動（remote / root|フォルダURL / readOnly / drive）
POST /api/cloud/stop      … 停止（ドライブ割当も解除）
POST /api/cloud/drive     … ドライブ割当・解除（Windows）
GET  /api/cloud/list      … フォルダ一覧（rclone lsjson）
GET/PUT/DELETE /api/cloud/file … ファイルの読み書き・削除（Range 転送対応）
POST /api/cloud/localize  … 接続ルートを DATA/ へコピーし .kasc の cloud: を書換え（納品用）

制約・注意点

  • ドライブ経由の読み書きは Windows WebClient の既定上限（約 50MB）を受けます。cloud: スキーム（アプリ内プロキシ）はこの制限を受けません
  • ドライブ割当は Windows のみ。オフラインキャッシュはなく、WebDAV のロックは限定的なため同時編集は避けてください（Box 等のバージョン履歴で過去版には戻せます）
  • rclone の OAuth トークンは rclone 側の設定ファイル（%APPDATA%\rclone\rclone.conf）で管理されます

💾 ローカルファイル保存

ローカルサーバー版の /api/files API で projects/<id>/DATA/ へのファイル書き込み・一覧・削除ができます。ブラウザ側は File System Access API による DATA/ 直接保存も併存します（Chromium系のみ・選択フォルダへ直接書込み）。

利用例: 描画ルートの保存、インスペクターからのファイル追加（.geojson/.gpkg/.fgb/.parquet を選ぶと対応する行タイプのレイヤー行を自動追記）、ダウンロードしたデータのプロジェクト内配置など。静的配信では利用できません（サーバー API 依存機能）。

📦 納品用ローカル化

クラウドパネルの「クラウドの内容をDATA/へ同期（納品用）」ボタン（または POST /api/cloud/localize）で、接続中のクラウドルートを rclone copy で projects/<id>/DATA/ へ丸ごとコピーし、.kasc 内の cloud:パス 参照を DATA/パス に書き換えます。

これにより「クラウドを正とした構築・共有 → 納品時にローカル完結パッケージ化」という流れができます。納品先は rclone の設定も元のクラウドの OAuth 認証情報も不要で、ファイル一式だけで動作します。

安全対策として、..・バックスラッシュ・制御文字を含む cloud: 参照はプロジェクト外に出るため書き換え対象外です（クラウド参照のまま残ります）。大容量フォルダではダウンロードに時間がかかる点と、同期後はクラウド側の更新が自動反映されない点に注意してください。
