V4: プラグイン（認証機構）・外部連携

拡張可能なプラグイン機構と認証方式の導入に加え、データ形式・外部サービス連携を大きく拡充しました。

🧩 プラグイン機構・認証方式

起動前の認証プラグイン（auth-selector）と起動後の通常プラグイン（plugin-loader）を分離した拡張機構です。認証方式は 0〜7（認証なし / ローカル / 簡易パスワード / Cloudflare Pages / Cloudflare Workers / Cloud Run / Cloud Run IAP）から選択でき、公開環境でも ID プロバイダの認証・承認の内側に置けます。

プラグインは window.kasugaiApi を通じて地図を操作します。AI が生成したプラグインはまず IndexedDB（ブラウザローカル草稿）に保存され、.kasp でエクスポート可 → レビュー後にローカル版で PLUGIN/ へ公開、という「開発→草稿→公開」の昇格ルートを持ちます。高権限操作（プラグイン公開等）はフロント側で必ず確認ダイアログを挟みます。詳細は 認証とプラグイン を参照してください。

🗃️ クエリ系・大規模ベクター

CesiumJS ネイティブ非対応の形式は「ブラウザ側でデコード → GeoJSON へ正規化 → 既存のベクター描画経路に流す」が基本ルールです。これによりレイヤー一覧・表示切替・フォーカス・ベクトル検索・属性パネルが新形式でも自動的に機能します。

  • geoparquet: — hyparquet（CDN 遅延ロード）で WKB/ネイティブ GEOMETRY を GeoJSON 化。常に全件読み込み
  • flatgeobuf: — 公式 JS リーダーでレスポンスを ReadableStream のまま逐次デコード。全件読み込みだが全件バッファリングはしない
  • gpkg: — sql.js(SQLite WASM) を module Worker で動かし GPKG を SQLite として直接開く。where=/limit=/columns=/bbox=auto（既定 ON。GPkgBinary エンベロープで JS 範囲判定）対応。QGIS の layer_styles(QML) を読んで既定スタイルに適用
  • duckdb: / sql: — DuckDB-WASM で SQL 絞り込みしてから GeoJSON 化。:bbox プレースホルダで表示範囲連動、proxy=on でローカルサーバーの /api/fetch 経由取得（Range/HEAD 転送対応）

クエリ系レイヤーは「検索は常に全件検索・表示はバッファの表示範囲のみ」の設計で、⏷フィルター編集による対話的な条件変更にも対応します。ベクター描画件数の上限・primitive バッチ描画（render=primitive）で大規模データにも対応します。形式の使い分けは データ形式 を参照してください。

🗺️ Google Maps Platform 連携

設定 → Google タブで API キーを登録すると、Geocoding / Places を使ったハイブリッド検索と、Street View リンク・候補ラインオーバーレイが利用できます。検索は国土地理院/Yahoo/Google を切り替えて使えます。

外部エージェント呼出し（エージェントタブにエンドポイント URL を設定し、チャット入力を POST {message, project, camera, layers, history} → 応答 {reply, actions} の actions をチャットツールとして実行）で Antigravity 等の外部構築エージェントと接続できます。このプロトコルが V6 の ANTIGRAVITY エージェント API の契約です。詳細は Google 連携・AI を参照してください。
