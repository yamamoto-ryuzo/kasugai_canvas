KASUGAI Canvas で扱えるデータ形式一覧

直接描画可能なデータ形式

分類 形式 描画方法 備考
2D ベクトル GeoParquet / FlatGeobuf geoparquet: / flatgeobuf: → GeoJSON 正規化 → GeoJsonDataSource ブラウザ内デコード（hyparquet / flatgeobuf 公式リーダー）で変換不要。duckdb:/sql: なら SQL 絞り込みも可
2D ベクトル GeoJSON（小〜中規模） geojson: → CesiumJS GeoJsonDataSource 大容量時は GeoParquet/FlatGeobuf または duckdb:/sql: クエリ経路を推奨
2D タイル XYZ / WMTS / TMS CesiumJS ImageryLayer（地形・3D Tiles にドレープ） 広域地図・航空写真。MVT は現行未実装（将来候補）
3D モデル GLB / glTF 2.0 CesiumJS Model / Three.js GLTFLoader 建機・構造物
3D タイル 3D Tiles 1.1 (GLB 内包) 3dtiles: → CesiumJS Cesium3DTileset PLATEAU・Google Photorealistic 等。LOD・ストリーミング対応
点群 3D Tiles 点群 (pnts / 1.1 glTF) Cesium3DTileset / Three.js Points 大規模点群向け。LAS/LAZ・EPT は変換が必要
3DGS PLY / SPZ / .splat / .ksplat / .sog Three.js 系専用レンダラー gaussian-splats-3d 等。CesiumJS とカメラ同期（オーバーレイ canvas）
DEM / 地形 標高PNG (XYZ) / Cesium Terrain CesiumJS TerrainProvider 地理院標高PNG は独自デコーダー （GsiDemTerrainProvider）実装済み

パイプライン（変換）が必要なデータ形式

分類 形式 変換先 備考
2D ベクトル GPKG (GeoPackage) duckdb: の ST_Read で直接読込 / GeoParquet・FlatGeobuf SQLite + WKB。DuckDB-WASM spatial 拡張でブラウザ内読込可
2D ベクトル FGDB (File Geodatabase) GeoParquet / FlatGeobuf / GeoJSON プロプライエタリ。ogr2ogr 等で変換
2D ベクトル GeoJSON（大規模） GeoParquet / FlatGeobuf 列指向・空間インデックスで読み込み効率化
点群 PLY / LAS / LAZ EPT / 3D Tiles / PointCloud バッファ ブラウザ内 or 事前変換
DEM / 地形 GeoTIFF / CSV 等 標高PNG / GLB / 3D Tiles Web Worker またはサーバー側で変換
  • 直接描画可能：CesiumJS ネイティブ形式、または vectorDecoders レジストリのデコーダーで GeoJSON へ正規化して既存のベクター描画経路（GeoJsonDataSource / GeoJsonPrimitive）に流す
  • 要専用レンダラー：Three.js 系の専用ライブラリが必要。CesiumJS とはカメラ同期（オーバーレイ canvas + postRender）のみ
  • パイプライン（変換）が必要：ブラウザ内 Web Worker または事前変換が必要。GPKG/FGDB は Single Source of Truth として管理・変換元に使用

CesiumJS と Three.js の担当分け

データ 主担当エンジン 補完エンジン 用途
2D ベクトル (GeoJSON / GeoParquet / FlatGeobuf) CesiumJS (GeoJsonDataSource / GeoJsonPrimitive) duckdb: / sql:（SQL 絞り込み） 図面・境界・大容量 2D
2D タイル (XYZ / WMTS) CesiumJS (ImageryLayer) – 広域地図・航空写真（地形ドレープ可）
GLB / 3D Tiles CesiumJS (Model / Cesium3DTileset) Three.js (GLTFLoader) 建機・構造物・都市モデル
点群 (PLY / LAS / EPT) CesiumJS (Cesium3DTileset pnts) Three.js (Points / Potree) 測量・LiDAR 点群
3DGS (PLY / SPZ / Splat) Three.js 専用レンダラー CesiumJS (カメラ同期) 写真測量・ニューラル表現
管理データ (GPKG / FGDB) duckdb:（ST_Read）または Web Worker → 変換 – 正データ保持・変換元
  • CesiumJS：グローブ・地形・3D Tiles・ベクター・イメージリを同一 Scene / 深度バッファで描画
  • Three.js：点群・3DGS・高度な GLB 表現を補完。別 canvas を重ね、postRender で CesiumJS のカメラ行列を同期させる

2D データ

2D データ整理

用途・データ領域 最適フォーマット 評価 強み 弱み・注意点
数千〜数万件の 2D図面・境界 GeoParquet / FlatGeobuf 🏆 最推奨 列指向バイナリ・空間インデックス。geoparquet: / flatgeobuf: でブラウザ内デコードし GeoJSON 正規化。変換不要で置くだけ 全件読み込みのため超大規模は向かない
大規模・条件絞り込み・表示範囲連動 GeoParquet + duckdb: / sql: 🏆 大規模向け 述語プッシュダウン・row group スキップ・列プルーニング・bbox=auto で「見ている範囲だけ読む」。検索は常に全件 DuckDB-WASM の初期ロードが重い（SW キャッシュで緩和）
広域・大量の全国地図・航空写真 XYZ / WMTS（MVT は将来候補） 🥈 GIS/Web 標準。ImageryLayer で地形ドレープ可 MVT ベクタータイルは現行未実装
管理・連携用の正データ GPKG (GeoPackage) ✅ 管理用 Single Source of Truth。属性・トポロジ保持に優秀。duckdb: の ST_Read で直接読込も可 大規模データは描画用形式への変換を推奨
Esri 資産の管理・連携 FGDB (File Geodatabase) ✅ 管理用 Esri ツールとの互換。フィーチャクラス・ドメイン・関係対応 プロプライエタリ。ブラウザ直接描画不可。変換が必要
2D 図面への GLB 使用 — ❌ 3D メッシュ向け 属性・トポロジが弱く、2D 図面には向かない
  • KASUGAI Canvas 描画層：GPKG は duckdb: の ST_Read で直接読み込むか GeoParquet/FlatGeobuf へ変換、FGDB は ogr2ogr 等のサーバー or 事前変換で GeoParquet / FlatGeobuf / GeoJSON に変換し、GeoJSON 正規化経路（GeoJsonDataSource / GeoJsonPrimitive）へ流す

3D データ

3D データ整理

用途・データ領域 最適フォーマット 評価 強み 注意点
単体オブジェクト（建機・構造物） GLB (glTF 2.0) 🏆 最推奨 3D モデルの「3D 版 JPEG/PNG」。1 ファイルで完結 –
広域・大容量（都市モデル） 3D Tiles 1.1（GLB 内包） 🏆 最推奨 タイル化・LOD 制御でストリーミング 1.1 から glTF 2.0 / GLB ペイロードを直接利用可能
点群（測量・LiDAR 生データ） LAS/LAZ / PLY / EPT 🥈 測量標準。EPT は大規模点群を階層タイル化 そのままの描画には変換・ローダーが必要
画像からのニューラル表現 3DGS (PLY / SPZ / Splat) 🥈 写真起点の高品質ビジュアル。SPZ は PLY 比 10x 圧縮 PLY は未圧縮で大容量。描画には専用レンダラーが必要

KASUGAI Canvas への読み込み方

データ 描画エンジン ロード方法
GLB / 3D Tiles CesiumJS (Model / Cesium3DTileset) または Three.js (GLTFLoader / 3DTilesRenderer) 3dtiles: 行で URL 指定。LOD・ストリーミングは CesiumJS が管理
点群 (PLY / LAS) CesiumJS (Cesium3DTileset pnts) または Three.js (Points / Potree) PLY/LAZ → 3D Tiles 変換 → 3dtiles: で読み込み
3DGS (PLY / SPZ) Three.js 専用レンダラー gaussian-splats-3d / SuperSplat 等で読み込み

点群の扱い

  • LAS/LAZ：測量・LiDAR での標準。LAZ は圧縮形式
  • PLY：簡易入出力用。点位置 + RGB のみの軽量点群も可能
  • EPT (Entwine Point Tile) / Potree 形式：ブラウザ向け大規模点群配信。八分木階層で LOD 制御
  • 大量点群は EPT や 3D Tiles 点群（pnts / 1.1 glTF） に変換して Cesium3DTileset / Three.js で描画すると安定

3D Gaussian Splatting（3DGS）

  • 3D 空間上の多数のガウス分布でシーンを表現するニューラル描画手法
  • 主要フォーマット
    • PLY：学習済みモデルのデファクト標準。各ガウスに位置・スケール・回転・不透明度・球面調和係数を保持
    • SPZ：Niantic 公開の圧縮形式。PLY と比べて約 10 倍小さく、Web 配信に適している
    • .splat / .ksplat / .sog：各ビューアー向けの圧縮・最適化形式
  • KASUGAI Canvas では Three.js 側で専用レンダラーを使い、オーバーレイ canvas + postRender で CesiumJS とカメラ同期を行う

地形（DEM）の扱い

  • CesiumJS TerrainProvider：KASUGAI Canvas は独自実装の GsiDemTerrainProvider（HeightmapTerrainData を返す）で地理院標高PNG (XYZ) を直接地形化する。国土地理院標高タイルは RGB → 標高値（x = 2^16R + 2^8G + B、u は標高分解能 0.01m）かつ符号付き・条件分岐形式（x < 2^23 のとき h = xu、x = 2^23 のとき NA、x > 2^23 のとき h = (x - 2^24)u）だが、この変換は gsiDecodeHeight として実装済み。設定タブで Re:Earth Terrain（楕円体高 / 標高）・地理院 5m+10m・地理院 1m を切替可能
  • Three.js：DEM 画像から PlaneGeometry + displacement map / 頂点シェーダーで terrain メッシュを生成する代替経路（オーバーレイ canvas 上）
  • PLATEAU 3D Tiles：3D 都市モデル（建物・地形等）を LOD 付きで配信しているので 3dtiles: 行 → Cesium3DTileset でそのまま表示
  • 生の DEM（GeoTIFF / CSV 等）は、Web Worker またはサーバー側で 標高PNG / GLB / 3D Tiles に変換してから描画

データパイプライン

KASUGAI Canvas へのデータは、以下のパイプラインを経て描画層に届く。

現場データ（GPKG / FGDB / GeoJSON / GLB / LAS / PLY / SPZ）
    ↓
① 変換
    ブラウザ内（Web Worker / WASM）: DuckDB-WASM / hyparquet / flatgeobuf
    サーバー or 事前変換: ogr2ogr / Potree Converter / entwine
    ↓
② 描画用フォーマット
    GeoJSON / GeoParquet / FlatGeobuf / XYZ / 3D Tiles / GLB
    ↓
③ 配信・キャッシュ
    OPFS / IndexedDB / S3 / MinIO / CDN
    ↓
④ 描画
    CesiumJS（GeoJsonDataSource / GeoJsonPrimitive / ImageryLayer /
    Cesium3DTileset / TerrainProvider）+ Three.js（オーバーレイ）
段階 役割 対象データ・技術
入力 正データ・管理データの保持 GPKG、FGDB、Re:Earth（属性・プロジェクト管理）
変換 ブラウザ内 or 事前変換 2D 図面 → GeoParquet/FlatGeobuf、点群 → EPT/3D Tiles、3DGS → SPZ
配信 タイル・バイナリの配信 S3/MinIO、CDN、Martin、Tegola
描画 GPU 描画 CesiumJS GeoJsonDataSource / GeoJsonPrimitive / ImageryLayer / Cesium3DTileset、Three.js
  • 点群・3DGS・生 DEM は ブラウザ内で変換するのではなく、事前に 3D Tiles / EPT / SPZ へ変換 しておくのが現実的
  • GPKG は duckdb: の ST_Read（DuckDB-WASM spatial 拡張）で直接読み込む か事前変換、FGDB は ogr2ogr 等のサーバー or 事前変換で GeoParquet / FlatGeobuf / GeoJSON に変換し、GeoJSON 正規化経路へ流す
  • 変換済みデータは OPFS や IndexedDB にキャッシュし、次回起動時の読み込みを短縮する
