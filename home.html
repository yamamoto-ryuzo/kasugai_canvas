KASUGAI Canvas v4.8.0

ローカルPC・ブラウザ完結で動作する 2D/3D データ可視化システムの技術選定

📋 概要

KASUGAI Canvas は、CesiumJS + Three.js を核とした 2D/3D データ可視化システムです。Re:Earth GeoSuite との互換性を意識した GIS 基本機能に加え、KASUGAI 独自の FLY 機能を追加しています。

v3.4.2 以降、地図タイル・検索・レイヤー取得は CesiumJS が直接行い、Rust サーバーはバージョン管理・シャットダウン・ヘルスチェック API のみ提供します。

▶ デモサイトを開く（インストール不要・ブラウザで即起動）

デモは GitHub Pages 上の静的配信版です。設定の保存・サーバー経由の一部機能は無効ですが、地図閲覧・Fly など主要機能はそのまま試せます。

▶ デモサイトを開く（Cloudflare Pages・認証方式3）

Cloudflare Pages 上のデモです。認証方式 3（Pages Functions + KV）で動作しており、ログイン ID／パスワードはいずれも demo です。

▶ デモサイトを開く（Cloudflare Workers・認証方式4）

Cloudflare Workers 上のデモです。認証方式 4（Worker + KV・全ファイル認証ゲート）で動作しており、未ログインでは静的ファイルも取得できません。ログイン ID は admin、パスワードは admin123 です。

🗂️ 対応データ形式

インスペクターの .kasc 設定で行タイプとして指定できるデータ形式の一覧です。CesiumJS ネイティブ非対応の形式は、ブラウザ側で GeoJSON に正規化して描画するため、レイヤ一覧・表示切替・属性検索・属性パネルがそのまま使えます。

geoparquet: で指定。列指向バイナリ形式を hyparquet でデコードし GeoJSON へ正規化。Range Request による部分読み・属性検索に対応

🦆 DuckDB SQL 対応 NEW v4.8.0

duckdb: / sql: で指定。DuckDB-WASM（CDN から遅延ロード）で Parquet・CSV・JSON 等を SQL で絞り込んでから GeoJSON へ正規化して描画。spatial 拡張により空間述語・WKT・ST_Read(Shapefile/GeoPackage 等) も利用可能

🧭 FlatGeobuf 予定

空間インデックス内蔵のバイナリ形式。範囲ストリーミングに強く、GeoJSON 正規化経路での対応候補

📄 CSV / TSV 対応

🗂️ Shapefile / GeoPackage 対応

duckdb: の format=read（spatial 拡張の ST_Read）で読み込み可能。QGIS での編集成果物をそのまま扱える

🧩 MVT / PMTiles 検討中

ベクタータイル。数十万地物級の全件表示・LOD が必要な大規模データ向けの別経路として検討

方針の詳細（経路分類・新形式の追加手順）はリポジトリの AGENTS.md「データ形式方針」を参照してください。

🔍 V4. 拡張機能（Plugin）と認証

認証方式は web/auth-methods.json の control で 0〜4 の番号で指定します。デフォルトは 0（認証なし）で起動します。認証後、window.kasugaiAuth に認証情報がセットされ、その後 app.js と通常プラグインが起動します。.kasc は全方式で読み取り可能ですが、サーバーへの書き込み（KV への保存）ができるのは 3・4（cloudflare 系）のみです。0〜2 では「適用」はブラウザ内への反映のみで、「エクスポート(.kasc)」でのファイル運用になります。

⚠️ セキュリティ上の注意

Cloudflare Pages 認証は最低限の起動制御 + .kasc 設定情報の保護です。アプリの起動を制御し、.kasc の内容は ID/PASS 認証後に Cloudflare KV から取得されます。ただし、HTML/JS/CSS などの静的ファイル自体は公開されており、DATA/ 内の画像・GeoJSON 等は保護対象外です。auth-selector.js は auth-methods.json で選択された方式のみを読み込みます。完全なファイルアクセス制御が必要な場合は、Cloudflare Access（Zero Trust）や R2 等でファイル配信を制御してください。

0. 認証なし（none）

ID/PASS 不要。誰でも起動可能。ローカル開発や非公開の信頼環境向け。

1. ローカル認証（local）

最小限のローカル向け認証。ID/PASS を平文で照合するテスト・実験用。

2. 簡易パスワード認証（password）

クラウド不要の JS 内ハッシュ比較。閉じた環境・テスト用途向け。

3. Cloudflare 認証（cloudflare）— Pages

サーバーレス ID/PASS 認証。.kasc は Cloudflare KV、秘匿データは r2:// で R2 認証ゲート経由。安全な本番運用に推奨。

4. Cloudflare 認証（cloudflare）— Workers

3 の機能に加え、静的ファイル自体も含めて全リクエストを認証ゲート。最も強い保護。

「web/ 静的配信」の2区分について：静的ファイルに認証チェックはなく、URL が分かれば誰でも取得できる点は同じです。違いは URL の発見可能性だけです。「URL が公開情報から分かる」とは、公開の .kasc・projects.json・HTML/JS 内にパスが書かれている、または projects/default/DATA/... のような推測しやすい固定パスのケース — 実質的に一覧・総当たりで列挙可能です。「URL が非公開・推測困難」はどこにもパスが書かれていないケースで、URL そのものが秘匿情報として機能します（ obscurity による弱い隠蔽で、URL が一度漏れれば防御はゼロです）。方式3 で .kasc を KV に移せば、そこに書かれたデータ URL は未ログイン者には発見できなくなります。

共通の前提：「ログインした人」からは .kasc・データは見えます（ブラウザへ配信されるため）。秘匿が効くのは「未ログインの第三者」に対してです。方式3/4 の署名トークンは /api/data/...?token=… の URL に現れるため、ログイン済みブラウザから読み取れば有効期間中（12時間）は KV/R2 にアクセス可能です。各方式の詳細はそれぞれのページを参照してください。

認証用ログインUI

ローカル認証（1）、パスワード認証（2）、Cloudflare 認証（3）は、同じログインUIコンポーネント web/auth-login-form.js を使用します。画面の見た目・入力チェック・ローディング表示・エラー表示を共通化し、認証方式ごとの判定処理だけを web/PLUGIN/auth-*/auth.js に閉じ込めています。

新しい認証方式を追加する場合は、web/PLUGIN/<id>/auth.js から showLoginForm({ onSubmit }) を呼び出し、onSubmit コールバック内で独自の認証処理を記述してください。詳細は README.md を参照してください。

起動後通常プラグイン

機能拡張プラグインは web/PLUGIN/<plugin-id>/plugin.js に配置し、web/plugins.json に登録します。

web/PLUGIN/sample-hello/plugin.js
web/PLUGIN/auth-local/auth.js

通常プラグインは window.kasugaiApi 経由で Cesium viewer やカメラ、レイヤー情報にアクセスできます。詳細は README.md を参照してください。

plugins.json に layer を宣言すると、本体がプラグイン専用レイヤーを自動登録し、レイヤ一覧・表示切替・属性検索・属性パネルの対象になります。format: "entities" は本体生成の DataSource に動的 entity を追加する方式、format: "geojson" は api.setPluginLayerData() で GeoJSON を渡して内蔵レイヤーと同じ描画経路で表示する方式です。scope: "project" でプロジェクト切替時に自動削除もできます。

🧩 AIプラグイン生成（自己拡張）

チャットに「〜するプラグインを作って」と頼むと、AIがコードを生成してブラウザ内 IndexedDB に保存・即時有効化。適用前にコード全文の確認ダイアログが出ます。読み込みエラーはAIへ返るため、修正→再保存の自律ループが回ります。Google → エージェント タブで一覧・有効化・コード確認・.kasp 出力/取込・削除が可能。ストレージ保存のため配布物とは分離され、気に入ったものだけ PLUGIN/ に登録して公開できます

📊 データ取得・加工・表示パイプライン

fetchData（外部URL取得・CORS前提）と getLayerGeoJson（読込済みレイヤーのGeoJSON取り出し）でデータを取得し、runCode で任意の加工・集計・変換を行い、addDataLayer で GeoJSON を直接レイヤー表示。feature の properties に simplestyle 属性（marker-color/fill/stroke/description 等）を書けば色分け・ポップアップも制御できます。一時レイヤーは .kasc には含まれません

🌐 実行環境ティア（公開/ローカルの使い分け）

AI機能は操作の影響範囲で3ティアに分かれます。static（静的配信のみ）と workers（Cloudflare Pages/Workers 公開環境）では、セッション内に閉じる安全な機能（地図操作・runCode・データ加工・IndexedDBプラグイン生成）を誰でも利用可能。local（ローカルサーバー版）では永続化・共有・システムに触れる高権限機能（/api/fetch によるCORS回避の取得プロキシ、/api/plugins による PLUGIN/ へのプラグイン公開、ファイル保存）が使えます。フロントは /api/capabilities で能力を検出してツール・UIを出し分け、バックエンド無しでも安全機能のみで動作します。昇格ルートは「IndexedDB草稿 → .kasp出力 → ローカル版で公開ボタン → PLUGIN/」です

ローカルサーバー版の独自API（公開環境では無効）

GET  /api/capabilities   → {"tier":"local","features":["fetchProxy","pluginWrite",...]}
GET  /api/fetch?url=...  → CORS回避のGETプロキシ（http/httpsのみ・30秒・20MB上限）
POST /api/plugins        → {"id","name","version","description","layer","code"}
                           PLUGIN/<id>/plugin.js・manifest.json を作成し plugins.json に登録
DELETE /api/plugins/{id} → プラグインの公開取り消し（PLUGIN/<id>/ と plugins.json 登録を削除）

プラグインIDは半角英数・-・_ のみ（64文字まで）。公開・削除は実ファイルを書き換えるため、フロント側では必ず確認ダイアログが出ます。公開環境（Pages/Workers）に同等の無認証書き込みAPIを置かないでください。

  • サーバーサイドエージェント：Rust 側の長時間エージェントループ・SSE/WebSocket によるサーバー起点の通知・会話メモリ/RAG は未実装（現状のAIループはブラウザ内・最大5ステップ・タブを閉じると停止）
  • ローカルファイル連携：DATA/ フォルダ書き込み・File System Access 連携・QGIS/GDAL 呼び出しは未実装
  • Cloud Run 対応：PORT 環境変数での 0.0.0.0 バインドのみ対応済み。Dockerfile・コンテナビルド手順は未整備（永続化には別途ストレージ設計が必要）

設定種類

base: ベースマップ(先頭が既定) | maxZoom= / tileSize= / opacity= / proxy=off
xyz: タイルレイヤ | 同上+off
3dtiles: / geojson:(layer:) / geoparquet: レイヤ | off / proxy=off
duckdb: SQL絞り込みレイヤ | where=条件 / limit=件数 / geom=列 / lon=・lat=列 / format=parquet|csv|json|read / columns=列,列 / covering=xmin,xmax,ymin,ymax / bbox=auto / render=primitive|entity(既定primitive)
sql: 任意SELECT文レイヤ | sql:タイトル|SELECT ... (タイトル後の | 以降はすべてSQL・| 使用可・末尾 | off で非表示・| render=entity で entity 描画・:bbox で表示範囲連動)
cam: カメラプリセット | cam:名|緯度|経度|h=高さ|p=ピッチ|d=方位
fly_geojson: Flyパス | s=速度 h=高さ p=ピッチ step= loop=true v=基準(camera/center)
info: InfoパネルHTML / legend: 凡例画像 / background: 背景色 / yahooAppId: Yahoo検索ID

duckdb: / sql:（SQL絞り込みレイヤ）

初回利用時に DuckDB-WASM を CDN から遅延ロードします（数十MB・Worker 内で実行）。duckdb: は単一ファイルを読み込み、where=/limit= を適用して描画します。ファイル形式は拡張子から自動判別します（parquet/csv/json）。sql: はタイトル後の | 以降をすべて SELECT 文として実行します（クエリ内で | 使用可・|| 演算子も可）。クエリ内の URL は絶対指定が必要です。

ジオメトリ列は GEOMETRY 型 → geometry/geom/wkb 等の慣用名 → BLOB 列の順に自動検出し、geom= で明示も可能です（WKB・WKT・GeoJSON テキストを受理）。緯度経度列のみのデータは lon=/lat= でポイント化できます。format=read は spatial 拡張の ST_Read（Shapefile・GeoPackage 等）を使います。なお where= の値には | を含められません（条件が複雑な場合は sql: を使用）。

表示範囲連動フィルター：duckdb: に bbox=auto を付けると、カメラ停止ごとに表示範囲を ST_Intersects(geometry, ST_MakeEnvelope(...)) として再クエリします。sql: はクエリ内に :bbox プレースホルダを書くと同様に範囲連動します（例：WHERE ST_Intersects(geometry, :bbox)。WKB(BLOB)列の場合は ST_GeomFromWKB(geometry) でキャスト）。巨大データを「見ている範囲だけ読む」運用に使えます。ST_Intersects の精密判定には spatial 拡張が必要ですが、covering bbox 列があるデータは拡張無しでも近似フィルターとして動作します。

フィルター UI：レイヤー一覧の ⏷ ボタンから、duckdb: は WHERE 条件式、sql: はクエリ全文を対話的に変更して再読み込みできます。変更は inspector の .kasc テキストにも反映されます。

描画方式（既定はバッファ描画）：duckdb:/sql: は既定で entity を作らず CesiumJS の GeoJsonPrimitive（バッファプリミティブのバッチ描画）で表示し、大量地物でも軽く動作します。render=entity（sql: は末尾 | render=entity）で従来の entity 描画に戻せます。クリックした地物の属性はいずれの方式でも属性パネルに表示されます。なおバッファ描画は地形ドレープ（クランプ）非対応のため、起伏のある地形ではジオメトリが地表に埋まる場合があります。ドレープが必要な場合は render=entity を指定してください。

検索は常に全件対象：duckdb:/sql: の検索・絞り込みは ⏷ の SQL フィルターに一本化しており、常にファイル全件を対象に評価します（読み込み済みの一部だけを対象にするベクター検索パネルには登録されません）。bbox=auto と where= を併用した場合、表示は「検索条件 ∩ 表示範囲」になりますが、検索自体は全件に対して行われ、コンソールに「検索ヒット全 N 件 / 表示範囲内 M 件」と併記されます。

属性値一覧：属性値一覧ウィジェットのレイヤー選択に duckdb:/sql: レイヤーも表示されます。一覧は読み込み済み地物ではなく DuckDB へ直接クエリして作られ、where= は適用する一方 bbox/limit= は適用せず LIMIT 無しの全件を取得します。ウィジェット内の検索文字は全属性列への ILIKE 述語として SQL に変換されるため、常にファイル全件が検索対象です（表への描画は先頭1000行まで）。

Parquet 最適化：クエリ結果のジオメトリは WKB バイナリで受け取ります（テキスト変換を省き転送量・パース時間・ピークメモリを削減）。columns=列名,列名 で読み込む属性列を絞る列プルーニングが可能です。bbox=auto 時は GeoParquet 1.1 の covering bbox 列（または慣用名の xmin/xmax/ymin/ymax 列、covering= で明示指定も可）への範囲述語を優先的に使うため、Parquet の row group 統計スキップが効き、表示範囲外のデータは読み込み自体を省略できます。

グループ化ルール

/・\＝通常グループ（一括ON/OFF）、//・\\＝排他グループ（同時に1つだけ表示・ラジオ動作）。全グループの初期表示は折りたたみです。

未対応の記法（注意）

📖 使い方

基本の流れ

  • 設定は projects/<project>/kasugai_canvas.kasc に記述します。
  • ローカルデータは projects/<project>/DATA/ 以下に置き、設定から相対パスで参照できます。
  • 「エクスポート(.kasc)」ボタンで変更をダウンロードし、設定ファイルと差し替えて保存してください。
  • web/ ディレクトリは通常の HTTP サーバーにそのまま配置できます。

起動方法（通常のHTTPサーバー）

cd web
python -m http.server 8520

web/ をドキュメントルートに置くだけです。ブラウザで http://127.0.0.1:8520/ を開いてください。

起動方法（Rustサーバー / 開発）

cargo run --manifest-path server\Cargo.toml
# または
python run.py            # 開発起動
python run.py --release  # リリース版を起動

ブラウザで http://127.0.0.1:8510/ を開いてください。ポートは KASUGAI_CANVAS_PORT 環境変数で変更できます。インスペクター設定は projects/<project>/kasugai_canvas.kasc に保存されます。

プロジェクト構成

web/                    # フロントエンド資産(静的配信のみで動作)
├─ index.html / app.js / styles.css
└─ projects/
   ├─ projects.json      # プロジェクト一覧 [{"id":"...","title":"..."}]
   └─ <project_id>/
      ├─ project.json     # 表示名等
      ├─ kasugai_canvas.kasc  # インスペクター設定
      └─ DATA/            # ローカルGeoJSON・3D Tiles・画像等

設定内の相対パス（例: DATA/sample.geojson）は projects/<project_id>/DATA/ に解決されます。Rustサーバー使用時は同構成の projects/ をサーバーと同階層に配置します。

設定の保存

静的サーバーでは設定をサーバーに保存しません。インスペクターの「エクスポート(.kasc)」でダウンロードし、対象プロジェクトの kasugai_canvas.kasc と差し替えてください。

リリースビルド

python run.py -B

配布用 ZIP（kasugai_canvas.exe + web/ + projects/）と、NSIS が利用可能な場合はインストーラーを download\ に作成します。既定のインストール先は C:\kasugai\kasugai_canvas です。

自動更新

Rust サーバー起動時は、設定パネルから最新リリースの確認・自動更新が行えます。更新時は EXE を自動的に差し替えて再起動します。

1 行 種類: 値 形式でレイヤー、ベースマップ、カメラ、Info、凡例等を記述します。完全な書式・オプション・ローカルファイル追加手順は本ページ上部の「インスペクター設定（完全版）」を参照してください。

FLY 機能（KASUGAI 独自追加機能）

  1. kasugai_canvas.kasc に fly_geojson: ルート名 | URL | speed=10 | height=100 | pitch=-30 を追加
  2. ナビゲーションツールバーから Fly モードに切り替え、ドロップダウンでルートを選択
  3. マウスホイール / キー + / - で速度、キー Q / E で高さ補正を調整
  4. Orbit モードで Draw タブから右クリックで点を追加、右ダブルクリックでルート描画終了→ブラウザ IndexedDB に自動保存されドロップダウンに追加
  5. 「取込」で .geojson ファイルを IndexedDB へインポート、描画ルートを選択中は「出力」（.geojson ダウンロード）「削除」ボタンが表示。インスペクタで route:<ルート名> を参照することも可（例：fly_geojson: 名 | route:drawn_route_...）
