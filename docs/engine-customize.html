KASUGAI Canvas v7.2.0

エンジン自前配信 — CDN を使わない独自 WebGIS / カスタマイズ / WebGIS 開発の教本としての利用

1. 概要 — web/ はビルド不要の静的ファイル一式

KASUGAI Canvas のエンジン本体は web/ フォルダの静的ファイル（HTML・JS・CSS）だけで構成されており、 ビルド工程も npm install もありません。 CDN ホスト版（kasugai-canvas-web）は この web/ を GitHub Pages へコピーしたものにすぎません。 つまり web/ を任意の HTTP サーバー・任意の静的ホストへ置くだけで、 そのまま KASUGAI Canvas として動作します（ライセンスは MIT）。

このページでは次の3つの用途を説明します。

  • 自前配信: 社内サーバーや GitHub Pages 等へ自分でエンジンを置き、独自 WebGIS として公開する（本ページ）
  • 独自カスタマイズ: 画面・挙動・配色を改造して自社向け WebGIS のベースにする（本ページ）
  • AI 教本: 独自に各エンジンで WebGIS を開発する際、web/ の実装コードを AI エージェントへ参照材料として読み込ませる（2-2 AI 教本としての利用）

対象は主要4エンジン（cesium / maplibre / openlayers / leaflet）です。 なお、コードを書かずに画面構成を調整したいだけなら UI カスタマイズ（ui.config.json） で済みます — まずそちらを検討してください。

2. フォルダ構成 — web/ の中身

web/ がエンジン本体です。配布単位・改造単位ともにこの1フォルダで、 全体像は3ブロックに分かれます。黄色の枠は QGIS geo_webview のエクスポート出力の配置先です。

2-1. 4エンジン必須

4エンジンの動作に必要な一式。このブロックだけコピーすれば動く最小構成です。

web/ ← このフォルダ丸ごと = エンジン本体（静的ファイルのみ・ビルド不要）
  • index.html?engine= で各エンジンへ振り分けるリダイレクタ（既定 cesium）
  • favicon.ico
  • cesium/エンジン別メインエンジン（フル機能・3D）
    • index.htmlUI 構造（タブ・パネル・ボタン）＋ ライブラリ CDN 読込・importmap
    • app.jsエンジン別フロント（薄いアダプタ）— .kasc → Cesium API の写像
    • styles.css見た目・配色・レイアウト
    • plugins.json + PLUGIN/拡張プラグイン（plugin: 行宣言でパネル追加）
    • ui.config.sample.jsonui.config.json の雛形（UI カスタマイズ）
  • maplibre/ openlayers/ leaflet/エンジン別同構成の 2D プレイヤー（index.html / app.js / styles.css / PLUGIN/）
  • shared/全エンジン共通エンジン非依存コア — ここを変えると4エンジンすべてに効く
    • kasc.js.kasc パーサ・読込器・カメラ/縮尺換算・テンプレート生成
    • vector-load.js形式デコード（GeoParquet/FlatGeobuf/GPKG/DuckDB-WASM）→ GeoJSON 正規化
    • qml-style.js / qml-2d.jsQGIS スタイル（QML）コンパイラ
    • where-eval.js portal.js player-api.js ui-config.js …機能別モジュール
    • i18n/9言語 JSON カタログ
  • sw-duckdb.jsService Worker（cesium の DuckDB-WASM 永続キャッシュ。無くても起動可・キャッシュ効果だけ失われる）

<engine>/ と shared/ の分かれ目がこの設計の骨格です。 改造は「エンジン固有の画面・描画 → <engine>/」「データ形式・.kasc 仕様・スタイル解釈 → shared/」に振り分けてください。

2-2. WEBVIEW配布（geo_webview 出力の配置先）

QGIS プラグイン geo_webview のエクスポート出力を置く場所。?kasc= 無しでもプロジェクト選択肢に出ます。

web/projects/
  • projects.json一覧マニフェスト。{"id":"<id>","title":"表示名"} を追記して登録
  • <id>/フォルダ名 = プロジェクト ID（実例: sample_qgis/）
    • kasugai_canvas.kascgeo_webview の Export 出力をそのまま置く（必須）
    • canvas_data/同じく出力一式 — GeoJSON・.qml スタイル・SVG シンボル等（.kasc の相対参照はこのフォルダ基準）
    • project.json表示名 {"title":"…"}（任意）
    • bookmarks.xmlQGIS ブックマーク出力（任意）

エクスポート出力（.kasc + canvas_data/）を web/projects/<id>/ へ展開し projects.json に1行登録するだけで起動時のプロジェクト選択肢に出ます。 web/ の外へ置く場合は ?kasc=<.kascのURL>（外部ホスト配信参照）。

2-3. その他

4エンジンの動作には不要なもの。自前配信で削っても構いません。

web/
  • gsimaps/ navara/対象外vendor 依存エンジン（本ページでは扱わない）
  • vendor/ + vendor-proxy-sw.js配布物には同梱しない上流ライブラリの既定置き場＋gsimaps/navara 用の同一オリジン中継 SW。閉鎖環境で4エンジンのライブラリ実体を置く場合は別名の web/engine/ を使う（3. 閉鎖環境参照）
  • admin/管理画面（ui-config-admin.html 等。CDN にも配信される）
  • verify/ test-import.html portal-test.html動作確認・小さなサンプルページ
  • download/bridge-hub 等の配布物

3. 自前配信の手順

3-1. 最小手順

  1. web/ フォルダを丸ごと静的ホストへコピーする（サブパス配信でもよい。内部参照はすべて相対パス）
  2. https://<ホスト>/<配置dir>/cesium/ をブラウザで開く。ルートの index.html は ?engine= で各エンジンへ振り分けるリダイレクタ

取得は CDN リポジトリ kasugai-canvas-web の stable/（リリース済みの公開物と同じ一式）を基本にします。 配布に必要なフォルダだけを tar から抜き出すのが簡単です: 

# stable/ だけを取得
curl -L https://github.com/yamamoto-ryuzo/kasugai-canvas-web/archive/refs/heads/main.tar.gz | tar -xz '*/stable' --strip-components=1

# unstable/ の場合（開発版）
curl -L https://github.com/yamamoto-ryuzo/kasugai-canvas-web/archive/refs/heads/main.tar.gz | tar -xz '*/unstable' --strip-components=1

リポジトリを kasugai_canvas（対象 web）に差し替えれば、開発中の正本も同じ手順で取れます。

.git は付かず、stable/ の中身だけがそのまま展開されます （git clone + sparse checkout でも部分的には取れますが、.git とリポジトリ直下のファイルが付くため配布用にはこの方法が簡単です）。

ローカルでの動作確認は任意の静的サーバーで構いません。例:

cd stable
python -m http.server 8000
# → http://localhost:8000/cesium/  を開く
  • file:// 直開きは不可 — ES module・fetch・Service Worker が動かないため、必ず HTTP 配信にしてください
  • プロジェクトデータ: web/projects/ に同梱のサンプルが選択肢に出ます。?kasc=<.kasc のURL> を付ければ外部ホスト上のプロジェクトもそのまま再生できます（仕様は ブラウザ WebGIS（外部ホスト配信） と同じ。エンジンの URL が自分のホストに変わるだけです）

3-2. 自前配信で動かない機能

フロントは起動時に /api/capabilities でサーバー能力を検出して UI を出し分けるため、 純粋な静的配信でもエラーにはならず、サーバー依存機能のボタンが自動で消えます。 失われるのはローカルアプリ（Rust サーバー）専用の機能です:

  • 設定のサーバー保存・プロジェクトのファイル書き込み
  • rclone クラウドストレージ連携・ローカルファイル保存（V5 のアプリ機能）
  • /api/gemini プロキシ経由のキーレス内蔵 AI（AI チャット自体はブリッジハブ等の別経路で使えます）
  • 自動更新（自前配信はファイルの差し替え＝自分で管理）

3-3. Service Worker 系の注意

  • DuckDB-WASM の永続キャッシュ（sw-duckdb.js）や vendor 中継（vendor-proxy-sw.js）は Service Worker 前提のため https または localhost が必要です。登録失敗時は握り潰す設計なので、http のイントラ IP 直叩きでも基本機能は動きます（キャッシュ効果が無いだけです）

4. 外部ライブラリの依存関係（CDN 参照の内訳）

4エンジンとも描画ライブラリ本体は CDN からピン留めバージョンで読み込みます。 自前の完全ホスト（閉域網・CDN ポリシー制約など）にする場合は、下表の URL をローカルファイルへ差し替えます。

maplibre maplibre-gl@6.19.0（css は index.html、.mjs は app.js 先頭の import） maplibre/index.html・app.js
openlayers ol@10.11.0（個別モジュールを app.js で import）＋ rbush/earcut/pbf/geotiff/zarrita（importmap・+esm） openlayers/index.html・app.js

4-2. オフライン / クローズド網化の手順

汎用手順は次の通りです。Cesium 本体の具体的なローカル化手順は 3. 閉鎖環境での利用 を参照してください。

  1. 上表のバージョンの npm dist ファイルをダウンロードし、web/vendor/ 等へ配置
  2. index.html の <script>/<link>/importmap と、app.js 先頭の CDN import を相対パスへ書き換える（importmap 方式は値の書き換えだけで済みます）
  3. タイル・検索 API 等のデータ参照先も外部 URL（地理院タイル・OSM 等）なので、完全オフライン化では自前タイルサーバー・ローカルタイルを .kasc で参照します

補足: vendor 依存エンジン（navara・gsimaps）では vendor-proxy-sw.js が vendor/* を vendor.json のピン先から同一オリジン中継しており、tools/fetch_vendor.py で実体を取得して ?hosted=<base> のミラーモードに切り替える仕組みがあります。4エンジンのライブラリ差し替えにも同じ考え方が使えます。

5. 独自カスタマイズの勘所（どこを触るか）

ファイル・フォルダ役割改造の効果範囲
web/<engine>/ui.config.json機能の表示/非表示・初期値・起動タブ・ヘルプ先コード無しでできる調整はまずこれ（UI カスタマイズ）
web/<engine>/index.htmlUI 構造 — パネル・タブ・ボタンの DOMそのエンジンの画面構成
web/<engine>/styles.css見た目・配色・レイアウトそのエンジンの外観
web/<engine>/app.jsエンジン別フロント（薄いアダプタ）— .kasc の各行をそのエンジンの API へ写像そのエンジンの描画・操作ロジック
web/shared/エンジン非依存コア — .kasc パーサ（kasc.js）・形式デコーダ（vector-load.js）・QML スタイルコンパイラ（qml-style.js/qml-2d.js）・where 評価・ポータル・player-api・i18n全エンジン共通 — ここを変えると4エンジンすべてに効く
web/<engine>/PLUGIN/ + plugins.json拡張プラグイン（パネル追加）— plugin: 行宣言で読み込み機能追加はプラグインとして書くのが本体改変より保守しやすい
web/projects/同梱サンプルプロジェクト（default 等）配信時の初期表示データ
web/vendor/上流スナップショット（navara/gsimaps 用）改変禁止 — 再取得で消えます
  • 改造の基本方針: エンジン固有の見た目・操作は <engine>/ 側、データ形式・.kasc 仕様・スタイル解釈は shared/ 側に置くのがこの設計の分かれ目です。新しいデータ形式や .kasc 行タイプを追加する場合は shared/ に実装すれば全エンジンで使えます
  • ライセンス: MIT — フォーク・改変・商用・再配布いずれも自由です（著作権表示の保持のみ必須）
  • 追従: 正本は kasugai_canvas リポジトリの web/ です。自前改造は fork 管理にし、上流の変更は自分で取り込みます
