KASUGAI Canvas v7.2.0

AI 教本としての利用 — 自前 WebGIS 開発時に Canvas の実装コードを AI エージェントの参照材料にする

1. 概要 — Canvas のコードを「AI への教科書」にする

各エンジン（Cesium / MapLibre / OpenLayers / Leaflet）で独自の WebGIS を開発するとき、 KASUGAI Canvas の web/ 実装コードを AI エージェント（Devin・Copilot・その他コーディングエージェント）に 参照材料として読み込ませる使い方です。 「同じ GIS 要件（.kasc の行タイプ）を4つの地図ライブラリで実装済み」という構成のため、 AI は対象エンジンの正しい API 写像・エッジケース対処をこのコードから直接学んで移植できます。

AI 教本として使いやすい前提条件が揃っています。

  • バニラ JS の ES modules — フレームワーク・ビルド工程・npm install が無く、ファイルをそのままコンテキストへ渡せる
  • 日本語コメント主体 — 設計意図・ワークアラウンドの理由がコード内に残っている（AI が「なぜそうするか」まで引き継げる）
  • 機能ごとのモジュール分割 — shared/ がエンジン非依存の機能単位（.kasc パーサ・形式デコーダ・スタイルコンパイラ等）に分かれており、必要な機能だけを抜き出して読ませられる
  • MIT ライセンス — コード抜粋・改変・自プロダクトへの流用が自由（著作権表示の保持のみ必須）

2. なぜ AI 教本として有効か

  • 同一要件の4実装 — 「XYZ タイルを重ねる」「GeoJSON をスタイル付きで描く」「カメラを動かす」「地物クリックで属性を出す」等の同じ要件が、宣言型スタイルの MapLibre・命令型 API の OpenLayers/Leaflet・3D シーンの Cesium でそれぞれ実装されています。AI は設計思想の違うエンジン間で何が共通で何が固有かを対比して移植できます
  • 実運用級のエッジケース — Service Worker キャッシュ・同一オリジン Worker 制約・遅延ロード・CORS・座標変換・縮尺↔高度換算など、ドキュメントや公式チュートリアルには出てこない対処がコメント付きで残っています
  • .kasc = AI への指示単位 — 行ベースの宣言形式なので、「この .kasc 行タイプを読むビューアを作って」という曖昧さの無い指示ができます。仕様は .kasc 設定仕様（インスペクター） が正本
  • 実績 — このリポジトリ自体が AI エージェント運用（AGENTS.md ルール・エンジン/形式ごとの実装照合スキル）を前提に整備されており、AI が読むことを想定した構造になっています

3. 実践手順 — AI に読ませる素材の選び方

基本は「作りたい機能に対応する shared/ モジュール + 対象エンジン app.js の該当箇所」を コンテキストとして渡すことです。やりたいこと別の対応表:

実装したい機能読ませるファイル
.kasc 形式の読み込み・レイヤツリー構築shared/kasc.js（parseKasc・loadKascProject）＋ 対象エンジン app.js のレイヤ追加処理
XYZ / WMS / WMTS タイルshared/kasc.js の buildWmsTileTemplate・buildWmtsTileTemplate ＋ app.js の base:/xyz:/wms: 行処理
GeoJSON ベクター＋スタイル描画shared/vector-load.js ＋ shared/qml-style.js（QGIS QML→各エンジン表現のスタイルコンパイラ）
GeoParquet / FlatGeobuf / GPKG のブラウザ内デコードshared/vector-load.js（hyparquet・flatgeobuf・sql.js・DuckDB-WASM 経路）
CSV/DB への SQL クエリapp.js の duckdb-wasm 遅延ロード箇所 ＋ shared/ogr-sql.js
カメラ・縮尺↔高度の換算shared/kasc.js の camToZoom・heightToViewZoom 等 ＋ app.js カメラ操作

多言語対応shared/i18n.js ＋ shared/i18n/*.json（9言語カタログ）
UI の配布単位カスタマイズ機構shared/ui-config.js（ui.config.json の適用器）

5. 注意点

  • コピーより「仕様として読ませる」方が確実 — app.js にはエンジン固有の最適化・ワークアラウンドが多く、素直な実装とは限りません。「この実装を参考に、自分のアプリ向けに簡潔に実装して」と意図を伝えてください
  • ライブラリバージョンはピン済み — AI が最新版で書き換えようとする場合は、index.html の CDN URL・vendor.json のピンを根拠として固定させてください（2-1 の依存一覧）
  • shared/ でも DOM 前提の関数がある — UI 非依存の移植には、DOM を触らないパーサ・デコーダ・換算関数を選んでください
  • ライセンス — MIT です。抜粋・移植したコードに元の著作権表示を残してください
