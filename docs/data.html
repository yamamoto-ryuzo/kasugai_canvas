データ形式（標準） — 主要4エンジンで使えるデフォルト形式とデータ管理

対応データ形式（標準）

インスペクターの .kasc 設定で行タイプとして指定できるデータ形式の一覧です。このページは主要4エンジン（Cesium・MapLibre・OpenLayers・Leaflet）すべてで描画できる標準形式をまとめています（GSI Maps・Navara は試験段階のエンジンのため判定対象外。対応状況はオプションページのマトリクスを参照）。一部のエンジンでしか使えない形式（ベクタータイル・GLB・GeoTIFF・地形指定）は データ形式（オプション・エンジン別） を参照してください。形式は描画経路で4区分しています — ネイティブ対応（変換なし・最速）/ 変換エンジン対応・高速（軽量デコーダー → GeoJSON 正規化）/ 変換エンジン対応・中〜高速（DuckDB-WASM クエリ系・初回ロード後は大規模で最速級）/ 変換エンジン対応・低速（sql.js 等の全件メモリ読み込み）。ベクター系は 全件読み込み系（全件読み込み・ベクター検索対象）と クエリ系（SQL 絞り込み・表示範囲のみ描画・検索は常に全件）の2系統に分かれます。共通の設計方針は「描画は表示範囲・索引は全件」で、描画件数の上限（フリーズ防止の安全弁）・表示範囲スライス・where= フィルタは描画に適用され、属性一覧の行は描画済み地物から作られるため同じ絞り込みが反映されます（ベクター検索索引・プラグイン API は常に全件対象）。CesiumJS ネイティブ非対応の形式は、ブラウザ側で GeoJSON に正規化して描画するため、レイヤ一覧・表示切替・属性検索・属性パネルがそのまま使えます。

ネイティブ対応（変換なし・最速）

エンジンがデータを直接読み込んで描画する形式です。デコード・正規化のコストが無く最速です。

🗺️ XYZ タイル / ベースマップ 推奨

xyz: / tile: で指定するラスタタイル。{z}/{x}/{y} 形式のタイル画像を重ね合わせ・ドレープ表示。base: はベースマップ選択リストへの登録行で、transparent / none のモード指定も可能。オルソ写真（地理院 seamlessphoto 等のタイル化済み正射画像）はこの経路が標準

🌐 WMS / WMTS 対応

wms: / wmts: で指定する OGC タイルサービス。WMS は GetMap タイルテンプレート、WMTS は KVP / RESTful 指定を {z}/{x}/{y} へ正規化して描画

🏙️ 3D Tiles 推奨

3dtiles: で tileset.json を指定。PLATEAU 建築物・点群など大規模3Dデータをストリーミング表示。Cesium はネイティブ、MapLibre/OpenLayers/Leaflet は deck.gl オーバーレイ（初回利用時に CDN 遅延ロード）で描画

🖼️ ジオリファレンス画像 対応

image: で画像を地図上へオーバーレイ。bbox=w,s,e,n または corners=（TL,TR,BR,BL 順）で配置を指定。単一画像のオルソ写真もこの経路

📍 GeoJSON 対応

geojson: / layer: で指定。ベクトル検索・属性一覧・ドレープに対応したベクターデータの基本形式。小〜中規模・全件表示はこれが最速

MVT/PMTiles・GLB・GeoTIFF・地形指定等のエンジン別形式は データ形式（オプション・エンジン別） を参照。

変換エンジン対応（高速 — 軽量デコーダーで GeoJSON 正規化）

ブラウザ内の軽量デコーダー（shared/vector-load.js・hyparquet・flatgeobuf 公式リーダー・togeojson・shpjs 等、いずれも遅延ロード）で GeoJSON へ正規化し、ネイティブのベクター描画経路へ流す全件読み込み系の形式です（既定は entity 化・render=primitive でバッチ描画も可）。読み込みは必要となった初回（表示ON、属性テーブルやベクター検索パネルでの選択時）に行い、結果はメモリに保持して2回目以降の表示切替・属性一覧・検索では再取得しません。off のレイヤーは起動時にダウンロードされません。描画件数の上限（表示 → ドレープ・既定 20000）を超えるレイヤーは表示範囲内の地物のみを描画し、カメラ移動で範囲内の地物に追随します（切り捨ては描画に適用され、属性一覧も描画済み地物が行になります。ベクター検索索引は常に全件対象）。

📦 GeoParquet 推奨

geoparquet: で指定。列指向バイナリ形式を hyparquet でデコードし GeoJSON へ正規化。常に全件読み込みのため中規模まで。「Parquet をそのまま置くだけで表示」の利便性重視の経路

🗺️ KML / KMZ 対応

kml: / kmz: で指定。@tmcw/togeojson で GeoJSON へ正規化（CDN・遅延ロード）。KMZ（ZIP）は先頭の .kml エントリを展開して読み込み。SimpleData 属性や KML Style の simplestyle 系プロパティも引き継ぐ

🌐 WFS 対応

wfs: で指定。OGC WFS の GetFeature（GET）を発行し、GeoJSON 応答をレイヤーとして描画。typename= が必須で、version=/maxfeatures=/cql_filter=/srsname= 等をオプション指定できる。CORS 非対応サーバーは直接接続不可

📐 Shapefile 対応

shp: / shapefile: で指定。shpjs（CDN・遅延ロード）が .zip 一式・.shp+sidecar（.dbf/.prj/.cpg 自動取得）・ベース名 URL を処理し、.prj があれば WGS84 へ再投影。zip 内の複数レイヤーは1レイヤーへ統合。CP932 系 dbf は .cpg 非対応のため文字化けする場合がある

📄 CSV / TSV 対応

csv: / tsv: で指定。lon/lat・経度/緯度・x/y 等の列名を自動判定してポイント化する簡易経路（表データとしての SQL 絞り込みは下のクエリ系カードを参照）

🥾 GPX 対応

gpx: で指定。@tmcw/togeojson（KML と同一経路・CDN 遅延ロード）で GeoJSON へ正規化。trk/trkpt は軌跡 LineString、wpt はポイント地物になる

🧩 TopoJSON 対応

topojson: で指定。topojson-client（CDN・遅延ロード）でトポロジーアークを復元し GeoJSON へ正規化。複数オブジェクトは全件展開

🛰️ CZML 対応

czml: で指定。CZML パケットを Canvas 側で GeoJSON へ変換（時系列 position は軌跡 LineString、point/polygon は地物として取り込み）

🗺️ EsriJSON / ArcGIS 対応

esrijson: / arcgis: で指定。ArcGIS REST の JSON（features/geometry・wkid 3857 等）を GeoJSON へ変換。空間参照は 4326 以外も自動補正

📃 GeoJSON Lines 対応

geojsonl: / ndjson: / jsonl: で指定。行区切り GeoJSON/Feature を逐行パースして FeatureCollection 化（ストリーミング系ログ向け）

✏️ WKT / WKB 対応

wkt: / wkb: で指定。WKT テキスト（1行1地物 or 全文1地物）と WKB（バイナリ/hex 文字列）を GeoJSON ジオメトリへデコード

🪂 IGC 対応

igc: で指定。グライダー飛行ログ（IGC 形式）を ol/format/IGC（CDN・遅延ロード）でパースし軌跡 LineString へ。時刻は地物の time プロパティへ保持

〰️ Encoded Polyline 対応

polyline: で指定。Google Polyline Algorithm のエンコード文字列を ol/format/Polyline でデコード（1行1本）。factor=/geometryLayout= で精度・次元を指定可

📐 GML / WFS(XML) 対応

gml: で指定。OGC GML / WFS GetFeature の XML 応答を ol/format/{WFS,GML} でパース。wfs: 行も JSON 応答を取れないサーバーでは自動でこの経路へフォールバック。EPSG:4326 は GML 仕様の lat,lon 順で解釈（lon,lat 記述の実ファイルは axisorder=lonlat で入替）

変換エンジン対応（中〜高速 — 大規模向けクエリ系）

duckdb: / sql: で指定するクエリ経路と、flatgeobuf: の空間インデックス範囲読み経路です。DuckDB-WASM（CDN から遅延ロード・約60MB）は重いランタイムですが、ランタイム資産は Service Worker がブラウザ内に永続キャッシュするため重いダウンロードはバージョンごとの初回のみです（詳細は ランタイム永続キャッシュ）。SQL で絞り込んでから GeoJSON へ正規化するため、ロード済み以降は大規模データでも最速級の描画になります。表示は見えている範囲のみ・検索は常に全件。spatial 拡張により空間述語・WKT・ST_Read も利用可能です（ST_Read／format=read はスレッド生成が必要なため COI 環境限定。FlatGeobuf・Shapefile は flatgeobuf:・shp: 経路を推奨）。対応するファイル形式は以下のとおりです。

📦 Parquet / GeoParquet 推奨

duckdb: で指定（format=parquet・既定）。where=/bbox=auto/columns= の絞り込みで述語プッシュダウン・row group スキップ・列プルーニングが効くクエリ系の本来の対象。大規模・広範囲データ向け

🧭 FlatGeobuf 推奨

flatgeobuf: / fgb: で指定。bbox=auto が既定 ON で、空間インデックス＋HTTP Range リクエストにより表示範囲の地物だけを読むクエリ系（カメラ移動で再クエリ・検索は常に全件）。DuckDB-WASM 不要の軽量経路で、重いランタイムなしに大規模データを扱える。索引なしファイル・Range 非対応サーバーは全件へフォールバック。bbox=off で全件読み込み系に戻る（全件バッファリングしない逐次デコード）。where= も利用可

📄 CSV / TSV 対応

duckdb: の lon=/lat= 指定で緯度・経度列を持つ表データをポイントとして表示（lon/lat/lng/longitude/latitude 列は自動検出）

📋 JSON / GeoJSON 対応

duckdb: の format=json（read_json_auto）でテーブルとしてクエリ可能。FeatureCollection の構造は format=read（ST_Read・spatial 拡張必須・COI 環境限定）向け

変換エンジン対応（低速 — 重いランタイム）

ファイル全件を WASM メモリへ読み込む DB 経路です。小〜中規模の確認用途には使えますが、大規模データは上のクエリ系または変換済み形式を推奨します。

🗂️ GeoPackage 対応

gpkg:（または duckdb: の拡張子判別・format=gpkg）で読み込み。sql.js（SQLite WASM）がファイル全件を WASM メモリへ読み込むため大容量では低速になります（Web Worker 実行のためデコード中も地図操作はブロックしません）。table= で複数地物テーブルを選択可。where=/limit=/columns=/bbox=auto（表示範囲連動・既定 ON）の絞り込みにも対応。QGIS が埋め込む layer_styles のスタイル（QML）も自動適用

方針の詳細（経路分類・新形式の追加手順）はリポジトリの AGENTS.md「データ形式方針」を参照してください。

2D データ

2D データ整理

WEB 化の変換先としての定石: ベクター = FlatGeobuf（flatgeobuf:・bbox=auto 既定 ON の空間インデックス+Range 範囲読み）、大規模な属性・SQL 絞り込み = GeoParquet + duckdb:、ラスタ・オルソ = XYZ タイル（base:/xyz:）。小規模なベクターは GeoJSON のまま、管理用マスターは GPKG を保持して配信用に変換する形が推奨です。

用途・データ領域 最適フォーマット 評価 強み 弱み・注意点
数千〜数万件の 2D図面・境界 GeoParquet / FlatGeobuf 🏆 最推奨 列指向バイナリ・空間インデックス。geoparquet: / flatgeobuf: でブラウザ内デコードし GeoJSON 正規化。変換不要で置くだけ geoparquet: は全件読み込みのため超大規模は向かない （flatgeobuf: は bbox=auto の範囲読みで大規模も可）
大規模・条件絞り込み・表示範囲連動 GeoParquet + duckdb: / sql: 🏆 大規模向け 述語プッシュダウン・row group スキップ・列プルーニング・bbox=auto で「見ている範囲だけ読む」。検索は常に全件 DuckDB-WASM の初期ロードが重い（SW キャッシュで緩和）
大容量・広範囲のバイナリベクター GeoParquet / FlatGeobuf 🏆 別枠推奨 バイナリ形式で転送量が小さく GeoJSON より大幅に軽い。ともに範囲読み込み可: GeoParquet は列指向・duckdb: 経路の述語プッシュダウン、 FlatGeobuf は空間インデックス＋HTTP Range（flatgeobuf: の bbox=auto 既定 ON） 索引なしの FlatGeobuf・Range 非対応サーバーは全件転送にフォールバック。 SQL の絞り込み・列選択が必要なら GeoParquet + duckdb: を推奨
広域・大量の全国地図・航空写真 XYZ / WMTS / WMS 🥈 GIS/Web 標準。ImageryLayer で地形ドレープ可（4エンジン対応） MVT/PMTiles は対応エンジン限定（オプション）
管理・連携用の正データ GPKG (GeoPackage) ✅ 管理用 Single Source of Truth。属性・トポロジ保持に優秀。gpkg: / duckdb:（sql.js Worker 経路）で直接読込も可 大規模データは描画用形式への変換を推奨
Esri 資産の管理・連携 FGDB (File Geodatabase) ✅ 管理用 Esri ツールとの互換。フィーチャクラス・ドメイン・関係対応 プロプライエタリ。ブラウザ直接描画不可。変換が必要
2D 図面への GLB 使用 — ❌ 3D メッシュ向け 属性・トポロジが弱く、2D 図面には向かない
  • KASUGAI Canvas 描画層：GPKG は gpkg: （sql.js Web Worker）で直接読み込むか GeoParquet/FlatGeobuf へ変換、FGDB は ogr2ogr 等のサーバー or 事前変換で GeoParquet / FlatGeobuf / GeoJSON に変換し、GeoJSON 正規化経路（GeoJsonDataSource / GeoJsonPrimitive）へ流す
