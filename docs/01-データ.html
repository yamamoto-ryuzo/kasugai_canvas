KASUGAI Canvas で扱えるデータ形式一覧

直接描画可能なデータ形式

分類 形式 描画方法 備考
2D ベクトル GeoArrow / FlatBuffers deck.gl GeoJsonLayer（binary） 最も推奨。GeoArrow/FlatBuffers から deck.gl 独自 binary へ変換して GPU バッファへゼロコピー
2D ベクトル GeoJSON（小〜中規模） deck.gl GeoJsonLayer 大容量時は GeoArrow/FlatBuffers への変換を推奨
2D タイル MVT / XYZ / WMTS deck.gl TileLayer / MVTLayer 広域地図・航空写真（WMTS は TileMatrixSet 変換が必要）
3D モデル GLB / glTF 2.0 deck.gl ScenegraphLayer / Three.js GLTFLoader 建機・構造物
3D タイル 3D Tiles 1.1 (GLB 内包) deck.gl Tile3DLayer / Three.js 3DTilesRenderer PLATEAU 等。LOD・ストリーミング対応
点群 EPT / Potree 形式 deck.gl PointCloudLayer / Three.js Points 大規模点群向け
3DGS PLY / SPZ / .splat / .ksplat / .sog Three.js 系専用レンダラー gaussian-splats-3d 等。deck.gl はカメラ同期
DEM / 地形 標高PNG (XYZ / WMTS) deck.gl TerrainLayer GPU リアルタイムメッシュ化

パイプライン（変換）が必要なデータ形式

分類 形式 変換先 備考
2D ベクトル GPKG (GeoPackage) GeoArrow / FlatBuffers / MVT SQLite + WKB。Web Worker 等で変換
2D ベクトル FGDB (File Geodatabase) GeoArrow / FlatBuffers / MVT プロプライエタリ。ogr2ogr 等で変換
2D ベクトル GeoJSON（大規模） GeoArrow / FlatBuffers ゼロコピー描画のため変換
点群 PLY / LAS / LAZ EPT / 3D Tiles / PointCloud バッファ ブラウザ内 or 事前変換
DEM / 地形 GeoTIFF / CSV 等 標高PNG / GLB / 3D Tiles Web Worker またはサーバー側で変換
  • 直接描画可能：deck.gl / Three.js のローダーまたはレイヤーでそのまま描画可能
  • 要専用レンダラー：Three.js 系の専用ライブラリが必要。deck.gl はカメラ同期のみ
  • パイプライン（変換）が必要：ブラウザ内 Web Worker または事前変換が必要。GPKG/FGDB は Single Source of Truth として管理・変換元に使用

deck.gl と Three.js の担当分け

データ 主担当エンジン 補完エンジン 用途
2D ベクトル (GeoArrow / FlatBuffers) deck.gl (GeoJsonLayer（binary）) – 図面・境界・大容量 2D
2D タイル (MVT / XYZ / WMTS) deck.gl (TileLayer) – 広域地図・航空写真
GLB / 3D Tiles deck.gl (ScenegraphLayer / Tile3DLayer) Three.js (GLTFLoader) 建機・構造物・都市モデル
点群 (PLY / LAS / EPT) deck.gl (PointCloudLayer) Three.js (Points / Potree) 測量・LiDAR 点群
3DGS (PLY / SPZ / Splat) Three.js 専用レンダラー deck.gl (カメラ同期) 写真測量・ニューラル表現
管理データ (GPKG / FGDB) Web Worker → 変換 – 正データ保持・変換元
  • deck.gl：2D/3D Tiles/Buffers を同一 GPU コンテキストでゼロコピー描画
  • Three.js：点群・3DGS・高度な GLB 表現を補完。deck.gl とカメラを同期させて重ねる

2D データ

2D データ整理

用途・データ領域 最適フォーマット 評価 強み 弱み・注意点
数千〜数万件の 2D図面・境界 FlatBuffers / GeoArrow 🏆 最推奨 ゼロコピーで GPU バッファへ直結。数十万〜数百万のベクター可視化 –
広域・大量の全国地図・航空写真 MVT / XYZ / WMTS 🥈 GIS/Web 標準。圧縮・サイズ削減に強い デコードに CPU を使う
管理・連携用の正データ GPKG (GeoPackage) ✅ 管理用 Single Source of Truth。属性・トポロジ保持に優秀 ブラウザ直接描画は向かない（SQLite + WKB パース）
Esri 資産の管理・連携 FGDB (File Geodatabase) ✅ 管理用 Esri ツールとの互換。フィーチャクラス・ドメイン・関係対応 プロプライエタリ。ブラウザ直接描画不可。変換が必要
2D 図面への GLB 使用 — ❌ 3D メッシュ向け 属性・トポロジが弱く、2D 図面には向かない
  • KASUGAI Canvas 描画層：GPKG は Web Worker で、FGDB は ogr2ogr 等のサーバー or 事前変換で FlatBuffers / MVT に変換し、deck.gl の GeoJsonLayer（binary） / TileLayer へゼロコピーで渡す

3D データ

3D データ整理

用途・データ領域 最適フォーマット 評価 強み 注意点
単体オブジェクト（建機・構造物） GLB (glTF 2.0) 🏆 最推奨 3D モデルの「3D 版 JPEG/PNG」。1 ファイルで完結 –
広域・大容量（都市モデル） 3D Tiles 1.1（GLB 内包） 🏆 最推奨 タイル化・LOD 制御でストリーミング 1.1 から glTF 2.0 / GLB ペイロードを直接利用可能
点群（測量・LiDAR 生データ） LAS/LAZ / PLY / EPT 🥈 測量標準。EPT は大規模点群を階層タイル化 そのままの描画には変換・ローダーが必要
画像からのニューラル表現 3DGS (PLY / SPZ / Splat) 🥈 写真起点の高品質ビジュアル。SPZ は PLY 比 10x 圧縮 PLY は未圧縮で大容量。描画には専用レンダラーが必要

KASUGAI Canvas への読み込み方

データ 描画エンジン ロード方法
GLB / 3D Tiles deck.gl (ScenegraphLayer / Tile3DLayer) または Three.js (GLTFLoader / 3DTilesRenderer) loaders.gl 経由でゼロコピー
点群 (PLY / LAS) deck.gl (PointCloudLayer) または Three.js (Points / Potree) PLY/LAZ → 変換 → バッファ渡し
3DGS (PLY / SPZ) Three.js 専用レンダラー gaussian-splats-3d / SuperSplat 等で読み込み

点群の扱い

  • LAS/LAZ：測量・LiDAR での標準。LAZ は圧縮形式
  • PLY：簡易入出力用。点位置 + RGB のみの軽量点群も可能
  • EPT (Entwine Point Tile) / Potree 形式：ブラウザ向け大規模点群配信。八分木階層で LOD 制御
  • 大量点群は EPT や 3D Tiles 点群（pnts / 1.1 glTF） に変換して deck.gl / Three.js で描画すると安定

3D Gaussian Splatting（3DGS）

  • 3D 空間上の多数のガウス分布でシーンを表現するニューラル描画手法
  • 主要フォーマット
    • PLY：学習済みモデルのデファクト標準。各ガウスに位置・スケール・回転・不透明度・球面調和係数を保持
    • SPZ：Niantic 公開の圧縮形式。PLY と比べて約 10 倍小さく、Web 配信に適している
    • .splat / .ksplat / .sog：各ビューアー向けの圧縮・最適化形式
  • KASUGAI Canvas では Three.js 側で専用レンダラーを使い、deck.gl レイヤーとカメラ同期を行う

地形（DEM）の扱い

  • deck.gl TerrainLayer：標高PNG (XYZ / WMTS) を読み込み、GPU でリアルタイムにメッシュ化。国土地理院標高タイルを使う場合は RGB → 標高値（x = 2^16R + 2^8G + B、u は標高分解能 0.01m）に変換する必要がある。ただし GSI 標高タイルは x < 2^23 のとき h = xu、x = 2^23 のとき NA、x > 2^23 のとき h = (x - 2^24)u という符号付き・条件分岐形式のため、deck.gl の elevationDecoder だけでは扱えず、事前変換または GSI 専用レイヤーが必要
  • Three.js：DEM 画像から PlaneGeometry + displacement map / 頂点シェーダーで terrain メッシュを生成
  • PLATEAU 3D Tiles：3D 都市モデル（建物・地形等）を LOD 付きで配信しているので Tile3DLayer / Three.js 3DTilesRenderer でそのまま表示
  • 生の DEM（GeoTIFF / CSV 等）は、Web Worker またはサーバー側で 標高PNG / GLB / 3D Tiles に変換してから描画

データパイプライン

KASUGAI Canvas へのデータは、以下のパイプラインを経て描画層に届く。

現場データ（GPKG / FGDB / GeoJSON / GLB / LAS / PLY / SPZ）
    ↓
① 変換
    ブラウザ内（Web Worker / WASM）: sql.js / Arrow-JS / geopackage-js
    サーバー or 事前変換: ogr2ogr / Potree Converter / entwine
    ↓
② 描画用フォーマット
    GeoArrow / FlatBuffers / MVT / 3D Tiles / EPT / GLB
    ↓
③ 配信・キャッシュ
    OPFS / IndexedDB / S3 / MinIO / CDN
    ↓
④ 描画
    deck.gl / Three.js（VRAM ゼロコピー）
段階 役割 対象データ・技術
入力 正データ・管理データの保持 GPKG、FGDB、Re:Earth（属性・プロジェクト管理）
変換 ブラウザ内 or 事前変換 2D 図面 → GeoArrow/FlatBuffers、点群 → EPT/3D Tiles、3DGS → SPZ
配信 タイル・バイナリの配信 S3/MinIO、CDN、Martin、Tegola
描画 GPU 直接描画 deck.gl GeoJsonLayer（binary） / TileLayer / Tile3DLayer、Three.js
  • 点群・3DGS・生 DEM は ブラウザ内で変換するのではなく、事前に 3D Tiles / EPT / SPZ へ変換 しておくのが現実的
  • GPKG は Web Worker / sql.js + WKB パーサー 経由で FlatBuffers / MVT に、FGDB は ogr2ogr 等のサーバー or 事前変換で GeoJSON/CSV 経由 FlatBuffers / MVT に変換し、deck.gl へゼロコピーで渡す
  • 変換済みデータは OPFS や IndexedDB にキャッシュし、次回起動時の読み込みを短縮する

配信サービス

  • PLATEAU / GIS データの管理・メタデータ付与に強い
