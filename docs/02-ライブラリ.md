## 2. ライブラリ

KASUGAI Canvas を構成する主要ライブラリについてまとめる章。基本は **deck.gl + Three.js + loaders.gl**。

## 推奨構成：KASUGAI Canvas

| 役割 | ライブラリ | 備考 |
|------|-----------|------|
| 2D/3D/Tiles/Buffers 主軸描画 | **deck.gl (+ loaders.gl)** | KASUGAI Canvas の核。同一 GPU コンテキストでゼロコピー描画 |
| 点群・3DGS・高度な 3D 表現 | **Three.js** | GLB/点群/3DGS エコシステム。deck.gl と同一 canvas 内で連携 |

- **KASUGAI Canvas = deck.gl + Three.js**。地理院標高PNG / PLATEAU 3D Tiles 等をそのまま読み込む。
- **正式な描画方式：同一WebGLコンテキスト方式**。deck.glとThree.jsのレイヤーを同一の3D空間・深度バッファ・カメラで混在管理する。

## KASUGAI Canvas で可能な表示モード

| 表示モード | 可否 | 説明 |
|-----------|------|------|
| **平面（2D 地図・図面）** | ◎ | `MVTLayer` / `GeoJsonLayer（binary）` / `TileLayer` で標準対応 |
| **3D パース（3D モデル・点群・3DGS）** | ◎ | `Tile3DLayer` / `ScenegraphLayer` + Three.js `GLTFLoader` / 点群 / 3DGS レンダラー |
| **地形（DEM ドレープ）** | ◎ | `TerrainLayer` + 標高PNG、または Three.js displacement map |
| **グローブ（球形地球儀）** | ❌ | 球面上の地球儀表示は KASUGAI Canvas の対象外 |

- KASUGAI Canvas は **平面 or ローカル 3D 空間** を扱う。グローブは扱わない。
- **WGS84 / 平面直角座標等の座標系は使える**。データを **ローカル 3D 座標系（平面直角 + 標高 / ENU / UTM + 標高）** に変換して `deck.gl` / `Three.js` で描画する。地球儀にしない、ただ 3D 空間として扱うだけ。

## データ種別別のライブラリ選択

| データ | deck.gl | Three.js | 備考 |
|--------|---------|----------|------|
| 2D Buffers (GeoArrow/FlatBuffers) | ◎ | △ | deck.gl `GeoJsonLayer（binary）` が最適 |
| 2D タイル (MVT/XYZ) | ◎ | △ | deck.gl `TileLayer` / `MVTLayer` |
| 3D Tiles / GLB | ◎ | ◎ | `Tile3DLayer` / `ScenegraphLayer` or `GLTFLoader` |
| 点群 (PLY/LAS/EPT) | ◯ | ◯ | deck.gl `PointCloudLayer` or Three.js `Points` / Potree |
| 3DGS (PLY/SPZ/Splat) | △ | ◎ | Three.js 系専用レンダラー |
| 地形（DEM / 標高PNG） | ◯ (`TerrainLayer`) | △ | 地理院標高PNG / PLATEAU 3D Tiles / DEM を deck.gl `TerrainLayer` または Three.js displacement で扱う |

## deck.gl の強力機能

| 拡張 | 機能 | 用途例 |
|------|------|--------|
| **TerrainExtension** | 2D図面・境界を3D地形にドレープ | 施工区画線、道路中心線の地形吸着表示 |
| **MaskExtension** | 2Dポリゴンで DEM / 3D Tiles をくり抜き | 敷地枠内のみ3D地形を表示 |
| **ClipExtension** | 3D Tiles ・点群の断面カット | 建物内部、トンネル断面、点群高さスライス |

- いずれも **GPU シェーダー / ステンシル** で処理するため、大容量データでも重くならない

## 点群・3DGS 用ライブラリ

| ライブラリ | 点群 (LAS/PLY/EPT) | 3DGS (PLY/SPZ/Splat) | 特徴 |
|-----------|--------------------|---------------------|------|
| **deck.gl (+ loaders.gl)** | ◯ (`PointCloudLayer`) | △ (要カスタムレイヤー) | 大容量点群を GPU 描画。3DGS は現状最適化されていない |
| **Three.js** | ◯ (`BufferGeometry`) | ◎ (`gaussian-splats-3d` / Splat Viewer) | 3DGS エコシステムが最も充実 |
| **Potree** | ◎ (専用点群レンダラー) | ❌ | 大規模点群 Web 可視化特化 |
| **PlayCanvas SuperSplat** | ❌ | ◎ | 3DGS 専用ビューアー。変換・最適化にも強い |

- **点群**：大量 PLY / LAS は **Potree 形式 / EPT / 3D Tiles（pnts）** へ変換して KASUGAI Canvas（deck.gl / Three.js）で描画
- **3DGS**：そのまま描画には **Three.js 系の専用レンダラー** が現状最適。配信には **SPZ** 等の圧縮を検討

## deck.gl + Three.js の連携パターン

### 正式仕様：同一 canvas（同一 WebGL コンテキスト）

- `deck.gl` の `gl` / `device` に Three.js と同じコンテキストを渡し、1 フレーム内で両方を描画
- 深度バッファ・カメラ行列・ビューポートを同期すれば、2D/3D が正しく重なる
- フレームループを `deck.setProps({ onBeforeRender, onAfterRender })` や `luma.gl` 経由で制御
- deck.glレイヤーとThree.jsレイヤーを共通レイヤー管理へ登録し、表示順・深度・クリッピング・ピッキングを統合する
- 将来の本番実装はこの方式を採用し、オーバーレイ方式を正式な描画方式として採用しない

### 参考方式：オーバーレイ

- Three.js 用の `<canvas>` を下層、deck.gl 用の `<canvas>` を上層に重ねる
- 両方を同じサイズ・カメラに揃え、CSS `pointer-events` を調整
- 実装が容易で、各エンジンの描画サイクルを独立に保てる
- プロトタイプや障害切り分けには使用できるが、深度・レイヤー順・ピッキングを統合できないため本番仕様にはしない

### Three.js → deck.gl 橋

- Three.js の `BufferGeometry` や `Scene` を `deck.gl` の `ScenegraphLayer` 経由で描画可能
- GLB ロードは `loaders.gl` の `GLTFLoader` または Three.js `GLTFLoader` を使い、メッシュを `ScenegraphLayer` へ渡す

## 補完ライブラリ

| 用途 | ライブラリ | 説明 |
|------|-----------|------|
| 座標変換 | **proj4.js / coordsys** | 平面直角座標 ↔ WGS84 等の変換 |
| GPKG 変換 | **sql.js + WKB パーサー** | ブラウザ内で SQLite（GPKG） → Arrow/GeoJSON 変換 |
| FGDB 変換 | **ogr2ogr（サーバー or 事前変換）** | プロプライエタリ形式をブラウザ内では読みにくいため、サーバー or 事前変換で対応 |
| 点群変換 | **Potree Converter / entwine** | PLY/LAS → EPT / 3D Tiles |
