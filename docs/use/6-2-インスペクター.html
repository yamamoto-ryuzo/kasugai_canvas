.kasc 設定仕様 — インスペクター設定の完全な書式

使い方

管理（⚙）→ プロジェクト → インスペクター で .kasc 形式を編集・適用します。このページが設定仕様の正本です。ユーザーがテキストエリアに入力したレイヤー・ベースマップ・カメラプリセットを読み込み、CesiumJS Viewer へ反映します。設定の読み込みはブラウザ内で完結し、HTTP 通信は行いません。

ローカルファイルの追加（デモ用データ・Chromium系）

  1. Inspectorタブ「フォルダを選択」で canvas_data/ を指定（File System Access API・変更可・IndexedDB保持）
  2. ファイル選択 → 「canvas_data/ に保存して追加」 で書き込み＋設定追記＋登録まで一括
  3. 「設定行のみ追加」は追記のみ（手動コピー用）、「今すぐプレビュー」は一時表示
  4. 保存したcanvas_data/ファイルは .kasc と共に配布すればデモサイト化できます

設定方法（.kasc 行書式）

基本書式

種類:タイトル|URL|出典|オプション名=値|on/off

URLが canvas_data/... 等の相対パスなら projects/<project>/ 直下（canvas_data/ は慣例のサブフォルダ）に解決。ローカルサーバーでクラウド接続中は cloud:<パス> で接続中ストレージ（ルートフォルダ基準）のファイルを参照できます（Range 対応）。任意位置の on/off（false 可・大文字小文字不問）で初期表示を指定。

.. はプロジェクトフォルダの1つ上への参照です。例: ../canvas_data/x.geojson は、通常プロジェクトでは全プロジェクト共有の projects/canvas_data/、外部プロジェクト（.kasc をダブルクリック登録したもの）では .kasc のあるフォルダと並列の canvas_data/ に解決されます。プロジェクト群フォルダに projects.json（群マニフェスト）を置くとその上もスコープになり、../../canvas_data/x でワークスペースルート（複数のプロジェクト群が共有する canvas_data/）まで参照できます（マニフェストが無い構造では1階層上まで・それより上は拒否）。

  • html: セクションと portal:…|html= のカスタムHTML内では data-* 属性でGIS側を宣言的に操作できます：data-view="ビュー名"（view: 適用＋ポータルを閉じる）・data-link="URL"（外部URLを新規タブ）・data-cam="カメラ名"/data-base="背景名"（ポータルを開いたままカメラ/背景だけ変更）・data-clear（ビュー解除＝適用前スナップショット復元）・data-close（ポータルを閉じる）。<script>/<iframe>/<object>/<embed>/<form>/<link>/<style> は要素ごと、on*属性と javascript: URL は属性ごと除去されます（装飾は各要素の style= 属性で記述。詳細は 1-9 ポータル の「フルカスタムHTML」節）。

ベクターデータ形式の使い分け

ベクター系の行タイプは大きく2系統に分かれます。全件読み込み系（geojson:/kml:/wfs:/shp:/csv:/gpx:/topojson:/czml:/esrijson:/geojsonl:/wkt:/wkb: 等）はファイル全件を読み込んで描画し、ベクター検索パネルで属性検索できます（描画件数の上限を超える場合は表示範囲内の地物のみ描画し、カメラ移動で追随）。クエリ系（duckdb:/sql:/ogrsql:）は SQL で絞り込み、表示は見えている範囲だけ・検索は常にファイル全件を対象にします。gpkg:/flatgeobuf:/geoparquet: も既定で bbox=auto のクエリ系（表示は範囲のみ）として動作します。geoparquet: は covering.bbox 列か行グループ geospatial statistics が無いファイル・Range 非対応サーバーでは全件読み込み系へ自動フォールバックします。常時全件を描画したい場合は bbox=off を付けると全件読み込み系（検索パネル対象）に戻ります。

【全件読み込み系】全件読み込み・ベクター検索パネル対象
  小〜中規模・全件表示        → geojson:（事前変換が最速・最単純）
  中規模・Parquet をそのまま  → geoparquet:（利便性重視・変換不要で置くだけ）
  中規模・FlatGeobuf をそのまま → flatgeobuf:（変換不要・ストリームで逐次デコード）
  中規模・QGIS 成果物          → gpkg:（GeoPackage。layer_styles の QGIS スタイルも自動適用）

【クエリ系】SQL 絞り込み・表示範囲のみ描画・検索は常に全件
  大規模・広範囲・絞り込み    → duckdb:/sql:（Parquet の利点が発揮される）
  大規模・QGIS 成果物          → gpkg:（bbox=auto が既定。where= でさらに絞り込み可）

超大規模・全件表示            → タイル化（MVT/PMTiles = mvt:/pmtiles: 行で対応）

Parquet の利点（圧縮・述語プッシュダウン・row group スキップ・列プルーニング・Range Request）は「読まない部分を作れる」ときにだけ効きます。全件を読んで表示するだけなら、変換済み GeoJSON の方が速くて単純です。geoparquet: は絞り込みを持たず常に全件読み込みなので、広範囲データや条件絞り込みが必要な場合は duckdb:/sql: を使ってください。

読み込みタイミング：全件読み込み系レイヤーは、必要となった初回（表示ON、属性テーブルやベクター検索パネルでレイヤーを選択した時点）にダウンロード＋デコードします。ベクター検索パネルのレイヤー選択肢には未読み込みのレイヤーも「(未読込)」付きで表示され、選択すると読み込み後に索引されて検索できるようになります。「全選択」で文字検索を実行すると、非表示・未読み込みのレイヤーもその時点でまとめて読み込んで検索対象にします。表示中のレイヤーだけを対象にしたい場合は「表示レイヤ」を選択してください。off のレイヤーは起動時に読み込まれません。取得結果はメモリに保持されるため、2回目以降の表示切替・ドレープ変更・属性一覧では再取得せず即座に反映されます（キャッシュはインスペクター/プロジェクト変更で破棄）。クエリ系は条件ごとに結果が変わるため毎回クエリします。

QGIS スタイル（style=）：ベクター系レイヤー全般に style=QMLファイルのURL を付けると、QGIS のレイヤースタイルファイル（.qml）を取得して描画に適用します。単一シンボル・属性値による分類（categorizedSymbol）・数値段階（graduatedSymbol）・ルールベース（RuleBased・QGIS 式のサブセットを評価）の各レンダラに対応し、シンプルマーカー/SVG・ラスタ/フォントマーカー、実線・破線、単色塗り・ハッチ/ドット/画像パターン塗り、ラベル（<labeling> のシンプル/ルールベース）を再現します。データ定義プロパティ（式による色・サイズの上書き）や縮尺依存ルール（概算のカメラ距離へ変換）も反映します。式関数 is_layer_visible('レイヤー名') にも対応し、別レイヤーの表示状態を参照した条件付きスタイルが使えます（レイヤー名はタイトル・ID・グループパスで照合、見つからないレイヤーは非表示として扱います）。QGIS で再現困難な要素（ジオメトリジェネレータ・ヒートマップ等）は最も近い表現にフォールバックし、コンソールに警告を出します。render=primitive 経路では色・サイズ・線幅のみ適用（形状・破線・パターンは簡略化）。.kasc プロジェクトと同じ場所に .qml を置けば相対パスでも解決します。

GeoPackage の埋め込みスタイル：gpkg:（または duckdb: で .gpkg ファイル・format=gpkg を指定した場合）は、QGIS の「スタイルを保存 → データベースに保存」で GPKG 内の layer_styles テーブルに書き込まれる QML を自動的に読み取り、useAsDefault のスタイルを描画に適用します。データとスタイルを1ファイルで配布できます。style= を明示した場合はそちらが優先されます。複数スタイルが登録されている場合は gpkgstyle=スタイル名 で既定以外を選択できます。layer_styles に SLD 形式（styleSLD）のスタイルしか無い場合は、SLD サブセット（Point/Line/Polygon Symbolizer・TextSymbolizer ラベル・条件フィルタ・縮尺範囲）として描画に適用します。OGC の Portrayal（スタイル格納）拡張のテーブル（gpkgext_styles／gpkgext_stylesheets／gpkgext_symbols／gpkgext_fonts。作業部会ドラフト OGC 24-050）を含む GPKG では、MapLibre エンジンに限り GeoDataClass 注釈（OGC 24-049）で地物表へ紐付けられた mbstyle スタイルシートを自動適用し、シンボル画像（gpkgsym 参照・スプライト切出し対応）・mbstyle sprite 指定の sprite.png/sprite.json 登録・フォント（Mapbox glyphs zip・TTF/OTF）も登録します。他エンジンでは登録内容（スタイル名・形式・シンボル・フォント件数）を警告として通知します。複数の地物テーブルを持つ GPKG は table=テーブル名 で対象を指定できます。GPKG は SQLite として読み込みます。sql.js（SQLite WASM）を Web Worker 内で遅延ロード・実行するため、デコード中も地図の操作をブロックしません。ファイル全体の初回ダウンロードは必要ですが、開いた DB は Worker が保持するため、bbox=auto の表示範囲再クエリ・⏷フィルター変更・属性一覧のクエリは再ダウンロード無しで実行されます。なお sql.js の WASM 本体はランタイム永続キャッシュの対象外（通常のHTTPキャッシュのみ）です。

GeoPackage の埋め込みスタイル：なお default_style: 行で地物の既定スタイルを指定できます（後述の専用節を参照）。

GeoPackage のメタデータと警告：gpkg: は gpkg_spatial_ref_sys の座標系を確認し、経緯度系ではない GPKG（投影座標系など）は自動的に WGS84 へ再投影して描画します（EPSG:3857 は内蔵数式、それ以外は GPKG 内蔵の座標系定義 WKT を proj4 で解釈、どちらも解けない場合のみ epsg.io の定義を参照。すべて失敗した場合は「表示位置がずれます」という警告を出します）。また gpkg_extensions に登録された未対応拡張（タイル行列セット・関連テーブル等）も警告として通知します。曲線ジオメトリ（CircularString／CompoundCurve／CurvePolygon 等の WKB 8〜17 タイプ）は折線近似して描画し、QGIS の曲線地物が消失することはありません。gpkg_data_columns に列の日本語タイトルがある場合は属性パネルの列名として使われます。ジオメトリを持たない属性専用テーブル（data_type=attributes）も table= で指定でき、属性一覧・ベクター検索から参照できます。

地物の既定スタイル（default_style:）

ベクター系レイヤー（geojson:/geoparquet:/flatgeobuf:/gpkg:/duckdb:/sql:/ogrsql:）の地物で、スタイル指定を持たない項目に適用する既定値を、ジオメトリ種別ごとに1行ずつ設定します。配色をプロジェクト単位で調整したいときに使います。地物ごとの優先順位は次のとおりです。

地物の simplestyle プロパティ(marker-color / stroke / fill 等)
    > style= の QML スタイル(レイヤー全体)
    > default_style: 行(この設定)
    > エンジン既定色

地物側にその項目の指定があれば地物側が優先され、default_style: はあくまで「未指定項目の穴埋め」です。style= の QML が適用されたレイヤーには適用されません。設定はプロジェクト（.kasc）スコープで、同じ種別の行を複数書いた場合は後の行が採用されます。

default_style: point   | color=#3388ff | size=48 | symbol= | opacity=1
default_style: line    | color=#ff0000 | width=2 | opacity=0.8
default_style: polygon | fill=#3388ff | fill_opacity=0.3 | stroke=#000000 | stroke_width=1 | stroke_opacity=1

  • ポリゴンの輪郭：Cesium 版では stroke=・stroke_width=・stroke_opacity= のいずれかを指定した場合のみ輪郭を描きます（通常は輪郭なし。地物側の stroke プロパティがあればその色が優先）。ドレープ（地形/3D Tiles へのクランプ）時は周線をポリラインで描きます。2D エンジンではポリゴンに常に輪郭があるため、未指定時はエンジン既定の輪郭色が使われます。
  • ポイントの描画差：Cesium（entity 経路）はピン形状で描画し size= はピンの高さ(px)。render=primitive（バッチ描画）と 2D エンジンはドット描画のため約1/6の径に換算します。
  • 地物側の指定との併用：GeoJSON プロパティの marker-color/marker-size/marker-symbol/stroke/stroke-width/stroke-opacity/fill/fill-opacity（simplestyle）が各項目に優先します。例えば default_style: line | color=#ff0000 でも stroke プロパティを持つラインはその色で描かれます。marker-symbol は Maki アイコン ID・a〜z/0〜9 の1文字・画像 URL を受理します（2D は円バッジ近似・Cesium entity は PinBuilder のピン）。色値は # 省略形（3bb2d0）も受理します（simplestyle 準拠・ロード時に # 付きへ正規化）。title/description プロパティは地物クリック時のポップアップ見出し・本文として表示されます（description の HTML はスクリプト等を除去して描画）。KML 変換系（togeojson）由来の icon/icon-scale/icon-opacity/heading/icon-offset/icon-color プロパティも点アイコンとして適用されます（icon-color は KML の aabbggrr 形式を受理）。

  • 種別は point/p/marker/dot、line/l/polyline、polygon/poly/area/fill の別名を受け付けます。解釈できない種別の行は無視されます。

duckdb: / sql:（SQL絞り込みレイヤ）

初回利用時に DuckDB-WASM を CDN から遅延ロードします（Worker 内で実行）。duckdb: は単一ファイルを読み込み、where=/limit= を適用して描画します。sql: はタイトル後の | 以降をすべて SELECT 文として実行します（クエリ内で | 使用可・|| 演算子も可）。末尾オプションとして | off（非表示）・| render=entity|primitive（描画方式）・| attr=出典（右下の出典表示。値に | は含められません）を付けられます。クエリ内の URL は絶対指定が必要です。なおクエリ系レイヤーが非表示の場合は、表示ONまたは属性テーブルで選択されるまで WASM 自体をロードしません。

ランタイムの永続キャッシュ：DuckDB-WASM のランタイム資産（WASM 本体約33MB・Worker スクリプト・spatial 拡張約22MB・parquet/httpfs 拡張、計約60MB）は cdn.jsdelivr.net と extensions.duckdb.org から取得しますが、Service Worker（sw-duckdb.js＝DuckDB-WASM 永続キャッシュ）がこれらの取得を横取りしてブラウザの CacheStorage に永続保存します。そのため実際のダウンロードはバージョンごとに最初の1回だけで、2回目以降の起動・再読み込み・ブラウザ再起動後もキャッシュから即座に読み込まれます（通常のHTTPキャッシュと違い、ブラウザ任せの失効がありません）。キャッシュキーは URL そのまま（@duckdb/duckdb-wasm@1.32.0・拡張 v1.4.3 のようにバージョン入り）のため、DuckDB のバージョンが上がると新しい資産が自動的にダウンロードされ、起動時に旧バージョンのエントリだけが削除されます。Worker 内部のフェッチ（Worker スクリプトの読み込み・拡張 INSTALL の内部取得）も対象で、DuckDB 以外の通信には一切介入しません。Service Worker は HTTPS または localhost でのみ有効で、静的ホスティングでも動作します。ブラウザのサイトデータ削除でキャッシュも消えるため、その場合は次回利用時に再ダウンロードが発生します。詳細は ランタイム永続キャッシュ を参照してください。

対応ファイル形式（format= 指定または拡張子から自動判別）：

format=省略        → 拡張子自動判別（.parquet / .csv / .tsv / .json / .fgb 等）
format=parquet     → Parquet / GeoParquet（read_parquet）
format=csv | tsv   → CSV / TSV（read_csv_auto。lon=/lat= 列でポイント化、WKT/WKB 列も可）
format=json|geojson→ JSON / GeoJSON テキスト（read_json_auto。FeatureCollection は format=read 推奨）
format=read        → Shapefile / FlatGeobuf(.fgb) 等（ST_Read。spatial 拡張必須・非 COI 環境・リモート URL では動作しません。*.fgb は拡張子からも自動判別されます。GeoPackage は gpkg:/sql.js 経路へ自動振り分け）

Parquet では述語プッシュダウン・row group スキップ・列プルーニングが効くため本機能の本来の対象です。それ以外の形式は全件読み込みになりますが、「絞り込んだ分だけ描画オブジェクトを作る」「事前変換不要」「SQL で加工できる」利点は共通です。

ジオメトリ列は GEOMETRY 型 → geometry/geom/wkb 等の慣用名 → BLOB 列の順に自動検出し、geom= で明示も可能です（WKB・WKT・GeoJSON テキストを受理）。緯度経度列のみのデータは lon=/lat= でポイント化できます。format=read は spatial 拡張の ST_Read（Shapefile・FlatGeobuf 等）を使いますが、非 COI 環境ではスレッド生成に失敗しリモート URL も読めないため、通常の配信環境では利用できません。なお where= は行の最終オプションで値は改行までが式のため、|| 連結や | を含むリテラルもそのまま書けます（where= より後ろに他のオプションは置けません）。

取得プロキシ（proxy=on・ローカルサーバー版のみ）：duckdb: に proxy=on を付けると、ファイルの取得をローカルサーバーの /api/fetch 経由に切り替えます。CORS 非対応の外部サーバーにあるデータを読めます。/api/fetch は Range/HEAD リクエストを転送するため、Parquet の部分読み（メタデータ・row group スキップ）はプロキシ経由でも有効です。既定は直接接続で、静的配信環境やバックエンド非対応時は指定しても直接接続になります。sql: のクエリ内 URL には適用されません。Range 非対応のサーバーへ全件 GET が必要な形式（CSV/JSON 等）では 20MB 上限があります。

表示範囲連動フィルター：duckdb: と gpkg: は既定で bbox=auto が有効で、カメラ停止ごとに表示範囲で再クエリします（duckdb: は ST_Intersects(geometry, ST_MakeEnvelope(...)) または covering bbox 列への範囲述語、gpkg: は各行の GPkgBinary エンベロープで判定）。sql: はクエリ内に :bbox プレースホルダを書くと同様に範囲連動します（例：WHERE ST_Intersects(geometry, :bbox)。WKB(BLOB)列の場合は ST_GeomFromWKB(geometry) でキャスト）。巨大データを「見ている範囲だけ読む」運用が標準動作です。常時全件描画にしたいレイヤーは bbox=off を付けます（範囲外に出ても地物が消えません）。ST_Intersects の精密判定には spatial 拡張が必要ですが、covering bbox 列があるデータは拡張無しでも近似フィルターとして動作します。

失敗時の自動リトライ：bbox=auto/:bbox レイヤーの初回読み込みが失敗（ペイロード上限・タイムアウト等）した場合、失敗状態を保持したまま次のカメラ移動で縮小した表示範囲による再クエリを自動的に行います。ズームインして条件を満たせばユーザー操作なしでレイヤーが表示されます。geojson: 等が bridge-hub（127.0.0.1:8511）の /vector/ を指して失敗した場合は、ハブの /health・/vector/sources を疎通して原因（ハブ未起動／旧版ハブ・/vector 未搭載／duckdb CLI 未導入／ソース未登録）をエラーメッセージへ付記します。

ベクター描画件数の上限（描画は表示範囲・索引は全件）：表示 → ドレープ の「ベクター描画件数の上限」（既定 20000、0・空欄=無制限）で、entity 描画するベクターレイヤーの合計描画件数を制限します。大量の entity 生成によるブラウザのフリーズを防ぐ安全弁で、上限を超えたレイヤーはレイヤー一覧に 描画数/全件数 のバッジが付きます。上限を超えた全件読み込み系レイヤーは「ファイル先頭から」ではなく表示範囲内の地物を優先して描画し、カメラを動かすたびにメモリ上の全件データから範囲内の地物を選び直します（再ダウンロード無し）。検索結果や属性一覧から未描画の地物へ飛んでも、その場所で描画が復活します。表示範囲外にデータがある間は 0/全件数 のバッジでデータが残っていることが分かります。切り捨ては描画だけの制限で、ベクター検索・プラグイン API の getLayerGeoJson は常にファイル全件を対象にします（属性一覧は描画済み地物から行を作るため、スライス適用中は描画分が表示されます）。render=primitive のバッチ描画は entity コストを支払わないため上限の対象外です。

フィルター UI：レイヤー一覧の ⏷ ボタンと属性テーブルの「SQL」ボタンは同じダイアログを開きます。sql:/ogrsql: はクエリ全文、それ以外は WHERE 式（where=）を入力し、テスト件数の確認・「一覧を絞る」（表示のみ）・「レイヤフィルタ」・「新規レイヤ」（ogrsql: 追加）を選べます。レイヤフィルタの変更は inspector の .kasc テキストへ書き戻され（空入力で削除）、描画と属性一覧に反映されます。

描画方式（既定は entity 描画）：ベクター系レイヤー（geojson:/layer:/geoparquet:/flatgeobuf:/gpkg:/duckdb:/sql:/ogrsql:）は既定で GeoJsonDataSource の entity 描画を使い、地形・3D Tiles へのドレープ（クランプ）に対応します。render=primitive（sql: はクエリ末尾 | render=primitive、その他はオプション欄）を付けると CesiumJS の GeoJsonPrimitive バッチ描画に切り替わります。レイヤー行の render= 指定は表示 → ドレープ の「ベクター高速ドレープ」より優先され、render=entity を書くと高速ドレープが有効でもそのレイヤーだけ entity 描画に戻せます。違いは以下のとおりです。

【entity(既定)】1地物ごとに Cesium Entity を生成
  ・地形/3D Tiles にドレープ可能(clampToGround。ポイント・ラベル・
    クラスタバッジも heightReference で地表クランプ)
  ・フォーカス・属性パネル等の entity 機能がすべて使える
  ・地物数が多いと生成コストが重い

【primitive(render=primitive)】GeoJsonPrimitive バッチ描画
  ・entity を作らずジオメトリだけをまとめて描画するため大量地物でも軽い
  ・地形ドレープ非対応(高さ0の楕円体面に描画。起伏のある地形では地表に埋まる)
  ・属性はクリック時に picked.properties から表示。ベクター検索の索引対象(描画に使った GeoJSON から索引を構築)

検索は常に全件対象：duckdb:/sql: の検索・絞り込みは ⏷／SQL ダイアログのフィルターに一本化しており、常にファイル全件を対象に評価します（読み込み済み地物を対象にするベクター検索パネルには登録されません）。bbox=auto と where= を併用した場合、表示は「検索条件 ∩ 表示範囲」になりますが、検索自体は全件に対して行われ、コンソールに「検索ヒット全 N 件 / 表示範囲内 M 件」と併記されます。

属性値一覧：属性値一覧ウィジェットのレイヤー選択には duckdb:/sql: を含む全ベクターレイヤーが表示されます。選択肢はレイヤー定義から即座に作られるため、データの読み込み完了を待たず起動直後から選択可能です。一覧は読み込み済み地物ではなく DuckDB へ直接クエリして作られ、where= は適用する一方 bbox/limit= は適用せず LIMIT 無しの全件を取得します。ウィジェット内の検索文字は全属性列への ILIKE 述語として SQL に変換されるため、常にファイル全件が検索対象です（表への描画は先頭1000行まで）。

Parquet 最適化：クエリ結果のジオメトリは WKB バイナリで受け取ります（テキスト変換を省き転送量・パース時間・ピークメモリを削減）。columns=列名,列名 で読み込む属性列を絞る列プルーニングが可能です。bbox=auto 時は GeoParquet 1.1 の covering bbox 列（または慣用名の xmin/xmax/ymin/ymax 列、covering= で明示指定も可）への範囲述語を優先的に使うため、Parquet の row group 統計スキップが効き、表示範囲外のデータは読み込み自体を省略できます。

ogrsql:（OGR SQL SELECTレイヤ）

sql: と同じ行規則で、| 以降を OGR SQL（GDAL の SQL 方言）の SELECT 文として実行します。DuckDB ではなく OGR 系フィルター・式評価の再現が目的で、QGIS が出力するクエリ・プロバイダフィルタをそのまま記述できます。

ogrsql: 河川(上位100件) | SELECT * FROM 'rivers' ORDER BY 延長 DESC LIMIT 100
ogrsql: 市区町村JOIN    | SELECT a.*, b.人口 FROM '行政区域' a LEFT JOIN '人口表' b ON a.コード = b.コード
ogrsql: ファイル直接    | SELECT * FROM 'canvas_data/points.geojson' WHERE 区分 = 'A'

FROM の解決順：① 読み込み済みレイヤーのタイトル（他行の geojson: 等を参照可）→ ② 'データソース'.'レイヤー' 形式（GPKG の特定テーブル等）→ ③ プロジェクト相対パス（canvas_data/…）・絶対 URL（GeoJSON/GPKG/FGB/Parquet/KML/SHP zip/CSV 等を自動判別）。

実行エンジン（JS 主経路）：ブラウザ内 JS 実装（shared/ogr-sql.js）で実行します — CDN 単体利用でも QGIS の有無で挙動が変わりません。JS で FROM を解決できない場合（QGIS プロジェクトレイヤー名・ローカルパスの SHP・PostGIS 等）や JS パーサ未対応の構文だけ、ローカル QGIS（geo_webview/geo_driver の Live relay・127.0.0.1:8089-8091）検出時に ogr.ExecuteSQL(dialect="OGRSQL") へフォールバックします。JS 実装はSELECT 式・AS 別名・DISTINCT・集計（COUNT/SUM/AVG/MIN/MAX）・JOIN/LEFT JOIN・WHERE・ORDER BY・LIMIT/OFFSET・OGR 疑似フィールド（FID/OGR_GEOMETRY/OGR_GEOM_WKT/OGR_GEOM_AREA/OGR_STYLE）に対応します。QGIS 側でも解決・実行できなかった場合は JS 側のエラーとして報告されます。

GDAL との方言差：GDAL 本体では ORDER BY に SELECT 別名を使えませんが、JS 実装は受理します（GDAL より寛容）。その他の方言差は QGIS Live 連携をゴールデンオラクルとした差分検証で随時洗い出して JS 実装へ反映しています。

Fly モードの経路設定（fly_geojson:）

fly_geojson: では、GeoJSON の LineString / MultiLineString を読み込み、Fly モードで自動飛行する経路として使えます。複数定義すれば Fly パネルのドロップダウンから選択でき、手動 を選ぶと従来の WASD / マウス操作に戻ります。

fly_geojson: ルートA | https://example.com/route.geojson | speed=60 | height=100 | pitch=-15 | loop=true
fly_geojson: ルートB | https://example.com/routeB.geojson | speed=30 | height=50

URL には外部 URL・プロジェクト相対パスのほか、route:<ルート名> でブラウザ IndexedDB に保存した描画ルートも指定できます（例：fly_geojson: 描いたルート | route:drawn_route_20260918_153000）。IndexedDB はブラウザごとの領域のため、他環境と共有したい場合は GeoJSON を実ファイル化して URL で参照してください。

オプション 意味 デフォルト
speed（s） 地上速度（km/h） 30
height（h） 操作中の高さ補正（m） 0
pitch（p） カメラピッチ（度） -10
step 互換性のため受け付けるが、現在は頂点間を直接移行するため無視 （不使用）
loop（l） 終点で最初に戻してループ false
view（v） ルート座標の基準。camera=カメラ位置（カメラがルート上を飛行）、center=画面中心（ルート点が画面中心に来るよう後方・上空から追従） camera
off 選択肢に表示しない -

fly_geojson: の GeoJSON ルートは LineString / MultiLineString のオリジナル頂点をそのまま使用します。各頂点の z はその点の AGL（地形からの高さ） として解釈します。飛行時の実際の高さは GeoJSON z + 地形高 + flyHeight として計算します。flyHeight は操作中の補正値であり、GeoJSON には含まれません。セグメント内では始点・終点の 3D 位置と地形高を距離に応じて補間します。
