KASUGAI Canvas を構成する主要ライブラリについてまとめる章。基本は CesiumJS + Three.js。3D Tiles・DEM 上への XYZ 重ね合わせなど、地球規模の 3D 表示が必要な箇所は CesiumJS を主軸とする。

地図エンジン（フロントエンジン）の選定と追加候補

web/ はエンジン別フロントを並べるマルチエンジン構成 （?engine= で切替）ですが、開発の基本としてメインエンジンは CesiumJS です。新機能・UI・AI 制御対応はまず Cesium フロント （web/cesium/）を対象とし、他エンジンは .kasc プロジェクトの再生プレイヤーとしての互換実装です。プロジェクトデータは エンジン非依存の projects/ に置き、web/shared/ の .kasc ローダー・ベクターデコーダー・QML コンパイラを全エンジンで 共有するため、新しい 2D エンジンの追加コストは比較的小さくなっています。

追加候補エンジンの優先順位

評価軸: ①ライセンス（OSS か）、 ②メンテナンス状況、③web/shared/ の .kasc 基盤を再利用できるか（移植コスト）、 ④既存 3 エンジンでは埋まらない用途があるか。

優先度 エンジン 特性・採用理由 用途・条件
中 deck.gl（オーバーレイ） 単独エンジンではなく MapLibre/Cesium 上に重ねる大規模データ 可視化レイヤ（ArcLayer・GridLayer・HexagonLayer・TripsLayer 等）。 MapboxOverlay で maplibre フロントに統合可能 数十万点規模の密度・集約・軌跡表現が要件化した場合
中 ol-cesium（olcs）（連携方式） 新エンジンではなく OpenLayers 2D ↔ Cesium 3D のカメラ同期ライブラリ。 openlayers フロントで編集しながら cesium の 3D 確認を同時に行う 2D/3D 連動ビューを実現できる 2D/3D 連動表示が欲しくなった場合（同期モードとして実装）
中 Potree（点群特化） EPT/COPC 形式の大規模点群に特化した three.js 系ビューア。 Cesium の 3D Tiles（pnts）でも代替可能だが、LAS/LAZ の大量点群を そのまま軽快に見せる用途では専用ビューアに分がある kasuga_converter（PDAL 経路）の点群成果物の納品が要件化した場合
中 Maptalks 2D + 2.5D + 3D を1ライブラリで扱うハイブリッド（three.js 統合・ 地形対応）。OpenLayers 的 API で 3D 建物まで描ける。活発に開発中だが 日本語情報・採用実績は少ない OL の手軽さで軽い 3D まで欲しい場合（代替検討枠）
低 iTowns IGN（フランス国土地理院）の three.js ベース 3D エンジン。 グローブ・3D Tiles・点群に対応し Cesium より軽量だが、 エコシステムが小さく役割が Cesium と重複 Cesium が重すぎる環境での軽量 3D が必要になった場合
低 Mapbox GL JS MapLibre の本家。v2 以降はプロプライエタリで、スタイル仕様は MapLibre と互換のため既存 maplibre フロントで事実上代替済み Mapbox 独自サービス（Mapbox タイル・Search 等）を使う場合のみ
低 Google Maps JS API ／ ArcGIS Maps SDK 商用・API キー・課金必須。ベンダーロックインが .kasc の中立性（エンジン非依存のプロジェクト形式）と衝突する 顧客要件で明示指定された場合のみ
低 globe.gl / three-globe 最小構成の three.js 地球儀。デモ・可視化特化で、地図レイヤ体系 （XYZ・ベクター・属性）は自前実装が必要 簡易 3D グローブのデモが必要な場合
低 Mapillary JS / Panoramax ビューア（特殊用途） 街路画像の専用ビューア。地図エンジンではなく連携ウィジェットとして 既存フロントに組み込む性質のもの kasugai_box の画像連携など、地点写真ビューアの構想が具体化した場合

参考（不採用）: Tangram（Mapzen の WebGL ベクタータイルレンダラ）と harp.gl（HERE）は いずれも開発が停止しており、新規採用の対象外です。

CesiumJS + Three.js の連携パターン

現行実装：オーバーレイ canvas + カメラ同期

  • #cesium-container 内に Three.js 用の <canvas>（three-canvas、pointer-events:none）を重ねる
  • scene.postRender で viewer.camera.viewMatrix / frustum.projectionMatrix を Three.js カメラへコピーして同期。ECEF（Cartesian3）座標を Three.js のワールド座標としてそのまま共有できる
  • 実装が容易で、各エンジンの描画サイクルを独立に保てる
  • 深度バッファを共有しないため、地球・3D Tiles との遮蔽関係やピッキングの統合はできない（Three.js 側は常に全面に描画される）

将来候補：同一 WebGL コンテキストでの統合

  • CesiumJS の GL コンテキスト上で Three.js を描画し、深度バッファを共有する方式（遮蔽関係を正しく合成可能）
  • CesiumJS の内部 GL 状態管理に依存しバージョンアップで壊れやすいため、現行はオーバーレイ方式を採用している
  • 単独オブジェクトなら Three.js を介さず CesiumJS の Model / Primitive + CustomShader で済ませる方が安定
