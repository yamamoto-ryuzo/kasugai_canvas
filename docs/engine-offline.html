KASUGAI Canvas v7.1.0

閉鎖環境での利用 — 描画ライブラリ本体もダウンロードして CDN ゼロの完全自前配信にする

1. 概要 — ライブラリも web/ に同梱する

通常の自前配信（2-1）でも、描画ライブラリ本体は CDN（jsdelivr / unpkg）から読み込んでいます。 外部ネットワークに出られない閉鎖環境（イントラ・オフライン）で使うには、 ライブラリ本体をダウンロードして web/ 内に同梱し、参照をローカルファイルへ差し替えます。 対象の全一覧は 2-1 の依存関係表 を参照してください（使わない機能の遅延ロード分は不要です）。

配置先は 2-1 のフォルダ構成に合わせ、web/engine/ を新設して ライブラリ実体を1箇所にまとめます。web/<エンジン>/ は「KASUGAI 側のエンジン別フロント（.kasc を各 API へ写像する薄い層）」で、 本当のエンジン本体＝地図描画ライブラリ（Cesium.js・maplibre-gl・ol・leaflet）はここに置く、という住み分けです。 

web/                  ← 配信ルート（2-1 のフォルダ構成と同じ階層）
├─ index.html
├─ cesium/ maplibre/ openlayers/ leaflet/   ← エンジン別フロント（.kasc → エンジンAPI 写像の薄い層。参照を書き換える側）
├─ shared/ projects/ …
└─ engine/            ← ここを新設して「地図描画エンジン本体」（ライブラリ実体）を置く
   ├─ cesium/         ← Build/Cesium/ の中身（Cesium.js・Workers/・Assets/・Widgets/・ThirdParty/）
   ├─ three/          ← three.module.js
   ├─ maplibre/       ← maplibre-gl.mjs・maplibre-gl.css
   ├─ ol/             ← ol モジュール一式 ＋ rbush・earcut・pbf・geotiff・zarrita
   ├─ leaflet/        ← leaflet.js・leaflet.css・images/
   └─ …               ← 遅延ロード分も同じく engine/<ライブラリ名>/（duckdb-wasm・hyparquet・flatgeobuf・deck.gl 等）
  • なぜ vendor/ という名前を避けるか: vendor は gsimaps/navara 用の既存機構 （web/vendor/・vendor.json・vendor-proxy-sw.js）で使われる語です。 web 直下の web/vendor/ は Service Worker の中継対象で実体を置いても横取りされるため使えず、 各所に vendor/ を増やすと「どの vendor か」が紛らわしくなります。web/engine/ は中継対象外かつ一意です
  • 遅延ロード分も同じ場所: shared/ や app.js が遅延ロードするライブラリも engine/<ライブラリ名>/ に置き、 参照元ファイル（shared/vector-load.js 等）の import URL を書き換えます
  • 取得した実体を置くだけでは読まれません — 各エンジンの index.html/app.js と shared/ 内の CDN 参照をこのパスへ書き換えて初めてローカルが使われます

2. Cesium 本体のローカル化（手順例）

バージョンは cesium/index.html のピンに合わせてください。他エンジンも同じ考え方です。

  1. Cesium の取得 — cesium@1.147.0 の Build/Cesium/ 一式を取得します （npm パッケージ cesium、GitHub Release、jsdelivr いずれでも同じ内容です）。 Cesium.js 単体では動きません — Workers/・Assets/・Widgets/・ThirdParty/ を含むディレクトリ丸ごとが必要です
  2. 配置 — web/engine/cesium/ に Build/Cesium の中身を置きます （engine/cesium/Cesium.js・engine/cesium/Workers/… という形になるように）
  3. cesium/index.html の書き換え — CDN 参照をローカルへ差し替えます: 
    <script>window.CESIUM_BASE_URL = "../engine/cesium/";</script>
<link rel="stylesheet" href="../engine/cesium/Widgets/widgets.css" />
<script src="../engine/cesium/Cesium.js"></script>
    CESIUM_BASE_URL は Cesium.js が Worker・画像・言語ファイルを解決する基点です （script タグの src から自動検出もされますが、明示する方が確実です）。 importmap の three も同様に、three@0.187.0/build/three.module.js を engine/three/ に置いて "three": "../engine/three/three.module.js" に差し替えます
  4. 外部サービス依存の遮断 — 閉鎖環境では Cesium ion（既定トークンの地図・Cesium World Terrain）にも届きません。 .kasc の base:/xyz: は自前・ローカルのタイルを参照し、 地形（DEM）もローカル配信の TerrainProvider・標高タイルに差し替えます
  5. 遅延ロード系も同様 — duckdb:・geoparquet: 等を使う場合は 依存関係表の遅延ロード分も同じ手順でローカル化します（使わない形式は不要です）

3. 他エンジンも同じ手順

エンジンダウンロードするもの差し替え箇所
maplibremaplibre-gl@6.19.0 の dist/maplibre-gl.mjs + maplibre-gl.css → engine/maplibre/index.html の css と app.js 先頭の import
openlayersol@10.11.0 のモジュール一式 ＋ rbush/earcut/pbf/geotiff/zarrita → engine/ol/ 等index.html の importmap と app.js 先頭の import 群
leafletleaflet@1.9.4 の dist/leaflet.js + leaflet.css（+ images）→ engine/leaflet/index.html の script/link
  • 遅延ロード（deck.gl・pmtiles・jszip・leaflet.markercluster/heat/vectorgrid・heatmap.js 等）は使う機能の分だけで足ります
  • OpenLayers は多数の個別モジュールを import しているため、パッケージ全体を engine/ol/ として配置し、importmap で "ol/": "../engine/ol/" のようなプレフィックスマッピングにすると一括で済みます

4. ライブラリ以外の外部依存も洗い出す

ライブラリをローカル化しても、次の外部参照が残ると閉鎖環境では動きません。.kasc と設定を確認してください。

  • タイル・地形データ — base:/xyz:/wms:/wmts:/3dtiles: の参照先（地理院タイル・Google・OSM 等）。自前のタイルサーバーまたはローカルタイルツリー（xyz: ローカルテンプレート）へ差し替え
  • DEM — 表示タブの地形ソース（地理院標高 PNG・Re:Earth Terrain 等）も外部 URL。ローカル配信の標高タイルに差し替え
  • 検索・ジオコーディング API — 地理院 msearch・Yahoo ジオコーダ等は外部サービス（不要なら hide: ["search"] でタブごと隠せます）
  • AI チャット — 内蔵 AI・ブリッジハブ経路は外部 API・ローカルプロセス依存。閉鎖環境では hide: ["chat"] で非表示が無難です
  • ベクターデータ本体 — geojson:/gpkg: 等の URL 参照も当然ローカルへ（canvas_data/ 同梱なら相対参照のまま動きます）

5. 注意点

  • file:// 直開きは不可 — HTTP サーバーは必須。 ライブラリを全てローカル化しても、以下がブラウザにブロックされるため index.html のダブルクリック起動は動きません:
    • <script type="module">・dynamic import — file:// は同一オリジンを持たず CORS で拒否
    • fetch() での .kasc・canvas_data/・タイル読み込み — file:// の fetch は失敗
    • Service Worker・Web Worker（Cesium Workers 等）— file:// では登録・生成不可
    「サーバーなし」に近づける現実的な代替は:
    • localhost の最小静的サーバ（python -m http.server 等）— 閉鎖環境でも外部通信なしで動き、これが最小構成です
    • Tauri / WebView2 への内蔵 — カスタムスキーム（仮想ホスト）に web/ をマッピングすれば、見かけ上サーバー無しのアプリとして起動できます（KASUGAI フレーム側の構想と同じ方向）
  • Service Worker — sw-duckdb.js（DuckDB-WASM キャッシュ）は https または localhost でのみ動きます。http のイントラ IP 直叩きでも基本機能は動き、キャッシュ効果が無いだけです。4エンジンでは vendor-proxy-sw.js は不要です（gsimaps/navara 専用）
  • バージョン固定 — 同梱ライブラリは index.html・app.js のピン済みバージョンに厳密に合わせてください（違う版を置くと API 差異で壊れます）
  • ライセンス — 各ライブラリの再配布条件（著作権表示等）は個別のライセンスに従ってください
