## 3. 2D/3D データの最適フォーマット

### 2Dベクトルデータの最適フォーマット

#### 比較

| フォーマット | 評価 | 強み | 弱み |
|-------------|------|------|------|
| **FlatBuffers (GeoArrow)** | 🏆 最推奨 | ゼロコピーで GPU バッファへ直結。数十万〜数百万のベクター可視化 | – |
| **MVT (Mapbox Vector Tile)** | 🥈 | GIS/Web 標準。圧縮・サイズ削減に強い | デコードに CPU を使う |
| **GLB** | ❌ 2Dには不向き | 3Dメッシュ向け | 属性・トポロジが弱い |

#### GPKG（GeoPackage）の扱い

- **管理・連携**には GPKG が優秀（Single Source of Truth）
- **ブラウザ直接描画**には向かない（SQLite + WKB パースのオーバーヘッド）
- 現場のベストプラクティス：**GPKG を正データとして保持し、描画時に Web Worker で FlatBuffers / MVT に変換**

### 3D Tiles と GLB/glTF

- **GLB/glTF**：3Dモデルの「3D版JPEG/PNG」、単体モデル表示に最適
- **3D Tiles**：広域データをタイル化・LOD 制御してストリーミングする規格
  - 1.1 から内部ペイロードとして **GLB/glTF 2.0** を直接利用可能
- **使い分け**
  - 単体オブジェクト → **GLB**
  - 広域・大容量データ → **3D Tiles**
