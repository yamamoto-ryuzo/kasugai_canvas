ユーザーパネル — プラグインでパネルタブへ独自のパネル・レイヤ表示を追加

1. 概要 — プラグインがパネルタブへ独自 UI を追加できる

プラグインは api.registerPanel(spec) でパネルタブへ独自のユーザーパネルを追加できます。 機構は web/shared/plugin-panels.js（エンジン非依存）が担い、 Cesium（.panel-tab/section.plugin-panel 規約）と 2D プレイヤー各エンジン — maplibre / openlayers / leaflet / navara （.tab[data-tab]/.tab-pane 規約）の両方で同じ API 面を提供します。

  • プラグインが停止・登録解除されるとパネルは自動で撤去されます（owner = pluginId で追跡）
  • 生成されたタブは data-panel/data-tab 属性を持つため、AI の汎用ブリッジ（listUiControls/controlUi）からそのまま操作できます
  • 標準のレイヤタブは変更せず、別タブとして追加されます。レイヤの自由な表示（型別グループ・独自順・絞り込み・行装飾）は 3. カスタムレイヤビュー を参照してください

2. 使い方 — api.registerPanel(spec)

// プラグインの init(api, manifest) 内
const view = { unbind: null };
api.registerPanel({
  id: "layers2",            // プラグイン内で一意
  title: "レイヤ2",
  icon: "🗂",               // 省略可
  after: "layers-panel",    // 挿入位置（省略可・タブキー名）
  onInit(panel) {           // DOM 構築
    view.unbind = api.bindLayerView(panel, {
      groupBy: l => l.type,            // グルーピング（既定: l.group）
      sort: ls => [...ls].sort(...),   // 並べ替え
      filter: l => true,               // 表示行の絞り込み
      decorateRow: (row, l) => {},     // 行へのバッジ/ボタン追加
      decorateGroup: (head, key, ls) => {},
    });
  },
  onShow(panel) {},
  onHide(panel) {},
});
// 関連 API: unregisterPanel(id) / selectPanel(id) / listPanels()
  • onInit(panel) は登録時に1回、onShow/onHide はタブ表示状態の変化ごとに呼ばれます（組み込みタブへの切替でも正しく発火します）
  • plugin-loader / ストレージプラグインのローダーが pluginId をスタンプした scoped api を渡すため、spec.owner を書く必要はありません

3. カスタムレイヤビュー — bindLayerView / renderLayerView

api.bindLayerView(container, opts) / api.renderLayerView(container, opts) （web/shared/layer-view.js）はレイヤ一覧の最小描画＋layers-changed イベントでの自動追従を提供します。チェックボックスは setLayerVisible に連動するため、 別タブで「型別にまとめたレイヤ一覧」「担当者向けの絞り込み一覧」などがそのまま作れます。

  • bindLayerView は layers-changed を購読して自動再描画し、{ unbind } を返します（パネル撤去時に解除）
  • 完全に独自の表示は api.listLayers()・api.setLayerVisible()・api.focusLayer()・api.setLayerLegendVisible() と api.on("layers-changed", cb) を直接使って構築します
  • listLayers() の各エントリは options（.kasc 行の key=value をそのまま保持するマップ）を持ちます。site= などの独自キーをレイヤ行へ付けてプラグイン側で集約・制御する用途に使えます
  • api.setLayerOrder(keys) — 表示順の制御。keys（id または title・先頭=最前面）に挙げたレイヤ同士の相対順を keys 順に並べ替えます。未指定のレイヤは現在の位置を維持する（＝指定レイヤが占めていたスロットを指定順で埋める）ため、レイヤ群だけをまとめて並べ替えられます。全エンジン対応（実描画反映はエンジン別に map.moveLayer / zIndex＋再挿入 / bringToFront / 再マウントで実現）
  • 参考実装: PLUGIN/sample-layer-panel/plugin.js（レイヤを型別にまとめた別タブ表示）、PLUGIN/custom-layer/plugin.js（次項）

カスタムレイヤ（site= 集約サンプル）

PLUGIN/custom-layer は「ポイント・ライン・ポリゴンなど型の違うレイヤを任意グループにまとめて1トグルで制御する」カスタムレイヤパネルです。レイヤ行に site=<グループ名> を付けるだけで、その名前1行に集約されます。

geojson: A工区・ポリゴン | canvas_data/a-poly.geojson | site=A工区 | order=1
geojson: A工区・ライン   | canvas_data/a-line.geojson | site=A工区 | order=2
geojson: A工区・ポイント | canvas_data/a-pt.geojson   | site=A工区 | order=3
geojson: 背景ライン    | canvas_data/free.geojson    （site なし → 標準タブにも「その他」にも出る）
plugin: custom-layer | name=レイヤ | url=canvas_data/custom-layer.js | before=layers-panel
  • 箇所ごとの1トグルで全メンバーをまとめて on/off（setLayerVisible をメンバー全件に適用）、部分表示は中間状態表示
  • メンバーが分類凡例（QML style=）を持つ場合、箇所行の下に凡例項目（チェック＋スウォッチ＋ラベル）を表示し、シンボル単位の on/off（setLayerLegendVisible）ができます。凡例の並び順は legend_order=asc|desc|reverse またはカンマ区切りのラベル列挙（legend_order=区分A,区分C,区分B。未列挙は末尾・元順維持）で変更でき、未指定時は .qml のシンボル順です。listLayers() の legend[].spec を api.legendSwatchUrl() でスウォッチ画像に変換します
  • メンバー内の順序は order=<数値>（書式: レイヤ行の key=value・例 order=1）で制御します。小さいほど上で、省略時は現在の並び順の末尾扱いです。これはプラグインが listLayers() の options.order を読んで並べ替える独自キーであり、エンジン本体の描画順（.kasc 行順・setLayerOrder）とは別物です — 「この集約タブでの表示順のヒント」として使います
  • site= はこのタブ専用の集約キーで、標準レイヤタブには全レイヤが従来通り表示されます（全体を見る標準タブ＋簡素化した集約タブの併用）。レイヤ一覧（標準・カスタムとも）から隠したいレイヤは list=off を付けます（地図には描画される）。site= と別の集約キー名を使う場合は manifest.options.key（plugin: sc | ... | key=site）で変更できます
  • site= を付けないレイヤはタブ末尾の「その他」に集約され、一括 on/off ができます（順序操作は出さず .kasc 順のまま）
  • プラグインタブの表示名（name=）が組み込みタブと重複する場合、組み込み側のタブ名が自動的に「システムレイヤ」等に改称されます（name=レイヤ → 組み込みは「ｼｽﾃﾑﾚｲﾔ」表示。重複解消で自動復元・i18n 対応）。また重複が発生したプラグインタブは組み込みの代替とみなされ、初期表示タブとして自動選択されます
  • 同じプラグインが「フィルタ」タブも登録します — QGIS WEBVIEW の Filter タブと同じ構成で、site 単位の共通属性フィルタを全メンバーレイヤへ where= 式として一括適用します。数値フィールドは演算子（= != < <= > >=）＋数値入力、その他は = / != ＋既存値入力、「複数選択」で IN/NOT IN＋既存値チェックリスト（数値も可）に切り替わります。適用経路はレイヤ行の ⏷ フィルタと同じ setLayerFilter（クエリ系は SQL 再クエリ、geojson: 等はクライアント評価）で、値の列挙は適用中フィルタを一時解除して全件から集めます

4. プラグインの起動 — plugin: 行

plugin: プラグインID | name=表示名 | url=JSファイル | after=タブキー | before=タブキー | key=value | off
plugin: my-panel | name=レイヤ2 | url=canvas_data/my-panel.js | after=info-panel
  • plugin: は plugins.json カタログまたは管理タブのストレージプラグインの ID を指定し、そのプロジェクトでのみプラグインを起動します。key=value はプラグインの manifest.options にマージされ、真偽値・数値・カンマ区切り（配列）を解釈します
  • ID は起動・照合のキー（後勝ち・| off 照合・パネル/レイヤ撤去の所有単位）で、表示名ではありません。表示名は name= で分離し manifest.name へ渡されます — プラグイン側が title: manifest.name のように使えば .kasc からタブ名を制御できます（ID 指定・url= どちらでも有効）
  • plugin: 行を複数書くと宣言順に逐次起動し、各プラグインのパネルタブは組み込みタブの右から順に追加されます。after=<タブキー> を書くとプラグインが登録するパネルの既定挿入位置がそのタブの直後、before=<タブキー> なら直前になります — プラグイン側の registerPanel({ after }) 指定があればそちらが優先されます。タブキーは組み込みタブの data-panel/data-tab 値（Cesium: layers-panel/info-panel 等、プレイヤー: layers/info 等）です
  • url=<JSファイル> はプラグインコードの設置場所を .kasc 内で直接指定する記法です。canvas_data/my-panel.js のような相対パスは .kasc のあるフォルダ基準で解決されるため、.kasc＋canvas_data/＋プラグインJS をまとめて配布すれば、CDN 配信でもユーザー側でプラグインを設置できます（IndexedDB への取込・ローカルサーバーへの公開は不要）。manifest.url に解決後の絶対 URL が渡されます
  • url= で同一オリジン（配備物に同梱したJS）は無確認で読み込みますが、クロスオリジン（?kasc= で共有された .kasc が指す外部ホストのJS 等）は任意コード実行防止のため、コード全文を表示する確認ダイアログを出します。承認は同一コードに限りそのセッション内で記憶されます
  • 起動したプラグインのレイヤーはプロジェクトスコープになり、プロジェクト切替・行削除・| off でレイヤー除去＋停止（dispose）されます
  • plugin: 行は全エンジンで読めます。Cesium は plugin-loader.js、maplibre / openlayers / leaflet / navara は web/shared/plugin-storage.js の setInspectorPlugins が差分ロード/停止を担います。プレイヤー系は同梱カタログ（plugins.json）を持たないため、ID 指定は IndexedDB のストレージプラグインを解決します（url= は全エンジンで同一の動作）

5. プラグインの設置方法 — url=（.kasc 埋め込み）を標準とする

ユーザー側へのプラグイン設置・配布は plugin: id | url=<JS> の .kasc 埋め込みを標準経路とします。プラグインJS を canvas_data/ などプロジェクトと同じ場所に置き、.kasc に1行書くだけで、CDN 配信・ローカルサーバー・全エンジンで同一に動作します。

project/
  my.kasc                     ← plugin: my-panel | url=canvas_data/my-panel.js
  canvas_data/
    my-panel.js               ← プラグイン本体
    ...（プロジェクトデータ）
  • プラグインの有効範囲はその .kasc のみ。別プロジェクトでも使う場合はその .kasc にも plugin: 行を書きます
  • 配布は .kasc と canvas_data/ をまとめてコピーするだけ。?kasc=<外部ホストの.kasc> で読ませる構成でも動きます（その場合のJSはクロスオリジン確認の対象）

※ IndexedDB ストレージ・サーバー PLUGIN/ は内部機構です（7-2 プラグイン・外部連携 参照）。
