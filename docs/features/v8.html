QGIS 双方向オーサリング

V7 が「QGIS プロジェクトを、そのまま Canvas で再現する」一方向のテーマなら、V8 はその往復 — Canvas 側の操作・成果物を QGIS プロジェクトへ書き戻すテーマです。QGIS がデータ・スタイル・編集の正本、Canvas が最終 2D/3D 表示エンジンという役割分担は V7 と同じで、そこに「Canvas → QGIS」の復路を追加します。

📏 役割分担の原則

  • スタイル（.qml）は QGIS で作る — Canvas 側は style= の参照・適用のみ。Canvas でのスタイル編集 → .qml 書き戻しは対象外とします
  • データ本体の編集・正本管理は基本的に QGIS — Canvas からの地物投入はスクラッチレイヤ経由とし、正式レイヤへの昇格・保存・主データへの追記は QGIS 側の操作で行います（Canvas 上での地物編集を QGIS レイヤへ直接書き込む API や、Canvas 発の新規レイヤ正式追加は設けません）
  • Canvas → QGIS の受け渡しは URL ベース — 複雑な部分書き込み・トランザクション機構は持たず、GeoJSON / .kasc の URL を QGIS が ogr / vsicurl / delimitedtext で読む形に統一します

🔄 双方向の流れ

QGIS プロジェクト ── geo_webview（.kasc 出力 / GET /live/kasc）──→ Canvas で再現・配信
        ▲                                                                  │
        └── kascImport（.kasc URL → QGIS 復元）・/live/writeback（表示/      │
            フィルタ/テーマ）・/live/features（作図→スクラッチ）・            │
            /live/camera・/live/selection（逆通知）────────────────────────┘

✅ 実装済みの基盤（geo_webview + Canvas）

機能経路内容
.kasc → QGIS 復元bridge kascInspect / kascImport（4.14.0〜）.kasc+canvas_data/（パスまたは http(s) URL）を QGIS プロジェクトへ逆取り込み。全行タイプをレイヤ化し、style=（.qml）・縮尺・不透明度・where=→subsetString・グループ構造・theme:→マップテーマ・bookmark:・cam:・| off を復元。replace で冪等再取込。kascInspect は dry run
表示/フィルタ/テーマ書き戻しPOST /live/writeback（4.11.0〜）Canvas 側の表示トグル・⏷フィルタ・テーマ適用を QGIS プロジェクトのレイヤチェック・subsetString・マップテーマへ反映
作図・地物の投入POST /live/features（4.11.0〜）Canvas の作図スケッチ・選択レイヤの GeoJSON を QGIS スクラッチ（memory）レイヤとして投入（昇格・保存は QGIS 側）
カメラ・選択の逆通知POST /live/camera・POST /live/selection（4.9.0〜）Canvas の視点 → QGIS キャンバス中心/縮尺/回転、Canvas の地物ピック → QGIS レイヤ選択
Canvas 操縦の QGIS 集約live.controls・POST /live/controls（4.33.0〜）追従・選択表示の正を QSettings で一元管理し GET /live/state で全ライブビューアへ配信。live.add_layers キューで QGIS 側からのレイヤ追加要求も実現

bridge API（kascImport・liveControls・liveSetControls・liveAddToCanvas 等）により、これらの往復操作は AI エージェントからも駆動できます。

🔎 構想（本格化対象）

  • Canvas 編集結果の URL 提供 → QGIS が読む往路導線 — Canvas 側で編集した地物を GeoJSON URL（ローカルアプリ :8510 の API または /live/* 経由）として提供し、QGIS がレイヤとして読み込む入口（「Canvas から取り込み」導線）を整備する。kascImport は既に URL 対応済みのため、単一 GeoJSON URL を読む薄い入口で実現できる

なお以下は方針上の対象外です：地物編集の QGIS レイヤ直接書き込み API（URL 経路で代替）、Canvas 発の新規レイヤ正式追加（QGIS 側で昇格・保存）、Canvas でのスタイル編集 → .qml 書き戻し（.qml は QGIS で作る）。
