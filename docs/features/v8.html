V8: ポータル

V7 が「QGIS プロジェクトをそのまま Canvas で再現する」テーマなら、V8 はその先の「作業者がレイヤー管理を意識せず、目的別の大きなボタンで GIS 業務を完結させる」テーマです。道路工事の「近接工事・未発注・工事中」のように、必要なレイヤー・スタイル・フィルタ・カメラ・背景をあらかじめ .kasc に束ねておき、作業者はポータルのカードを押すだけで目的の画面状態に到達します。全6エンジン（Cesium / MapLibre / OpenLayers / Leaflet / GSI Maps / Navara）で同一の UI・同一の .kasc 宣言が動きます。

🧭 コンセプト

従来: レイヤーパネルで表示ON/OFF → スタイル差替 → ⏷フィルタ → カメラ移動 → 背景切替 を手作業で繰り返す
V8 : .kasc に view: で目的別プリセットを1行宣言 → ポータルの大きなカードを押すだけで全部まとめて適用
     「ビュー解除」で適用前の状態へ完全復元（表示・フィルタ・スタイル・カメラ・ベースマップ）

📝 .kasc 行形式（4行タイプ）

行タイプ書式役割
portal: portal:on|off | title=見出し | open=auto|manual | html=ファイル/URL ポータル画面の宣言。open=auto で起動時に全画面表示、manual は 🏠 ボタンから手動、off で無効化。html= でボディ全体をカスタムHTML化
view: view:名 | desc=説明 | img=画像 | cam=プリセット名 | base=背景名 | レイヤ[;style=QML][;where=条件] | * 目的別プリセット（theme: の発展形）。可視性＋スタイル＋フィルタ＋カメラ＋背景を束ね、カード押下で一括適用
link: link:名 | url=https://… | desc=説明 | img=画像 外部サイト・外部データへのリンクカード（↗ バッジ・新規タブ）。view: カードと宣言順で混在。http(s)/mailto のみ許可
html: html:タイトル | インラインHTML または ファイル/URL ポータル内のHTMLセクション（お知らせ・説明文等）。info: と同じサニタイズ経路。宣言順に表示

🖱️ UI

要素動作
🏠 ボタンレイヤータブバー先頭に常駐（アイコンのみ・枠いっぱい）。ポータルをいつでも再表示。宣言なしプロジェクトでも表示され、既定のお知らせ/ビュー/機能説明ガイドが開く。適用中ビューはハイライト＋ツールチップでビュー名表示

既定コンテンツportal:/view:/html:/link: が1行も無い場合は、タイトル（title: 行→プロジェクト名→ポータル）＋お知らせ/ビュー/機能説明のガイドを表示

⚙️ カスタムHTMLからの GIS 制御（data-* 属性）

portal:…|html= のフルカスタムHTMLや html: セクション内では、以下の属性を付けた要素（ボタン・リンク等）が GIS 側を宣言的に操作します。<script>・<iframe>・on* 属性はサニタイズで除去されるため、操作はこの宣言属性に限定されます。

属性動作ポータル
data-view="ビュー名"view: 定義を適用閉じる
data-link="URL"外部URLを新規タブで開く開いたまま
data-cam="カメラ名"カメラプリセットへ移動開いたまま
data-base="背景名"背景地図を切替開いたまま
data-clearビュー解除（適用前へ復元）開いたまま

🧩 フルカスタムHTML（portal:…|html=）詳細

portal: 行に html= を付けると、ポータルのボディ部分全体を1つのHTMLファイル（またはURL・インラインHTML）で構成できます。自動生成される「お知らせ」「ビュー」「ポータル機能について」のセクションとビュー/リンクカードは一切表示されず、見た目は完全に作成者のHTML次第になります。ポータルの骨格（見出しの title=・「地図を開く」ボタン・左上の 🏠 ボタン・「ビュー解除」フッタ）は共通のまま残ります。

portal:on | title=フルHTMLポータル | open=auto | html=DATA/portal.html

設計上の役割分担

どこに書くか内容
.kasc の view:/link: 行GIS側の操作定義（レイヤ・スタイル・フィルタ・カメラ・背景の束ね。フルカスタムモードではカードとして自動表示されないが、data-view から名前で参照される定義として必須）
html= の HTML ファイル見た目と導線（レイアウト・画像・説明文・ボタン配置・装飾。操作は data-* 属性で .kasc 側の定義を呼び出す）

書けるもの・書けないもの（サニタイズ仕様）

埋め込みは info: と同じ embedKascInfoHtml 経路（DOMParser→除去→挿入）を通ります。

仕様
✅ 任意のHTML構造div/section/h1〜h6/p/table/ul/img/button 等。ネストや配置は自由
✅ インライン style="…" 属性見た目の調整はこれだけ。<style> タグと <link> スタイルシートは要素ごと除去されるため、装飾は各要素の style= で記述します
✅ class 属性属性自体は残りますが、外部CSSを読み込めないため実質「アプリが定義するクラス」でのみ有効。.tab-button+.tab-content の組を置くとポータル内サブタブとして自動配線されます（info: と同じ規則）
✅ 画像 <img src>src/href/poster/background の相対参照はHTMLファイル自身のURLを基準に解決されます（.kasc 基準ではない）。DATA/portal.html と同じ DATA/ 内の画像なら src="x.png" で参照可
✅ <a href>target 未指定のリンクには自動で target="_blank" rel="noopener noreferrer" が付き、アプリ自体は遷移しません。http(s)/mailto/相対パス/#アンカーが有効
✅ data-* 属性そのまま残り、委譲クリックが拾って GIS 操作を実行（前節の表）
❌ <script>・<iframe>・<object>・<embed>・<form>・<link>・<style>要素ごと除去されます（コード実行・外部リソース読込・フォーム送信を防ぐため）。動的な振る舞いは data-* 属性に限定されます
❌ on* 属性・javascript: URL属性ごと除去されます

data-* でできることの補足

  • data-view は .kasc の view: 行の名前で照合します。フルカスタムでもビュー定義自体は .kasc 側に必要です
  • data-cam/data-base/data-clear はポータルを閉じずに地図だけ動かします。「対象区域へ移動」→地図を見て→次のボタン、という連続操作が組めます
  • data-view/data-close はポータルを閉じます（ビュー適用で地図に戻る導線）
  • data-link は URL を直接書くため link: 行不要。安全なスキーム（http/https/mailto）のみ許可されます

🔍 where= の全ベクター行対応

view: のレイヤ指定に付ける ;where= だけでなく、ベクター行のオプションとしても全形式で where=条件 が使えます。duckdb:/sql:/gpkg: 等のクエリ系は従来通り SQL で評価し、geojson:/geoparquet:/flatgeobuf:/kml:/shp: 等の全件読み込み系は shared/where-eval.js の SQL WHERE サブセット評価器（= != <> < <= > >=・AND/OR/NOT・括弧・IN・BETWEEN・LIKE/ILIKE・IS NULL・"識別子"/'文字列'/日本語裸属性名）でクライアント側評価します。絞り込まれるのは描画のみで、属性一覧・ベクター検索は引き続き全件対象です。

⚠️ 制限・今後の課題

  • sql: レイヤへの ;where= は行構造上サポート外（警告のみ）。個別フィルタは各行の where= を使用
  • 属性一覧・ベクター検索は全件対象（where= は描画のみに適用。クエリ系と同じ方針）
  • 今後の課題: 「現在の表示をビューとして保存」＋スクリーンショット自動サムネイル、geo_webview 側の view:/portal: エクスポート・エディタ、リッチな GIS コントロールの追加

検証資産は web/verify/（feature-verify で15機能・全エンジン PASS を記録）。テストプロジェクトは web/projects/_portal_test/。
