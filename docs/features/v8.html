V8: 解析（予定）

V7 が「QGIS プロジェクトの表示を再現する」テーマなら、V8 はその延長の「解析を Canvas から駆動する」テーマです。方針は、解析エンジンは自前で実装せず QGIS Processing をバックエンドとして借りること。Canvas 側は AI チャットによる解析の操縦面と、結果レイヤーの 2D/3D 表示を担います。

本ページは計画段階のテーマページです。「QGIS に接続」経路（MCP リレー）は実装済みで、その上で processing.run() を呼ぶ解析も技術的には今日動きますが、定型化した解析機能としての整備はこれからです。headless QGIS を使うサーバサイド化は構想段階です。

🧭 役割分担

QGIS   = 解析エンジンの正本（Processing アルゴリズム数百種 + データ正本・編集）
Canvas = AI チャットによる解析の駆動 + 結果の 2D/3D 表示
  「このレイヤに500mバッファを掛けて」「AとBの交差を集計して」→ AI が解析を組み立てて実行

🔗 解析の3経路

経路 実行場所 状態 適する解析
QGIS Live Driver（MCP） 起動中の QGIS GUI プロセス 接続基盤 実装済
解析運用は計画		 プロジェクトのレイヤーへの ad-hoc 解析（AI 副操縦）
qgis_process サイドカー headless QGIS（ローカル or サーバ） 構想 無人・繰り返し・重い解析、複数クライアント共有
ブラウザ内解析 ブラウザ（WASM / JS） 一部実装済 軽い集計・空間選択・計測など即時フィードバック系

🟢 経路1: 起動中 QGIS への AI 副操縦

管理 → AI → データソース の「QGIS に接続」は、ローカルアプリの /api/qgis-live/mcp リレー経由で QGIS Live Driver の /mcp へ接続し、qgis_pyeval・qgis_bridge_call・qgis_screenshot 等がチャットツールへ合成されます（セッション検出は /api/qgis-live/discover が ~/.qgis-live/ レジストリを走査し、ポート・トークンは QGIS 再起動ごとに自動追随）。pyeval は QGIS 内の任意 Python を実行するため、AI が processing.run("native:buffer", {...}) を呼べば解析は追加実装なしで動きます。

  • 強み: 初期化済みのフルランタイム。native / gdal / スクリプトの全アルゴリズムが使え、開いているプロジェクトのレイヤーを名前で直接参照できる。アルゴリズムとパラメータは processingRegistry() 経由で AI が自己発見し、結果は kasugaiExport（bridge）で Canvas へ持ち出せる
  • 制約: pyeval は GUI スレッドの同期実行（長時間解析で QGIS UI がブロック）・実行は直列・QGIS が起動している間だけ有効・pyeval は「書き込み系ツール」ゲート＋実行ごとの確認対象・大きな結果は JSON では返せないためファイル出力＋ kasugaiExport で受け渡す設計が必要

🟡 経路2: qgis_process 解析サイドカー（構想）

QGIS 同梱の公式 headless CLI qgis_process（qgis_process run native:buffer --INPUT=… --OUTPUT=…・--json パラメータ対応）を、kasuga_converter と同型の Axum サイドカーとしてラップする構想です。QGIS 本体をサーバ・端末へインストールして headless 実行するため、無人解析・繰り返し実行・複数クライアントからの共有が可能になります。QGIS の Processing .py ファイルをサーバに配置するだけでは動きません — native 系アルゴリズムの大半は C++ 実装で、Python 系も PyQGIS ランタイム（Qt + GDAL/PROJ/GEOS + QgsApplication 初期化）が必須のため、QGIS インストールごと必要です。起動コストを避けたい場合は常駐 PyQGIS サービス（QgsApplication([], False) + initQgis() を1回で HTTP 化）や、pygeoapi（OGC API - Processes）経由の公開も選択肢です。

🔵 経路3: ブラウザ内解析（一部実装済）

QGIS を介さない軽量解析は既存ツールで部分的に提供済みです — 計測系（measureDistance / measureArea / measureBearing / elevationProfile / lineOfSight）、spatialSelect・aggregateWithin・createBuffer、duckdb: / sql: レイヤーの DuckDB-WASM 空間述語、runCode サンドボックスによる任意 JS 解析。V8 ではこれらを「QGIS に依存しない第1段の解析」として位置づけ、重い処理・正確性重視の処理を経路1/2へ逃がす使い分けを想定します。
