KASUGAI Canvas v7.1.0

4-1 WEBVIEW連携 — QGIS からカスタムレイヤ＋フィルタを出力

1. 概要 — QGIS 設定がそのまま Canvas のタブになる

QGIS プラグイン geo_webview（KASUGAI WEBVIEW）は、QGIS のレイヤツリー構成を .kasc＋canvas_data/ へ出力する際、Layers 設定で指定した site=/order=/list=off/legend_order= や Filter タブの選択状態を filter_* オプションとして書き出します。 Canvas 側では同梱プラグイン PLUGIN/custom-layer がそれらを読み、 「レイヤ」（カスタムレイヤ）と「フィルタ」の2タブを自動構成します。 ユーザー側でコードを書く必要はありません。 

# geo_webview が出力する .kasc の例
geojson: A工区・ポリゴン | canvas_data/a-poly.geojson | site=A工区 | order=1
geojson: A工区・ライン   | canvas_data/a-line.geojson | site=A工区 | order=2
geojson: A工区・ポイント | canvas_data/a-pt.geojson   | site=A工区 | order=3
geojson: 背景ライン    | canvas_data/free.geojson    （site なし → 標準タブにも「その他」にも出る）
plugin: custom-layer | name=レイヤ | url=canvas_data/custom-layer.js | before=layers-panel | filter_site=A工区 | filter_field=種別

2. カスタムレイヤ（site= 集約）

「ポイント・ライン・ポリゴンなど型の違うレイヤを任意グループ（箇所）にまとめて1トグルで制御する」タブです。レイヤ行に site=<グループ名> を付けるだけで、その名前1行に集約されます。

  • 箇所ごとの1トグルで全メンバーをまとめて on/off（setLayerVisible をメンバー全件に適用）、部分表示は中間状態表示
  • メンバーが分類凡例（QML style=）を持つ場合、箇所行の下に凡例項目（チェック＋スウォッチ＋ラベル）を表示し、シンボル単位の on/off（setLayerLegendVisible）ができます。凡例の並び順は legend_order=asc|desc|reverse またはカンマ区切りのラベル列挙（legend_order=区分A,区分C,区分B。未列挙は末尾・元順維持）で変更でき、未指定時は .qml のシンボル順です。listLayers() の legend[].spec を api.legendSwatchUrl() でスウォッチ画像に変換します
  • メンバー内の順序は order=<数値>（書式: レイヤ行の key=value・例 order=1）で制御します。小さいほど上で、省略時は現在の並び順の末尾扱いです。これはプラグインが listLayers() の options.order を読んで並べ替える独自キーであり、エンジン本体の描画順（.kasc 行順・setLayerOrder）とは別物です — 「この集約タブでの表示順のヒント」として使います
  • site= はこのタブ専用の集約キーで、標準レイヤタブには全レイヤが従来通り表示されます（全体を見る標準タブ＋簡素化した集約タブの併用）。レイヤ一覧（標準・カスタムとも）から隠したいレイヤは list=off を付けます（地図には描画される）。site= と別の集約キー名を使う場合は manifest.options.key（plugin: sc | ... | key=site）で変更できます
  • site= を付けないレイヤはタブ末尾の「その他」に集約され、一括 on/off ができます（順序操作は出さず .kasc 順のまま）
  • site=/order=/list=off はクエリ系行（gpkg:/duckdb:/sql:/ogrsql:/geoparquet:/flatgeobuf:）を含む全ベクター行で有効です。QGIS WEBVIEW が CSV/TSV・フィルタ付きソースを duckdb: 行として出力する場合も同じく site 集約・フィルタの対象になります（sql:/ogrsql: はクエリ全文を where= で差し替える仕様のため、フィルタタブからは式が適用されない点に注意）
  • プラグインタブの表示名（name=）が組み込みタブと重複する場合、組み込み側のタブ名が自動的に「システムレイヤ」等に改称されます（name=レイヤ → 組み込みは「ｼｽﾃﾑﾚｲﾔ」表示。重複解消で自動復元・i18n 対応）。また重複が発生したプラグインタブは組み込みの代替とみなされ、初期表示タブとして自動選択されます

3. フィルタ（site 共通属性の絞り込み）

同じプラグインが「フィルタ」タブも登録します。QGIS WEBVIEW の Filter タブと同じ構成で、 site（箇所）を選ぶとメンバーレイヤ全員が持つ共通属性フィールドを列挙し、 選択した条件を where= 式として全メンバーレイヤへ一括適用します。

  • チェックボックスの意味 = 表示される値。全選択は IN (全値)、全解除は常偽式 1=0 で地図から全地物が消えます（フィルタ解除＝全表示ではありません）。NOT IN で0件の場合のみ解除相当（全表示）です
  • 値の列挙は適用中フィルタを一時解除して全件から収集しますが、チェック状態は api.getLayerFilteredGeoJson（where= 適用後の表示中地物のみを返す API）から採取します。フィールド切替時は「いま地図に見えている地物が持つ値」だけがチェックされた状態で開きます。本 API は Cesium に加え maplibre / openlayers / leaflet / navara のプレイヤー系エンジンでも提供されます（フック未実装・古いホストでは適用済み式からの復元にフォールバック）
  • 適用経路はレイヤ行の ⏷ フィルタと同じ setLayerFilter（クエリ系は SQL 再クエリ、geojson: 等はクライアント評価）です。レイヤ自体の where= が既に適用済みの場合、その式をパースして初期選択（フィールド・演算子・値）を復元します。1=0 は「複数選択 IN・0件チェック」として復元されます
  • plugin: 行の filter_* オプション（filter_site/filter_field/filter_multi/filter_op/filter_values/filter_value）で QGIS WEBVIEW Filter タブの選択状態を初期値として受け取れます。なおプラグインが再初期化された場合は、プリセットよりセッション内の直前選択（window.__kascFilterSel）が優先されます
  • ライブ連携中は変更が /live/writeback で QGIS 側の subsetString へ反映されます（QGIS 側の抑止機構により再エクスポートの巻き戻しは防止済み）
  • setLayerFilter/getLayerGeoJson 非対応エンジンではフィルタタブ自体を表示しません
