## 3. システム構成

KASUGAI Canvas（**deck.gl + Three.js**）をローカルPC・サーバーレス・国内対応・組み込みで動かすための構成についてまとめる章。

## 全体の判断基準

- **描画基盤：deck.gl + Three.js（同一WebGLコンテキスト）**
- **描画方式：deck.glとThree.jsを同一canvas・同一WebGLコンテキストで描画し、共通レイヤー管理で扱う**
- **2D / 3D 混在**、**点群**、**3DGS**、**Tiles/Buffers** を同一 GPU 空間で扱う
- **ドレープ（2D を 3D 地形に貼り付け）**、**クリッピング**、**断面表示**などの現場機能
- 日本国内の **PLATEAU / 地理院タイル** との親和性
- ローカルPC完結・サーバーレスで動作

## ローカルPCで爆速操作する構成

### メインレンダラー：deck.gl + Three.js

- **deck.gl**
  - 2D/3D/Tiles/Buffers を同じ GPU コンテキストで一括描画
  - GeoArrow、FlatBuffers、MVT、3D Tiles を直接読み込み
  - Terrain / Mask / Clip 拡張で地形ドレープ・クリッピング・断面を GPU 処理
- **Three.js**
  - GLB/点群/3DGS 等、deck.gl 単体では扱いにくい高度な 3D 表現を補完
  - `deck.gl` と同一 canvas・同一 WebGL コンテキストで連携（正式仕様）
  - オーバーレイ canvas はプロトタイプ・障害切り分け用に限定
- **loaders.gl**
  - `@loaders.gl/arrow`, `@loaders.gl/3d-tiles`, `@loaders.gl/gltf` などでバイナリをゼロコピーで GPU へ

### データパイプライン

| 段階 | 技術 | 効果 |
|------|------|------|
| 読み込み | File / Blob / Box API | サーバー不要、ローカル完結。GPKG/FGDB/GLB/LAS/PLY/SPZ 等をそのまま読み込み |
| 変換 | Web Worker + Arrow-JS / sql.js + WKB パーサー、FGDBは ogr2ogr サーバー/事前変換 | UI ブロックなしで GPKG/GeoJSON → Arrow、FGDB → 事前変換、PLY/LAS → EPT/3D Tiles |
| 永続化 | OPFS / IndexedDB | 次回起動を即座に行える |
| 描画 | deck.gl + Three.js | 同一 canvas / 同一 WebGL コンテキストで共通レイヤー・深度・カメラを使用 |

### 必須テクニック

1. **GeoArrow / FlatBuffers**
   - 数十万〜数百万点の 2D ベクトルを CPU パースなしで GPU へ
2. **Web Worker + loaders.gl**
   - GPKG/GeoJSON → Arrow、FGDB → サーバー or 事前変換、PLY/LAS → EPT/3D Tiles をバックグラウンド化
3. **OPFS / IndexedDB**
   - 巨大バイナリをブラウザ内にキャッシュ
4. **deck.gl + Three.js 連携**
   - **同一 WebGL コンテキストでカメラ・深度・レイヤー順を共有（正式仕様）**
   - 重ねた canvas は正式な混在レイヤー管理には使用しない

## KASUGAI システム組み込み構成

### コアエンジン

- **deck.gl + Three.js + loaders.gl**
  - `@deck.gl/core`, `@deck.gl/geo-layers`, `@deck.gl/layers`, `@deck.gl/mesh-layers`
  - `@loaders.gl/arrow`, `@loaders.gl/3d-tiles`, `@loaders.gl/gltf`
  - `three` + 必要に応じて `gaussian-splats-3d`

### 組み込むべき拡張

1. **TerrainExtension**：2D図面の3D地形ドレープ
2. **MaskExtension**：敷地ポリゴンでの DEM/3D Tiles くり抜き
3. **ClipExtension**：3D Tiles・点群の断面カット

### データパイプライン

```text
ローカルファイル (GPKG / GeoJSON / GLB / LAS / PLY / SPZ) + FGDB（事前変換）
    ↓
Web Worker or サーバー変換（ブラウザ: sql.js + WKB パーサー / Arrow-JS、サーバー or 事前: ogr2ogr / Potree Converter / entwine）
    ↓
FlatBuffers / GeoArrow / TypedArray / 3D Tiles / EPT (VRAM)
    ↓
deck.gl + Three.js GPU Direct Render
```

### ロードマップ案

| Phase | 内容 | 効果 |
|-------|------|------|
| 1 | deck.gl + GeoArrow ローダー追加 | 大容量 2D データの即時表示 |
| 2 | Three.js 統合 + TerrainExtension & MaskExtension | 2D図面ドレープ・くり抜き実現 |
| 3 | 3D Tiles (1.1) + 点群 + ClipExtension、3DGS（Three.js） | 広域モデル・点群の断面表示、3DGS 可視化 |

## 日本国内向け構成

### 推奨構成

- **描画基盤：deck.gl + Three.js + loaders.gl**
  - 国土地理院タイル（XYZ / 標高PNG）を `TileLayer` / `TerrainLayer` で合成（GSI 標高PNG は符号付き・NA の条件分岐があるため `elevationDecoder` だけでは扱えず、事前変換または GSI 専用レイヤーが必要）
  - 国交省 **PLATEAU**（3D Tiles 1.1 / GLB）をそのままロード
  - 点群・3DGS は Three.js 側で補完
- **参考・相互連携：Re:Earth (OSS)**
  - PLATEAU 等のデジタルツイン可視化で参考になる OSS ツール（PLATEAU 公式基盤ではない点に注意）
  - データエクスポート/API 連携を担保

### 日本現場機能セット

| 国内データ | 組み込む技術 | 現場効果 |
|-----------|-------------|----------|
| 地理院 DEM + 2D図面 | `TerrainExtension` | 平面図を標高にぴったりドレープ |
| PLATEAU + 現場BIM/CIM | `MaskExtension` + `ScenegraphLayer` | 敷地だけくり抜いて CIM を埋め込み |
| i-Construction 点群 | `ClipExtension`（deck.gl 点群）+ Three.js `Points` / Potree 独自クリップ | 点群を高さスライスで施工管理 |
| 写真測量 3DGS | Three.js 専用レンダラー | 現場状況をニューラル表現で可視化 |

## サーバーレス・ローカル起動

HTTP サーバーが使えなくても KASUGAI Canvas はクライアント完結で動作可能。

### データ読み込み手法

| 方法 | 概要 |
|------|------|
| **File / Blob / ArrayBuffer 直読** | ドラッグ&ドロップ or ファイル選択。HTTP（fetch）不要、CORS なし |
| **OPFS / IndexedDB** | ブラウザ内にバイナリをキャッシュ。オフラインでも爆速起動 |
| **PWA (Service Worker)** | 内部で HTTP リクエストを横取りし、ローカル/Zip から返す |
| **Tauri / Electron** | デスクトップ化し、Tauri は `tauri://`、Electron は `file://` またはカスタムプロトコルで安全に読み込み |

### KASUGAI × Box 構成

- **Box を CDE（保存領域）**、**KASUGAI Canvas を可視化エンジン**
- Box API / Direct Download Link から取得したバイナリを、ブラウザ内でそのまま deck.gl / Three.js へゼロコピー転送
- オンライン時は Box から取得、オフライン時は OPFS / ローカルファイルで独立して動作
