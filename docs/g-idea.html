提案書：住まい候補地域の比較支援

応募部門：不動産情報活用部門

提案タイトル 50文字以内

AIと地図で住まい候補地域を比べる地域比較シート

解決したい課題・対象 400字以内

住み替えを考える人は、候補物件を絞った後も、価格、防災、都市計画、学校や周辺施設などの情報を別々のサイトで調べる必要があります。情報ごとに地図や更新時点、表記が異なるため、候補地域の違いや追加で確認すべき点を家族で整理しにくい課題があります。本提案の対象は、複数の候補地域を比較して住まいを検討する人です。物件そのものを推薦するのではなく、地域について公開情報に基づいて確認・比較する過程を支援します。

提案するアイデア・サービス内容 700字以内

住まい選びを支援するサービスを拡充し、幅広い地域課題にも活用できるGISへ発展させます。現在のKASUGAI Canvasには、住まい選びの困りごとを聞き取り、論点・優先度・不足情報に分けて整理する専用機能や、不動産情報ライブラリへの直接接続はありません。そこで、利用者が候補地と関心を入力し、AIとの対話で確認事項を整理して地図調査につなぐ「地域比較シート」を新たに試作します。候補ごとの情報、出典・時点・対象範囲、未掲載または追加確認が必要な項目を並べ、地図へ戻るリンク付きの資料にします。検討例は東京駅まで電車でおおむね30分以内の範囲から、ペットと暮らしやすい駅周辺を選ぶものです。取引価格・防災・都市計画等は不動産情報ライブラリ、所要時間・動物病院・公園の利用条件等は別の情報源を候補にし、取得元と限界を区別します。地域に点数を付けたり安全性を保証したりせず、根拠と不足情報を示して最終判断を利用者に委ねます。

課題に着目した背景・きっかけ 300字以内

要記入：住まい選びや地域情報の調査で感じた具体的な不便、着想のきっかけ、想定利用者への聞き取り・確認内容を記載してください。現時点では個人の体験やヒアリング結果を確認できていないため、事実を補っていません。

補足資料

PDFまたはPowerPoint、10ページ以内・10MB以下。候補地域の地図画面、使用データと出典・時点、比較シート例、操作の流れ、システム構成、未確認事項を掲載する想定です。実データを用いた試作後に作成します。

不動産情報活用部門で、住まいの候補エリアを公開地理情報から比較するシナリオを提案します。家や物件を検索・推薦するのではなく、物件ポータルなどで候補を絞った後に「この地域で暮らすと何が近くにあり、どの公開情報を確認しておくべきか」を地図で理解する場面を、Canvas の機能改善に取り組む題材とします。

システム構成

試作システムの構成です。課題の聞き取り・整理は LimeSurvey CE と Excalidraw が担い、地図比較と根拠付き資料化は KASUGAI Canvas が担います。不動産情報ライブラリ API は公式案内に従いブラウザーから直接リクエストせず、キー保護のためのサーバー側中継（/api/reinfolib。BYO キー転送またはサーバーキー注入、/ex-api/external/ 配下限定）を実装済みです。AI は内蔵 AI チャットが BYO API キーで Gemini を呼び、地図・レイヤー操作と比較シート作成を支援します。

提案の実現に向けた機能改善

機能領域現状今回磨く内容
外部データの取込・レイヤー化GeoJSON・CSV 等の表示機能があるが、ライブラリへの専用接続はないAPI 接続、形式変換、失敗時の説明、対象地域・データ種別の選択を共通化し、接続先ごとの機能は必要に応じて追加できるプラグインにする
レイヤー操作・属性確認AI チャットから検索、レイヤー追加・表示切替、属性検索などを実行できる候補地と関心条件に沿って調査手順をつなぎ、各地物の属性・出典・時点を追いやすくする
複数地域の比較地図を移動して個別に確認できるが、住まい選び向けの比較手順・専用 UI はない候補地域を同じ観点で見比べる操作と、比較結果の整理方法を試作する
資料生成・地図パーマリンクAI が資料を生成し、候補地点の地図視点リンクを埋め込める出典・時点・未確認項目・候補ごとの違いを含む地域比較シートへ改善する

現行コードと仕様を確認した範囲では、不動産情報ライブラリとの直接連携はありません。今回の成果は特定の住まい選び画面だけでなく、外部地理データを取り込み、調べ、説明・共有する Canvas の共通機能へ還元します。外部サービスとの接続は、利用者や用途によって必要性が異なり、利用条件や認証情報の管理も接続先ごとに異なるため、すべてを本体の標準機能にはせず、必要な接続を選んで追加できるプラグインとして設計します。共通のデータ受け口とレイヤー化の仕組みを整え、今回の試作では応募シナリオに必要な接続に絞ります。API データの地域別の有無や形式、更新時期を確かめたうえで、まず1地域・2〜3種類のデータを使って接続実験を行います。

試作の範囲

  • データ接続：取引価格、災害情報、学校・周辺施設などから、API で提供され対象地域で取得できる少数のデータを選ぶ。今回必要な接続をプラグインとして試作し、他の接続先は必要に応じて追加できる形にする。
  • 比較体験：候補エリアを選び、関心のある情報を地図に重ね、属性・出典を確認し、地域ごとの違いを整理できるようにする。
  • 説明・共有：比較シートに根拠・データ時点・未確認事項を含め、候補エリアの地図視点へ戻れるようにする。
  • 対象外：掲載物件の検索・推薦、将来の価格予測、通勤時間や安全性の断定。これらは別のデータや検証が必要です。

課題整理機能と外部システム連携の検討

現状のCanvasにあるのは、AIチャットによる地図・レイヤー操作、資料表示・ダウンロード、地図視点の共有URL生成などの汎用機能です。住まい選びの困りごとを体系的に聞き取り、課題・優先度・根拠・未確認事項として保存し、候補地域ごとに比較する専用機能は未実装です。したがって、課題整理は既存機能として扱わず、今回の試作で新たに設計・検証する対象とします。

役割連携候補・方式Canvas側で担うこと確認事項
日本語での聞き取りと課題整理LimeSurvey CEで日本語の質問票・自由記述を収集し、回答をExcalidrawの日本語UI上でカード化して分類する。どちらもWebで利用でき、日本語画面を備えたOSS。LimeSurveyはセルフホスト版を選べる。候補地・重視条件・困りごと・理由を質問票で集め、自由記述を引用単位のカードに分ける。参加者や担当者がExcalidraw上で似た意見をまとめ、課題・優先度・根拠・未確認事項を整理する。確定した課題をCanvasへ取り込み、地域の地理情報と照合して比較資料にする。Excalidrawは定性分析専用ではなく、カード分類やテーマ確定は人が行う。アンケート回答とカードの対応関係、個人情報を含む回答の保管・削除、共同編集の運用を試作で確認する。LimeSurvey CEのセルフホストにはWebサーバー等が必要。
公的な不動産・地域情報国土交通省「不動産情報ライブラリ」API。価格、都市計画、防災、駅情報等から対象地域で利用できるものを選ぶ。取得データをレイヤーとして表示し、出典・基準日・対象範囲を比較資料に残す。利用申請・APIキーが必要で、公式案内はCORS回避のためブラウザーから直接リクエストしないよう求めている。キーを保護するサーバー側中継（/api/reinfolib）を実装済みで、候補地域の実データ取得を確認した。
所要時間・施設情報経路検索、自治体オープンデータ、施設情報提供元のAPIまたは公開データを用途ごとに選定する。公的APIで得られる情報と外部補足情報を分け、取得日・提供元・利用条件を表示する。候補サービスのライセンス、商用・再配布条件、位置精度、更新頻度、APIキー保護、CORSを事前確認。ペット受入条件などAPIにない情報は自治体等の一次情報で確認する。

進め方：日本語UIを確認できるLimeSurvey CEで質問票を作成し、回答を収集します。自由記述をExcalidrawのブラウザー画面でカードにして、参加者・担当者がKJ法に近い手順で分類し、課題・優先度・根拠を確定します。分類結果と元回答を紐付けてCSV等でCanvasへ取り込み、候補地域の地理情報と照合します。外部ツールは聞き取りと課題整理を担い、地図比較と根拠付き資料化はCanvasが担います。いずれもOSSですが、LimeSurveyはセルフホスト時のサーバー運用が必要です。

候補条件とデータの確認状況

不動産情報ライブラリの公開 API 一覧と項目説明を確認した時点での整理です。API のデータが存在することと、候補地域で必要な精度・鮮度で使えることは別なので、申請承認後に実データと地域カバー範囲を確認します。

比較したいこと不動産情報ライブラリ API追加で必要な情報・扱い
東京駅まで電車で30分以内の候補駅駅の位置・駅名・路線名・運営会社・駅別乗降客数は取得候補。ただし乗降客数は駅の利用規模の参考情報。列車の所要時間・乗換・時間帯別の差は API 一覧で確認できないため、別の経路検索データで調べる。条件を固定し、候補駅を手動で確定する。
ペットと暮らすための動物病院・動物医療掲載されている「医療機関」API は病院・診療所等の医療機関情報で、動物病院の網羅データとしては使えない。自治体・動物病院の公開情報や別の施設データを確認。取得範囲・更新日を記録し、件数だけで暮らしやすさを断定しない。
散歩場所・公園や緑地公開 API 一覧に、一般の都市公園を網羅する項目は確認できない。自然公園地域は都市公園の代替にはならない。自治体の公園データ等を別途調査。ペット同伴可否、リード・利用制限は施設ごとの規則を確認する。
災害時の避難先指定緊急避難場所の位置・災害種別などは取得候補。API の項目だけではペット同行・同伴の可否や受入条件が分からない。自治体の避難所運営情報で確認し、未確認なら明示する。
住居費の目安・地域の基礎情報不動産取引価格・成約価格、地価公示・地価調査、都市計画、防災情報を取得候補にできる。取引価格は個別のペット可物件の家賃・飼育条件を示すものではない。物件検索・推薦は行わず、地域の参考情報として扱う。

したがって、今回の試作では「不動産情報ライブラリの API で確認できる価格・防災・駅情報」と、「別途確認する所要時間・動物病院・公園利用条件・避難所のペット受入情報」を区別して比較シートに載せます。API マニュアルは CORS 回避のためブラウザーから直接 API リクエストしないよう案内しているため、接続方式も申請後に利用条件と合わせて確認します。

外部 API の利用方針：不動産情報ライブラリ以外の経路検索・施設情報 API も候補にできます。候補駅の所要時間やペット関連施設の補足に利用する場合は、提供元・利用条件・CORS・キーの保護・取得日を確認します。AI機能はすでにCanvasにあり、これらの追加データを取得できるようになった後、出典と実データに基づく比較・説明に活用します。キーを公開ページや共有資料に含めません。

サーバーレス環境で利用できる外部 API・データの候補調査

採用方針：第一候補は、所要時間＝Transitous（または GTFS-JP の事前計算による静的データ）、施設情報＝Overpass API とし、OSM で不足する施設は自治体一次情報で補完します。いずれもキー不要・ブラウザ直接・非商用無償で、出典表記と取得日の記録だけで利用できます。YOLP は保存・外部出力の規約制約があるため一覧確認等の補助用途に限定します。Google Places/Routes は地図併用・キャッシュの規約制約と課金管理が必要なため今回の試作では採用しません。駅すぱあと API はフリープランでは所要時間をデータとして取得できず、有償プランはドメイン認証キーの秘匿にサーバー中継が必要なため今回は見送ります。Transitous は非公式 GTFS ベースのため、候補駅の所要時間は条件（平日・時刻・乗換基準）を固定したうえで、確定候補だけ公式時刻表情報で目視確認します。
