応募方針：不動産情報活用部門 — 住まい選びの地域比較

応募先と今回の出展で目指すこと

応募部門：不動産情報活用部門

住まい選びを支援するサービスの拡充を目指します。不動産情報ライブラリとの接続、複数レイヤーの比較、出典付き資料の作成を通じて、候補地域の特徴や確認したい情報を分かりやすく整理できるようにします。その実現に向けて KASUGAI Canvas の機能も強化し、住まい選びに役立つとともに、幅広い地域課題にも活用できる GIS へと発展させます。

不動産情報活用部門で、住まいの候補エリアを公開地理情報から比較するシナリオを提案します。家や物件を検索・推薦するのではなく、物件ポータルなどで候補を絞った後に「この地域で暮らすと何が近くにあり、どの公開情報を確認しておくべきか」を地図で理解する場面を、Canvas の機能改善に取り組む題材とします。

中心アイデア：暮らしの条件で候補エリアを見比べる

住み替えを考える家族が、候補に残した2〜3地域について、価格の目安・災害情報・都市計画・学校や周辺施設などを同じ地図上で確認します。AI は利用者の関心（例：通学先、買い物、防災、価格）に沿って、確認できる情報と未掲載・未確認の情報を整理した「地域比較シート」を作成します。

今回の仮設定では、東京駅まで電車でおおむね30分以内を候補地域の範囲とし、その範囲内からペットと暮らしやすい駅周辺を候補として選びます。所要時間は候補地域を絞る条件、ペットの暮らしやすさは候補駅を選び比較する条件です。候補駅を判定するときは、参照した経路情報と検索条件を記録します。

  1. 利用者が候補エリアと重視する条件を入力する。
  2. 不動産情報ライブラリで提供されている取引価格、都市計画、防災、周辺施設等のうち、対象地域で利用可能なデータを地図に表示する。
  3. エリアごとの地図を行き来しながら、属性・出典・データ時点を確かめる。
  4. AI が確認済みの情報、候補ごとの違い、追加確認が必要な点をまとめ、地図を再表示できるリンク付き資料を作る。

この仕組みは、地域に「住みやすさ」の点数を付けたり、安全性を保証したりしません。データの範囲と基準日を示し、最終判断は住む人に残します。

既存サービスとの違い

部門の公式事例には、LIFULL HOME'S が不動産情報ライブラリと AI を連携し、学区から物件を探したり、エリアの取引価格を確認したりする仕組みが紹介されています。KASUGAI Canvas は物件検索を重ねず、候補物件を決めた後の地域比較に焦点を当てます。複数の地理レイヤーを一緒に見て、家族間で根拠を確認できる地図資料にする点を提案の違いとします。

現行コードと仕様を確認した範囲では、不動産情報ライブラリとの直接連携はありません。今回の成果は特定の住まい選び画面だけでなく、外部地理データを取り込み、調べ、説明・共有する Canvas の共通機能へ還元します。API データの地域別の有無や形式、更新時期を確かめたうえで、まず1地域・2〜3種類のデータを使って接続実験を行います。

試作と機能改善の範囲

  • データ接続：取引価格、災害情報、学校・周辺施設などから、API で提供され対象地域で取得できる少数のデータを選ぶ。
  • 比較体験：候補エリアを選び、関心のある情報を地図に重ね、属性・出典を確認し、地域ごとの違いを整理できるようにする。
  • 説明・共有：比較シートに根拠・データ時点・未確認事項を含め、候補エリアの地図視点へ戻れるようにする。
  • 対象外：掲載物件の検索・推薦、将来の価格予測、通勤時間や安全性の断定。これらは別のデータや検証が必要です。

候補条件とデータの入手見込み

不動産情報ライブラリの公開 API 一覧と項目説明を確認した時点での整理です。API のデータが存在することと、候補地域で必要な精度・鮮度で使えることは別なので、申請承認後に実データと地域カバー範囲を確認します。

したがって、今回の試作では「不動産情報ライブラリの API で確認できる価格・防災・駅情報」と、「別途確認する所要時間・動物病院・公園利用条件・避難所のペット受入情報」を区別して比較シートに載せます。API マニュアルは CORS 回避のためブラウザーから直接 API リクエストしないよう案内しているため、接続方式も申請後に利用条件と合わせて確認します。

外部 API の利用方針：不動産情報ライブラリ以外の API も利用できます。常設サーバーを運用せずに呼び出せるサーバーレスの AI API や経路検索・施設情報 API などを、候補駅の所要時間調査、ペット関連施設の補足、比較内容の整理に活用して構いません。ブラウザーから直接呼び出せない API は、利用可能なサーバーレス関数等を中継先として検討します。利用条件、CORS、API キーの保護、送信するデータの範囲を確認し、キーを公開ページや共有資料に含めないこと、AI の生成内容は出典・実データと照合することを前提とします。
