4. Cloudflare 認証（cloudflare）：Workers

概要

3. Cloudflare 認証 — Pagesの機能（KV の .kasc・R2 秘匿データ配信）に加えて、静的ファイル自体も含めて全リクエストを認証ゲートする方式です。Worker スクリプトが全リクエストを処理し（run_worker_first）、ログイン時に発行される署名トークンの Cookie（HttpOnly・12時間有効）を持たないアクセスには静的ファイルも返しません。

秘匿データがすべて Functions/Worker 経由になる設計では Pages の「静的ファイル無料無制限」の利点が薄いため、静的ファイルまで保護できる本方式が適しています。

control を 4 に設定するとこの方式が選択されます（クライアント実装は cloudflare と共通で、r2:// 書き換えも有効）。

構成

workers/
  wrangler.toml  … assets=../web、KV/R2バインド、run_worker_first=true
  worker.js      … /api/* ルーティング＋静的ファイル認証ゲート

worker.js は functions/api/*・functions/_lib/token.js のハンドラをそのまま再利用します。二重実装ではありません。

認証前に公開されるのはログイン画面に必要な最小限のみです（index.html・styles.css・favicon.ico・auth-*.js・auth-methods.json・PLUGIN/auth-*/）。それ以外のファイル（app.js・projects/・DATA/ 等）はすべて未認証では 401 になります。

デプロイ手順

  1. workers/wrangler.toml の KV/R2 バインドを設定します。
  2. パスワード系は secret として登録します（wrangler.toml には書きません）。
  3. workers/ ディレクトリでデプロイします。
cd workers
wrangler kv namespace create KASUGAI_KV   # → 発行された id を wrangler.toml に
wrangler r2 bucket create kasugai-data
wrangler secret put KASUGAI_AUTH_PASS
wrangler deploy

.kasc の登録・R2 データ・r2:// 記法は 3 のページと同じです。

ローカル開発

cd workers
wrangler dev

ローカル用の変数は workers/.dev.vars（git 管理外）に置きます。

無料枠の消費

  • 全リクエストが Worker 呼び出しとして無料枠（10万回/日）を消費します — 静的ファイル・ログイン画面も含む
  • 起動時に数十ファイルを読む構成のため、少人数利用なら十分ですが不特定多数への公開には向きません
  • KV/R2 のオペレーション枠は別途あり（R2 読み出し 1,000万回/月 等）

セキュリティ上の注意

  • 保護できるもの：静的ファイルすべて（HTML/JS/CSS/DATA/ 等）、.kasc、R2 内の秘匿データ
  • 保護できないもの：公開許可リストのファイル（ログイン画面系）、PLUGIN/auth-*/ の内容（ID/PASS を直書きするプラグインの中身は見えます — 本番では cloudflare 系のみ使用してください）
  • セッションは HttpOnly Cookie（kasugai_session・SameSite=Strict・12時間）で管理され、JS から読み取れません
