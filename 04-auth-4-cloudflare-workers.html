4. Cloudflare 認証（cloudflare）：Workers

概要

3. Cloudflare 認証 — Pagesの機能（KV の .kasc・R2 秘匿データ配信）に加えて、静的ファイル自体も含めて全リクエストを認証ゲートする方式です。Worker スクリプトが全リクエストを処理し（run_worker_first）、ログイン時に発行される署名トークンの Cookie（HttpOnly・12時間有効）を持たないアクセスには静的ファイルも返しません。

秘匿データがすべて Functions/Worker 経由になる設計では Pages の「静的ファイル無料無制限」の利点が薄いため、静的ファイルまで保護できる本方式が適しています。

control を 4 に設定するとこの方式が選択されます（クライアント実装は cloudflare と共通で、r2:// 書き換えも有効）。

構成

workers/
  wrangler.toml  … assets=../web、KV/R2バインド、run_worker_first=true
  worker.js      … /api/* ルーティング＋静的ファイル認証ゲート

worker.js は functions/api/*・functions/_lib/token.js のハンドラをそのまま再利用します。二重実装ではありません。

認証前に公開されるのはログイン画面に必要な最小限のみです（index.html・styles.css・favicon.ico・auth-*.js・auth-methods.json・i18n.js・i18n/・PLUGIN/auth-*/）。それ以外のファイル（app.js・projects/・DATA/ 等）はすべて未認証では 401 になります。

デプロイ手順

以下の手順はリポジトリルートで python run-workers.py を実行すると自動化できます（ログイン確認・KV/R2 バインド記入・secret 確認・control=4 設定・deploy・簡易検証まで。control はデプロイ後に 0 に戻します。未ログイン時の wrangler login とパスワード入力のみ手動です）。

前提：wrangler（Cloudflare の CLI）が使えること。初回のみ wrangler login でブラウザ認証しておきます。

  1. KV / R2 を用意します（Pages ですでに作成済みならこの手順はスキップ。同じものをバインドし直すだけでデータ移行は不要です）。 
    cd workers
wrangler kv namespace create KASUGAI_KV    # → 発行された id を控える
wrangler r2 bucket create kasugai-data     # → バケット名を控える
    作成済みなら wrangler kv namespace list / wrangler r2 bucket list で id・バケット名を確認できます。
  2. workers/wrangler.toml にバインドを書きます。[[kv_namespaces]] / [[r2_buckets]] のコメントを外して、手順1の id・バケット名を記入します。ユーザーIDを admin から変える場合は [vars] の KASUGAI_AUTH_USER もここで編集します。
  3. パスワードをシークレット登録します（wrangler.toml には書きません）。 
    wrangler secret put KASUGAI_AUTH_PASS
    値は引数には書かず、コマンド実行後の対話プロンプトで入力します。 
    Enter a secret value:          ← ここでパスワードを打ち込んで Enter
✨ Success! Uploaded secret KASUGAI_AUTH_PASS
    • 入力中は画面に何も表示されません（パスワード入力と同じ）。貼り付けも可
    • 対話式なのは、端末の履歴にもファイルにも値を残さないためです
    • 登録済みかは wrangler secret list で確認できます（名前だけ出て値は読み出せません）。間違えたら同じコマンドで上書きします
    • ダッシュボードからも設定できます：Worker → Settings → Variables and Secrets → Add（Type: Secret）
  4. web/auth-methods.json の control を 4 にします（このファイルは静的アセットとして一緒にデプロイされます）。
  5. デプロイします。 
    wrangler deploy
    Pages の --project-name や配信ディレクトリのような引数は不要です。wrangler.toml が宣言的な設定ファイルになっており、以下がそこに書かれています。
    Pages のコマンド引数Workers での相当設定
    --project-name <プロジェクト名>wrangler.toml の name = "kasugai-canvas"
    web（配信ディレクトリ）[assets] の directory = "../web"
    functions/（自動検出）main = "worker.js"
    初回 deploy で name の Worker が自動作成され、以降は同名 Worker の更新になります。
  6. 動作確認します。https://kasugai-canvas.<アカウント>.workers.dev を開き、ログイン画面 → ID/PASS でログインできることを確認します。未ログインで app.js 等に直接アクセスして 401 になることも確認すると確実です。

再デプロイの目安：

  • web/・workers/・functions/ のファイルを変更した → wrangler deploy を再実行
  • secret（パスワード）を変えた → wrangler secret put のみ（再デプロイ不要・即反映）
  • KV の中身（.kasc）を更新した → デプロイ不要（インスペクターの「適用」や wrangler kv key put で即反映・伝播は最大60秒）

.kasc の登録・R2 データ・r2:// 記法は 3 のページと同じです。

Pages（方式3）との設定の違い

クライアント側（web/・認証プラグイン・API 呼び出し）は方式3と完全に共通で、違いはサーバー側のデプロイ・設定方法だけです。functions/api/* のハンドラも worker.js が import して再利用するため、API 実装の二重管理はありません。

Pages からの移行手順

KV 名前空間・R2 バケットはアカウント配下のリソースなので、データ移行は不要です。同じものを Worker にバインドし直すだけです。

  1. Pages プロジェクトの Settings → Bindings で KV 名前空間 ID・R2 バケット名を確認し、workers/wrangler.toml の [[kv_namespaces]] / [[r2_buckets]] に転記します（wrangler kv namespace list / wrangler r2 bucket list でも確認可）。
  2. シークレットを再登録します。値は Pages から読み出せないため再入力です（忘れた場合は新しいパスワードを登録すればよく、既存トークンが無効化されるだけです）。
cd workers
wrangler secret put KASUGAI_AUTH_PASS
wrangler secret put KASUGAI_TOKEN_SECRET   # Pages で設定していた場合のみ
wrangler deploy
  1. https://kasugai-canvas.<アカウント>.workers.dev でログイン・/api/data/* の動作を確認します。
  2. web/auth-methods.json の control を 4 にして再デプロイします。
  3. カスタムドメインを Pages に付けている場合は Worker の Settings → Domains & Routes で付け替えます（同時に1箇所にしか向けられません）。動作確認が済むまで Pages プロジェクトは残しておけば切り戻し可能です。

ローカル開発

cd workers
wrangler dev

ローカル用の変数は workers/.dev.vars（git 管理外）に置きます。

無料枠の消費

  • 全リクエストが Worker 呼び出しとして無料枠（10万回/日）を消費します — 静的ファイル・ログイン画面も含む
  • 起動時に数十ファイルを読む構成のため、少人数利用なら十分ですが不特定多数への公開には向きません
  • KV/R2 のオペレーション枠は別途あり（R2 読み出し 1,000万回/月 等）

セキュリティ上の注意

  • 保護できるもの：静的ファイルすべて（HTML/JS/CSS/DATA/ 等）、.kasc、R2 内の秘匿データ
  • 保護できないもの：公開許可リストのファイル（ログイン画面系）、PLUGIN/auth-*/ の内容（ID/PASS を直書きするプラグインの中身は見えます — 本番では cloudflare 系のみ使用してください）
  • セッションは HttpOnly Cookie（kasugai_session・SameSite=Strict・12時間）で管理され、JS から読み取れません
